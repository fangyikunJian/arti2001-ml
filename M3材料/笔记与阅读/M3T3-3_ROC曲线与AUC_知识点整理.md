---

## 0. 主旨

> 从**一个**混淆矩阵，走到**一串**阈值选择；然后**把「排序质量」和「决策质量」区分开**。
> ⚠ **全程保持模型和评估样本不变，只动阈值。**

---

## 1. 先把定义摆清楚

```
TPR = TP/(TP+FN)  = recall（召回率、真正率）
FPR = FP/(FP+TN)  = 1 − specificity（假正率）
specificity = TN/(TN+FP)      真实负例里被正确拒绝的比例
prevalence  = (TP+FN)/N       真实为正的案例占比
```

> **每个阈值产生一个点 (FPR, TPR)。**
> ⭐ **曲线越靠近左上角，排序能力越强**——**在错误接受很多负例之前，就已经找到很多正例。**

> ⚠ **校准（calibration）问的是预测概率与观测事件频率是否一致；
> 光有好的排序（高 AUC）并不保证校准好。**

---

## 2. ⭐⭐ 怎么构造这条曲线（五步）

```
① 定义正类，并确保「分数越大 = 支持该类的证据越强」
   （分数可以是概率，也可以是决策分数）
② 把真实正例数和真实负例数各数一次 —— ⭐ 这两个分母在整个过程中固定不变
③ 从比最大分数还高的阈值开始：全部预测为负 ⇒ 点 (0, 0)
④ 把阈值顺着「不同的分数值」往下降
   ⚠⚠ 共享同一个分数的观测必须一起加入
   每次重新数 TP 和 FP，再分别除以那两个固定的总数
⑤ 以比最小分数还低的阈值结束：全部预测为正 ⇒ 点 (1, 1)
   横轴画 FPR，纵轴画 TPR
```

> ⚠ **两个类别都必须存在**，否则这两个率没有定义。
> ⚠⚠ **硬类别预测只能提供一个工作点**——**要画完整曲线必须用原始分数。**
> ⚠ **数据量小时，曲线是一串阶梯，不是一条光滑的物理定律。**

---

## 3. ⭐⭐ 官方算例：四个样本

**A (0.90, 1)、B (0.80, 0)、C (0.40, 1)、D (0.10, 0)**（格式为 分数, 标签）
**2 个真实正例、2 个真实负例** ⇒ **TPR = TP/2，FPR = FP/2** 全程不变。

| 阈值 | 被预测为正 | TPR | FPR | ROC 点 |
|---|---|---|---|---|
| 高于 0.90 | 无 | 0 | 0 | **(0, 0)** |
| 0.85 | A | 0.5 | 0 | **(0, 0.5)** |
| 0.60 | A, B | 0.5 | 0.5 | **(0.5, 0.5)** |
| 0.30 | A, B, C | 1 | 0.5 | **(0.5, 1)** |
| 0.05 | A, B, C, D | 1 | 1 | **(1, 1)** |

> ⭐⭐ **每加入一个正例，点向上移 1/2；每加入一个负例，点向右移 1/2。**
> 这个「正例往上、负例往右」的规律是画 ROC 的核心直觉。

### 自测：阈值从 0.60 降到 0.30，哪个样本进来？点往哪移？

> **C 进来（分数 0.40）。C 是正例 ⇒ 点向上移**，从 (0.5, 0.5) 到 **(0.5, 1)**。

---

## 4. ⭐⭐ 梯形法算 AUC

```
AUC ≈ Σᵢ (FPRᵢ₊₁ − FPRᵢ) × (TPRᵢ + TPRᵢ₊₁)/2
```

> ⚠ **FPR = 0 处那段竖直线段贡献的面积为零**（横向宽度为 0）。

**本例计算**：
```
(0.5 − 0)  × (0.5 + 0.5)/2 = 0.5 × 0.5 = 0.25
(1 − 0.5)  × (1 + 1)/2     = 0.5 × 1   = 0.50
                                      AUC = 0.75
```

> ⚠ **要把两个端点和每一段都算进去；竖直段横宽为零，所以面积为零。**
> ⭐ **用全部不同阈值画出的分段线性经验 ROC 曲线，梯形法给出的就是它的精确面积。**
> **若只给了少数几个工作点，结果是基于直线插值的估计。**

---

## 5. ⭐⭐⭐ 用「正负配对」复核面积（更好用的办法）

> **AUC 的排序解释**：**随机取一个正例、随机取一个负例，正例分数更高的概率**（平局另算）。

**本例**：正例 **A=0.90, C=0.40**；负例 **B=0.80, D=0.10**。
**四个「正–负」配对**：

| 配对 | 比较 | 结果 |
|---|---|---|
| A vs B | 0.90 > 0.80 | **正例赢** ✓ |
| A vs D | 0.90 > 0.10 | **正例赢** ✓ |
| C vs B | 0.40 < 0.80 | **负例赢** ✗ |
| C vs D | 0.40 > 0.10 | **正例赢** ✓ |

```
3 胜 / 4 对 ⇒ AUC = 0.75        ✓ 和梯形法完全一致
```

> ⭐ **一个平局算半胜。**
> ⭐⭐ **这个办法不需要选任何阈值**，考场上比画梯形快得多，**而且能互相验算**。

---

## 6. ⚠ AUC 数值的解读分寸（措辞很讲究）

| 情况 | 正确的说法 |
|---|---|
| **AUC = 1** | **在被评估的这个样本上排序完美**，⚠ **不保证未来的准确率** |
| **AUC = 0.5** | **平均配对顺序处于随机水平**；⚠ **不等于「在每个阈值上都没有有用的行为」** |
| **AUC < 0.5** | ⚠⚠ **应当去检查分数方向、标签约定和抽样**，**而不是拿测试结果去自动把模型反过来用** |

> ⚠ AUC 接近 0.5 时，**单条经验曲线也不必恰好落在对角线上**。

---

## 7. ⭐⭐⭐ AUC 不能决定什么（四条，最可能出选择题）

> 1. **它不替你选工作阈值。**
> 2. **它不衡量概率校准。**
> 3. **它不编码误报和漏报的真实代价。**
> 4. **负例很多时，它可能掩盖掉数量不可接受的误报。**

⭐ 第 4 条的机理（页面说得很准）：
> **ROC 用的是「类内条件率」**，所以**单独改变 prevalence 不一定改变 ROC AUC**，
> **但 precision 和实际可用性可能变化很大。**
> ⇒ **还要同时看 precision–recall 和 prevalence。**

> ⚠ **用验证数据加上应用场景的代价、产能或安全约束来选最终阈值。在没碰过的测试集上评估一次。**

### 自测：两个系统 AUC 相同，它们的可用阈值或误报代价一定相同吗？

> **不一定。** **AUC 概括的是整条曲线（排序能力），而不是某一个工作点。**
> 两条形状不同的曲线**完全可以有相同的面积**，但在你实际会用的那个 FPR 附近表现差很远。

---

## 8. ⭐⭐ 同一组样本的 PR 视角（对照着看）

**PR 曲线：横轴 recall，纵轴 precision。** 还是 A/B/C/D 那四个：

| 阈值 | TP | FP | FN | Recall | Precision |
|---|---|---|---|---|---|
| 0.85 | 1 | 0 | 1 | 0.5 | **1** |
| 0.60 | 1 | 1 | 1 | 0.5 | **0.5** |
| 0.30 | 2 | 1 | 0 | 1 | **2/3** |
| 0.05 | 2 | 2 | 0 | 1 | **0.5** |

> ⚠ **高于 0.90 时没有任何正类预测 ⇒ precision 的分母为零**；绘图库可能自行提供一个端点约定。
> ⭐⭐ **注意 precision 这一列：0.5 → 2/3 → 0.5，先升后降** —— **阈值下降时 precision 不必单调变化。**
> **随机排序的无技能参考线 = 正例占比 = 2/4 = 0.5。**

---

## 9. ⭐⭐⭐ 稀有正例的那个算例（本页最该记的数字）

**1000 个观测，其中只有 10 个正例**（⇒ 990 个负例）。
**在 TPR = 0.8、FPR = 0.1 处**：

```
TP = 0.8 × 10  = 8          FN = 10 − 8 = 2
FP = 0.1 × 990 = 99

Precision = 8/(8 + 99) = 8/107 ≈ 7.5%
Recall    = 8/10       = 80%
```

> ⭐⭐ **recall 高达 80%，precision 却只有约 7.5%。**
> **原因：FPR 虽然只有 0.1，但底下有 990 个负例，于是产生了 99 次误报。**

⭐ 页面的总结很精辟：
> **ROC 衡量的是「类内条件的排序行为」；而 precision 揭示的是「在这个 prevalence 下，正类预测的实际质量」。**

> ⚠ **正例稀少时两种视角都要看**，并用验证数据和错误代价来选工作阈值。

### ⚠ 一条范围说明

> **不要机械地把 ROC 的梯形配方套用到「平均精度（average precision）」上**——
> **average precision 和梯形法算的 PR 面积是两个不同的概括量。**
> **本 Topic 不要求计算这些概括量。**

---

## 10. 总结自测

**Q：80% 的 recall 怎么能和约 7.5% 的 precision 并存？**
> 因为**两者的分母完全不同**：
> **recall 的分母是 10 个真实正例**（抓到 8 个，很好看）；
> **precision 的分母是 107 个「被预测为正」的案例**（其中 99 个是误报）。
> ⇒ **负例基数巨大时，很小的 FPR 也会压倒性地稀释 precision。**

**Q（页面的 Study check）：给一张「分数 + 标签」的小表，怎么做？**
> **① 按分数排序 → ② 让阈值依次穿过每个不同的分数值（⚠ 相同分数的观测要一起处理）
> → ③ 算出每个 ROC 点 → ④ 用梯形估计 AUC。**
> ⭐ **算完用「正负配对法」复核一遍**，两种方法应当一致。

## ⭐ 速查卡

```
TPR = TP/(TP+FN) = recall        FPR = FP/(FP+TN) = 1 − specificity

画 ROC： 分母(真实正例数、真实负例数)固定不变
         从 (0,0) 开始，阈值往下降，⚠ 同分数的样本一起加
         加正例 → 往上走     加负例 → 往右走
         到 (1,1) 结束

AUC 两种算法：
  梯形： Σ (ΔFPR) × (TPR_i + TPR_{i+1})/2    ⚠ 竖直段面积为 0
  配对： P[随机正例 > 随机负例]，⭐ 平局算半胜 —— 更快，且能互验

⚠ AUC 不决定：阈值 / 校准 / 真实代价；负例多时会掩盖误报数量

⭐ 稀有正例算例： 1000 个里 10 个正例，TPR=0.8 FPR=0.1
                  ⇒ TP=8, FN=2, FP=99  ⇒ recall 80% 但 precision 仅 7.5%
```
