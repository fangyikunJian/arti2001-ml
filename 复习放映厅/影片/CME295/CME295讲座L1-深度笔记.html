模块 b字幕第 111–175 句（10:38–17:31）：NLP 是什么、三个桶、 每个桶里有哪些任务、分类桶走一遍（数据集 + 四个指标）、⚠ 类别不平衡、多分类的指标粒度句 111–175 · 10:38–17:31

11:12And it is a field that is around manipulating text, just computing things with text

正课的第一个词。讲者说过这个领域全是缩写，而这是第一个。

定义：NLP 代表 Natural Language Processing（自然语言处理）。它是一个围绕「操纵文本」的领域 —— 就是拿文本来算东西。

⇒ 注意这个定义有多宽：只要你在对文本做计算，就算 NLP。它不要求你理解语义、也不要求输出是文本。

★ 然后他立刻给了一个分类框架：「而在一个很高的层面上，基本上可以把 NLP 任务分成三个桶。」

⇒ 这三个桶是：分类、多分类、生成。

★★ 我建议你把这三个桶当成一个一直用到最后的坐标系，因为讲者后面会反复把东西挂回去：讲 RNN 时他会说「分类任务取最后一个隐状态、多分类取对应 token 的、生成要先编码再解码」；讲 BERT 时会说它适合前两个桶；讲 decoder-only 时会说它赢在第三个桶。

⇒ 所以现在花两分钟把三个桶记牢，后面会省很多力气。

先看前两个桶，而区分它们的标准是输出的形状，不是任务的难度。

① 分类（classification）：我们有一段输入文本作为输入，然后我们想预测某个东西。⇒ 关键在于「某个东西」是单数：整段文本对应一个标签。

② 多分类（multi-classification）：我们仍然有文本作为输入，但这一次我们预测的不止一个东西。⇒ 典型形态是给句子里的每个词各打一个标签。

⚠ 这里有个术语要小心，因为它和你在别处学的可能不一样：在通常的机器学习语境里，「multi-class classification」指的是类别多于两个的单标签分类（比如三分类）；而讲者这里说的「multi-classification」指的是一次预测多个位置（序列标注）。

⇒ 从他举的例子（NER —— 标出句子里哪些词是地点、时间）可以确认他说的是后者。听的时候按他的用法理解即可，但你读别人的材料时要留个心。

把三个桶的输出形状并排看，一个很重要的梯度就出来了。

输出空间的大小：① 分类 —— 有限且固定（正/负/中，三个）；② 多分类 —— 有限，但要填很多个位置；③ 生成 —— 无限（任意长度的任意 token 序列）。

★★ 而评估的难度正好跟着这个梯度走：① 分类可以直接数对错；② 多分类也能数，只是要决定在哪个粒度上数（下面马上会讲）；③ 生成没法直接数 —— 因为「对的输出」有无穷多个。⇒ 讲者下面讲机器翻译时会说这句话：评估你的模型的表现实际上要难得多，因为正如你能想象的，同一个东西可以有很多种不同的翻译方式。

★ 这门课讲的 LLM 几乎全部落在第 ③ 个桶里，所以「评估难」这件事会一路跟着你到 L8。

⚠ 但别得出「前两个桶过时了」的结论：L2 会专门讲 BERT 那一类 encoder-only 模型，而它们正是为前两个桶设计的。⇒ 讲者在 L2 会给出一个很清楚的判断：decoder-only 之所以赢，不是因为它在每个任务上都更好，而是因为「预测下一个词」这个目标更能扩展。

11:34So one example is you have a movie review and you want to predict whether the sentiment is positive, negative, or neutral

第一个桶里的任务，讲者一口气举了四个。

① 情感分析：一个例子是你有一篇影评，你想预测它的情感是正面、负面还是中性。

② 意图识别（intent detection）：就是弄清楚比如这个人想做什么。假设你说「我想为明天设一个闹钟」—— 那这里的意图就是「设闹钟」。

⇒ 这个任务在语音助手里是核心：先把一句自由的话归到有限的几个意图里，后面才能走确定的流程。

③ 语种识别：比如如果你写的是法语，你想检测出这段文本是法语的。

④ 主题建模（topic modeling）。

★ 四个任务的共同点：整段文本进去，一个标签出来。

⭐ 而值得留意的是这四个任务今天的处境：它们在 LLM 时代并没有消失，而是变成了「用一个 prompt 就能做」的事。⇒ 但这不意味着它们不值得专门做 —— L2 讲 BERT 时你会看到，对这类固定输出的任务，一个小得多的专用模型往往更快更便宜。

12:14So we still have a text as input, but this time we predict more than one thing

第二个桶，而最有代表性的那个任务你一定会反复遇到。

讲者的说法：我们仍然有文本作为输入，但这次我们预测的不止一个东西。这个桶里也有不少任务，而其中非常流行的一个叫 Named Entity Recognition，简称 NER。

NER 在做什么：这个任务做的事是：给定一段输入文本，我们想基本上给某些特定的词打上标签 —— 比如识别出某个东西是不是一个地点、是不是一个时间，等等。

★★ 请留意这里发生的变化：标签的「挂载点」从整句变成了单个词。⇒ 这个变化看起来小，但它会连带影响后面所有东西：① 模型要输出的不是一个向量，而是每个位置一个向量；② 指标也得跟着换粒度（下面第 10 条会讲，讲者专门说了这一点）；③ 用 RNN 做这类任务时，你取的是「对应那个 token 的隐状态」，而不是最后一个（第 g 模块会讲）。

⇒ 所以「输出挂在哪一级」是一个会一路传导的设计选择，值得现在就建立意识。

12:49And then you have some other tasks as well that are a little bit more on the linguistic side

这一小段讲者讲得很快，但他说的那句评价本身就是信息。

他的话：「然后还有一些别的任务，更偏语言学那一侧。我想它们现在不那么时髦了，但大概十年前是人们会大量研究的东西。」

这些任务是：词性标注（part of speech tagging）—— 就是弄清楚哪个词是名词、哪个是动词等等；以及一些句法分析相关的任务 —— 依存句法分析（dependency parsing）或成分句法分析（constituency parsing）。

★★ 那句「十年前人们研究得很多、现在不那么流行了」值得停一下：⇒ 它说的是一件挺重要的事：这个领域里「什么算重要」变得非常快。

⚠ 而变化的机制也值得想清楚：这些任务并没有被「解决」，而是被「绕过」了。以前要先做词性标注、再做句法分析、再在这些结构上做下游任务；而现在的做法是直接端到端地学，中间那些显式的语言学结构就不再被单独建模了。

⇒ 这是一个在机器学习里反复出现的模式：当端到端的方法足够强时，中间那些「人设计的表示」就会消失。特征工程之于深度学习、句法分析之于 LLM，都是同一件事。

13:19And then the last bucket, which is very popular these days is the generation bucket

第三个桶，而它和前两个有一个结构性的差别。

讲者的定义：最后一个桶、也是如今非常流行的那个，是生成桶。你有文本作为输入，也有文本作为输出。而这里长度是可变的 —— 意思是你事先并不知道你输出文本的长度会是多少。

★★★ 请把「长度事先不知道」这一句单独记住，因为这一讲乃至整门课的很多东西都是从它长出来的。

⇒ 它直接导致了几件事（后面都会遇到）：① 你需要一个特殊 token 来表示「停」 —— 本讲后面有学生问「生成什么时候停？不然它不就永远停不下来了吗」，答案是 EOS（end of sequence）。② 你没法像分类那样一次算完 —— 必须一个 token 一个 token 地生成，每次把已生成的再喂回去（本讲最后的走查里会看到）。③ 评估变得极难 —— 因为「对的输出」不止一个，这正是下面 BLEU、ROUGE 要处理的问题，也是 L8 整整一讲的主题。

⇒ 所以这不只是一个分类标签，它是「这类任务为什么特别难」的根源。

13:50So you ask a question and you have a response

第三个桶里的任务，而讲者点名了你每天在用的那个。

① 机器翻译：比如把英文的东西翻成德文。⇒ 这个任务在本讲里地位特殊：transformer 那篇原论文做的就是它，而本讲最后的端到端走查走的也是它。

② 问答（question answering）：典型就是你正在用的 ChatGPT、Gemini 这些助手。你问一个问题，你得到一个回答。

③ 摘要（summarization）：比如你想概括一篇文章。

④ 「就是生成点什么」：这个「某些东西」可以是生成代码、生成一首诗，也可以是很多别的东西。

★★ 我想请你注意第 ④ 类的措辞有多松：「可以是很多东西」。⇒ 这不是讲者偷懒，它恰恰反映了生成任务的本质 —— 输出空间是无限的，所以任务的边界也是模糊的。

⚠ 而这个模糊会在 L8 变成一个真问题：当「任务」本身都没法枚举时，你怎么评估一个模型好不好？ 讲者在 L4 结尾给过一个很诚实的回答：没有哪一个数字能告诉你你关心的东西。

⭐ 这是泰迪熊第一次出场，而我要提醒你：它会一直陪你到第九讲。后面你会看到「一只可爱的泰迪熊在读书」被拿来讲分词、讲注意力、讲端到端走查；L5 用「给泰迪熊建议一个活动」讲偏好对；L7 用「找一只附近的泰迪熊」讲工具调用、用「泰迪熊怕冷」讲 agent 循环。

数据集：典型会用情感抽取的数据集。我提到了影评，就是 IMDb 的评论。但你也有商品评论，比如 Amazon 的评论，或者推文 —— 现在它叫 X 了，所以是 X 上的帖子。

15:23But you also have two key metrics, which I am just going to remind

两个指标的定义，我建议你直接按讲者的句式记，因为那个句式本身就把分母说清楚了。

precision（精确率）：在你做出的所有正例预测里，哪些是正确的？

recall（召回率）：在所有真实的标签里，你正确地把多少个预测成了正例？

★★ 这两句的差别全在分母上，而这正是记住它们的窍门：precision 的分母是「你说是的那些」；recall 的分母是「真的是的那些」。

⇒ 由此可以直接推出两者各自会被什么「作弊」策略骗到：① 想要 precision 高？只在最有把握的那一个上说「是」 —— 分母只有 1，很容易全对；② 想要 recall 高？全都说「是」 —— 分母是全部真正例，而你一个没漏。

★ 所以它们必须成对看，单看任何一个都能被轻易操纵。这也正是下一镜 F1 存在的理由。

⇒ 而 L7 里那条「第一阶段的指标必须是 recall」现在就能理解了：检索的第一级宁可多留（牺牲 precision），也绝不能漏（保住 recall），因为漏掉的后面永远找不回来。

15:47And you have this metric called the F1 score

把两个指标合成一个数，用的是调和平均 —— 而「为什么是调和平均」值得想清楚。

讲者的话：而你有这个叫 F1 分数的指标，它基本上取 precision 和 recall 的调和平均，好给你一个数。

★★ 为什么是调和平均？因为它偏袒小的那一个。⇒ 用极端情形一验就明白：precision = 1.0、recall = 0.0 时，算术平均是 0.5（看起来还行），而 F1 = 2×(1×0)/(1+0) = 0。

⇒ 这正是我们要的行为：上一镜说过，precision 和 recall 各自都能被作弊策略单独做高。「只在最有把握的那个上说是」能把 precision 做到 1.0，但 recall 会趴在地上；「全都说是」能把 recall 做到 1.0，但 precision 会很低。★ 调和平均让这两种作弊都拿不到分 —— 你必须两个都不差。

⚠ 一个推论值得记：任何时候你想把多个指标合成一个数，都要先问「我希望它惩罚短板，还是允许长板补短板？」要惩罚短板就用调和平均（或取最小值），允许互补才用算术平均。选错了，优化出来的东西会往你没想到的方向跑。

16:26Because if you have a model that would predict everything as the majority class

讲者自己提出了那个该问的问题，而答案是一个你一定要有的警觉。

他的自问：「那你现在可能会想：为什么需要所有这些指标？」

短答：短的答案是：有时候你会遇到一些任务和数据集，它们的类别非常不平衡。⇒ 比如你可能有 99% 的数据集是正例标签，然后只有 1% 的数据集是负例。

⚠ 后果：而这时如果你拿 accuracy 这样的指标，它会非常误导人。因为如果你有一个模型，它把所有东西都预测成多数类，那你就会有一个「了不起的分类器」—— 但事实并不是这样。⇒ 所以这就是为什么 precision 和 recall 真正起作用。

★★ 把这个例子算一遍你会印象更深：一个什么都不学、永远输出「正例」的模型，在 99:1 的数据上 accuracy 是 99%。而它的 recall（对负例）是 0 —— 它一个负例都没找出来。

⇒ 所以这类情形下的正确做法是：永远先看数据的类别分布，再决定看哪个指标。⚠ 而更隐蔽的版本是：有人给你报了一个 accuracy，但没告诉你分布 —— 这时那个数字几乎没有信息量。

17:01And we are illustrating this with the NER task

第二个桶怎么评，讲者只用了两句话，但那两句话里有一个重要的概念。

他的话：我们用 NER 任务来说明这个桶 —— 如我提到的，它是关于识别给定词的类别。所以这里比如我们想识别出 teddy bear 是一个实体。

★★ 指标怎么用：「我想为此你会用分类指标，但不是在句子这一级上，而更多是在 token 这一级、或者在「实体类型」这一级上。」

⇒ 这正好印证了第 8 条里那句话：输出挂在哪一级，指标就得跟到哪一级。

⚠ 而「在哪一级算」这件事在实践中会显著改变数字，值得知道：同一个预测，按 token 算和按实体算可以差很多 —— 比如一个三词的实体你只标对了两个词：token 级会给你 2/3 的分，而实体级会判你全错（因为实体没有被完整识别出来）。

⇒ 所以读别人的 NER 结果时，第一件事是确认它是在哪一级算的，否则没法横向比。

17:31And by that I mean, let us suppose you have a category, let us say location

讲者把「实体类型级」这个说法展开了一句，而这一句包含了一个很实用的做法。

他的话：「我的意思是：假设你有一个类别，比如说「地点」。而你想知道你在那个类别里的词预测得有多好。那你通常就会把这些指标按那个类别来聚合。」

★★ 这个做法的价值在于它把一个总分拆成了可诊断的几个分：一个 0.82 的总体 F1 不告诉你任何可以行动的东西；而「地点 0.95 / 人名 0.88 / 组织 0.61」立刻告诉你该去修什么。

⇒ 这是一条非常通用的实验习惯：报总分的同时，按你关心的维度拆开报。⚠ 而它的反面也很常见：只报一个加权平均，于是某一类上的灾难被别的类掩盖掉了 —— 尤其当那一类样本少的时候。

⇒ 后面你会看到这条习惯在这门课里反复出现：L6 修长度膨胀时，证据不是「平均长度下降了」，而是「正确样本长度不变、错误样本长度大降」；L5 讲奖励模型时强调「奖励总是相对某个维度（有用/友好/安全）而言的」。⇒ 同一个判断，在三讲里换了三种面貌。

18:36And that one contains a bunch of paired sequences in different languages

生成任务的第一个麻烦出现在数据这一侧，而讲者点得很直接。

他的话：「至于这个任务，我想获取数据集更难一些，因为这里你需要有成对的文本。」

⇒ 想一下差别有多大：分类任务只要「一段文本 + 一个标签」，而标签可以很快打；翻译任务要「一段文本 + 它的完整译文」，而那等于让一个双语的人把整句重写一遍。

数据集：你有一个非常流行的数据集叫 WMT，它代表 Workshop on Machine Translation。那个数据集包含一堆不同语言之间的成对序列。

★ 而来源很有意思：比如你有英语—法语、英语—德语的，它们来自欧洲议会（European Parliament）的数据集。

⭐ 这个来源本身就说明了成对数据有多稀缺：人们不得不去找那些「因为别的原因，本来就被逐句翻成多种语言」的文本。欧洲议会的会议记录必须以全部官方语言发布，于是它就成了现成的平行语料。

⇒ 这类「借用因其它目的而天然成对的数据」的做法，在机器学习里是常见套路，值得记住它的形状。

把三个桶的数据代价并排看，一个很重要的结论就浮出来了。

代价梯度：① 分类 —— 一段文本配一个标签，标注者看一眼点一下；② 多分类 —— 每个词都要标，慢得多；③ 生成 —— 你要给出整段正确的输出，等于让标注者把这件事本身做一遍。

★★ 而这个梯度直接指向这门课后面最重要的一件事：既然生成任务的标注这么贵，那 LLM 是怎么训出来的？

⇒ 答案是：它根本不用这种标注。「预测下一个词」这个目标的妙处在于 —— 标签就是文本本身的下一个词，完全免费。⇒ 所以整个互联网都能直接当训练数据。

★★★ 讲者在 L4 会把这件事说透：预训练的目标就是预测下一个 token，而且标签免费；在 L2 他会给出一个更强的判断：「下一个词预测」之所以赢，不是因为它在每个任务上最好，而是因为它最能扩展。

⇒ 所以请把这个「数据代价梯度」记住：它是理解「为什么是这条路线赢了」的第一块拼图。

19:42Same story for ROUGE, which is actually a suite of metrics

既然没有唯一答案，人们退而求其次：和一份参考答案比。这就是 BLEU 和 ROUGE。

讲者的交代：在过去，人们用过好几种基于规则的指标来做这件事。其中一个你可能听过的是 BLEU。

BLEU：BLEU 代表 Bilingual Evaluation Under Study。而它是一个衡量「你的翻译相对于一份参考文本表现如何」的度量。

ROUGE：ROUGE 也是同样的故事 —— 它其实是一套指标，但以一种不同的方式捕捉这件事。

★★ 两者的共同点才是关键，而它也是它们共同的软肋：都要有一份参考答案。

⇒ 而「有参考答案」这件事，意味着你已经让人把活干了一遍 —— 也就是说你又回到了上一条那个昂贵的成对数据问题。

⚠ 讲者下一镜就会把这一点挑明。所以这两个指标虽然缓解了「没有唯一答案」，却没有缓解「要人来做」。

⇒ 顺带一提：你会在 L5 和 L7 再次见到这两个名字，而两次都是以「如今已经不太常用了」的身份出现的。

一个小插曲，但它顺带提醒了一件实用的事。

讲者的话（他本人是法国人，所以这个梗他说起来特别自然）：「而你会看到机器学习社区挺好玩的 —— 因为 BLEU，我不确定你懂不懂法语，意思是「蓝色」；而 rouge 的意思是「红色」。所以我猜他们是想在这里加点乐子。」

⭐ 这类「名字里藏梗」的习惯在这个领域确实很常见。但我想借这个机会提醒你一件更有用的事：这个领域里的名字分两种，而它们该用不同的方式对待。

① 藏梗的名字：BLEU / ROUGE 这种，名字和方法本身没有关系，记住就好，别想从名字推出什么。

② 藏设计的名字：这类才值得你去拆。比如 PPO 的 proximal（邻近的）—— 它直接告诉你「不想离基座模型太远」是这个算法的核心约束；RAG 是 Retrieve-Augment-Generate 三步的首字母，名字就是流程；GRPO 的 group relative 直接说明了它和 PPO 唯一的区别在「拿同组的其它回答当基线」。

⇒ 所以遇到一个新缩写时，先花三秒判断它属于哪一类。第二类的名字是免费的理解。

20:16It takes a lot of time, a lot of money to get labels

讲者把这两个指标的软肋挑明了，而这句话是后面好几讲的伏笔。

他的话：「但这些指标的问题是：你总是需要一份参考文本。所以你基本上需要标签。而在实践中，拿到标签是非常昂贵的 —— 它要花很多时间、很多钱。」

★★ 请看清这个困境的形状：我们本来是为了解决「生成任务没有唯一答案」才引入这些指标的；但这些指标自己又要求一份「答案」。⇒ 于是问题并没有被解决，只是被挪了个位置 —— 从「模型该输出什么」挪到了「谁来提供参考文本」。

⚠ 而「需要标签」这件事的代价在真实项目里被严重低估：讲者说的是「很多时间、很多钱」，而更麻烦的是 —— 每当你换一个任务、换一个领域、换一批 prompt，你就要重新标一遍。

★★★ 请体会这个转变的分量：评估的瓶颈从「人要写出标准答案」变成了「人只要能判断好坏」—— 而后者既便宜得多，也更容易由模型代劳。

20:46And then the last metric that I will say that people sometimes use is called perplexity

第三个指标，而它的性质和前两个完全不同 —— 这一点值得专门留意。

讲者的话：「然后最后一个我会说人们有时会用的指标，叫 perplexity（困惑度）。而 perplexity 只看模型输出的那些概率。它基本上量化的是「模型对它自己的输出有多惊讶」。」

★★ 请抓住那句「只看模型输出的那些概率」，因为它意味着一件大事：perplexity 不需要参考文本。

⇒ 这正好是上一条那个困境的一个出口 —— 虽然讲者没有在这里点破。

⇒ 它怎么做到的？因为它根本不问「输出对不对」，只问「模型对自己输出的这串东西有多确信」。

⚠ 而这也正是它的局限，你必须同时知道：一个模型可以非常自信地输出一串胡话。perplexity 低只说明模型觉得这串 token 很「顺」，不说明它是对的。

⇒ 所以它更适合用来衡量「这个模型对这种语言/这个领域熟不熟」，而不是「这次回答好不好」。★ 这个区分在读论文时很要紧：看到 perplexity 下降，别直接理解成「更有用了」。

21:10And I guess LLMs have been a hot topic since 2022

讲者特意把方向说了一遍，而这正是最容易出错的地方。

他的话：「所以 BLEU 和 ROUGE，越高越好。perplexity，越低越好。」

★★ 为什么方向会反？因为它们量的东西方向相反：BLEU 和 ROUGE 量的是「和参考答案有多像」—— 像得越多越好；perplexity 量的是「模型有多惊讶」—— 越不惊讶说明模型越觉得这串输出是顺理成章的。

⚠ 这类「方向性」的东西在这门课里会出现好几次，而每一次搞反都会让你把结论读成相反的：⇒ 后面你会遇到 损失（loss）要最小化、而 PPO 那个写成 L 的式子其实要最大化（讲者专门为这个停下来提醒过）；KL 散度越小越近；advantage 为正要强化、为负要压低。

★ 一个好用的习惯：每遇到一个新指标，先问「它越大越好还是越小越好，为什么」。「为什么」这一半很重要 —— 记住理由就不会记反，而死记方向则很容易混。

把这三个指标收一下，顺便说清它们今天各自的处境。

三者对照：BLEU / ROUGE 要参考文本、越高越好、是规则式的；perplexity 不要参考文本、越低越好、只看模型自己的概率。

★ 今天的处境：讲者在 L5 讲偏好数据怎么比较时，会把 BLEU、ROUGE 列为一个选项，然后补一句「不过如今已经不太常用了」；在 L7 讲 vanilla LLM 的弱点时，他又会用它们当反例 —— 传统 NLP 有 BLEU、ROUGE 这类规则指标，但 LLM 能做的事远超这些，所以非常难评估。

⇒ 而 perplexity 仍然在用：L3 讲 LLM 时它还会再出现一次（那里有它的公式）。

★★ 为什么 perplexity 活了下来？因为它量的是一件仍然有意义的事：这个模型对这种文本熟不熟。这在比较「同一个模型在不同领域上」或者「预训练到哪一步了」时仍然有用。

⚠ 而 BLEU/ROUGE 之所以退场，是因为它们量的那件事（和一份参考答案有多像）在开放生成的场景里已经不成立了 —— 当任务本身都没法枚举时，参考答案从何而来？

② 它帮你分辨「新东西」和「老东西换了名字」。这在一个高速变动的领域里特别重要 —— 你会看到很多概念其实是旧的（注意力是 2014 年的、RNN 是 80 年代的），而真正新的只有少数几个。

⇒ 对你为科研看这门课来说，第 ② 点尤其有用：能分辨哪些是真正的新贡献、哪些只是重新包装，是读文献最省时间的能力之一。

⇒ 下一条就走这条时间线。

21:50And I guess this was one of the limiting factors

时间线从很早开始，而讲者点出的「缺什么」是整条线的关键。

他的话：「所以在 80 年代 —— 我们待会就会看到 —— 有一类模型其实在 80 年代就被想出来了。而到了 90 年代，我们有了 LSTM，我们待会也会看到。」⇒ 他说的那两类就是本讲后面要讲的 RNN 和 LSTM。

★★ 然后是关键的那一句：「但问题是，在那个年代，我们没有互联网。我们没有很多算力。而我想这正是其中一个限制因素 —— 它阻止了今天这些模型在当时被训练出来。」

★★★ 请认真对待这句话，因为它纠正了一个很常见的误解：今天的成功不是因为「终于想出了正确的想法」。⇒ 想法在 80 年代就有了。变的是数据（互联网）和算力。

⚠ 而这个判断有一个对你做研究很实际的推论：当你看到一个旧方法「不work」时，要分清它是「想法错了」还是「当时条件不够」。这两者的处理方式完全不同 —— 前者该放弃，后者值得在新条件下重试。⇒ 深度学习本身就是这样回来的，而注意力机制（2014 年提出、2017 年才爆发）也是。

22:12And then, of course, we had the transformers

时间线的后半段，而讲者用一句话交代了 LLM 这个名字是怎么来的。

他的话：「然后更近一些，我们有了几项进展。Word2vec 真的是在「计算有意义的嵌入」这件事上的先驱工作之一 —— 我们待会就会看到它。」

⇒ 然后当然就是 transformers，它是 2017 年发表的一篇论文的一部分，而它基本上就是你今天看到的所有模型的基础。

★★ 然后是最关键的一步：「而这些模型随后就被规模化了 —— 既在算力上，也在用来训练它们的数据上。而这就是 LLM 这个名字的由来。我想这更像是 2020 年代的事。」

★★★ 请注意这里的因果：LLM 不是一种新架构，它就是「被规模化了的 transformer」。⇒ 讲者在 L3 会把这件事说得更明确（他会给 LLM 下一个定义）；而 L4 整整一讲都在讲「规模化」具体是怎么做到的（数据从哪来、算力怎么量、固定预算下模型该多大、一块 GPU 装不下怎么办）。

⇒ 所以这条时间线的形状是：想法（80s–2017）→ 条件到位（互联网 + 算力）→ 规模化（2020s）。而这门课的九讲，几乎全部落在最后那一段上。

22:53Everyone good?

高层概览结束，讲者抛出了这门课真正的第一个问题 —— 而它简单得有点朴素。

他的过渡：关于高层的部分，有什么问题吗？大家都还好？好的。

★★ 然后是那个问题：「我想我想问我们自己的第一个问题是：我们想要的是一个能处理文本的模型。但模型懂的是数字，它们并不真的懂文本。所以我们得对那段文本做点什么，让它变得更可量化 —— 变成某种模型能理解的东西。」

★★★ 这句话是接下来一大段内容的全部动机，值得你带着它往下听：⇒ 分词（tokenization）回答「怎么把文本切开」；one-hot 回答「怎么给每一块一个数字表示」；Word2vec 回答「怎么让这些数字表示是有意义的」；RNN 回答「怎么把顺序也编进去」；而注意力回答「怎么让每个词的表示依赖于上下文」。

⇒ 这五步是一条连贯的、每一步都在修上一步缺陷的链条。这个片子接下来会一步步跟着它走。

⭐ 而我建议你每学完一步就问一句：「到这一步为止，我的表示还缺什么？」—— 下一步基本上就是在补那个缺口。

23:23So if you look at a sentence, for instance, a cute teddy bear is reading

模型只懂数字，所以第一步是把文本切成块。这一步的名字你会用一整门课。

讲者的问法：「所以如果你看一个句子，比如「a cute teddy bear is reading」，你首先得问自己：你要怎么切这个句子，才能把它传给模型？」

★ 名字与定义：这一部分叫 tokenization。而它所包含的，基本上就是「按照某个任意的文本单位去切分文本」。⇒ 顺便说，这个文本单位叫做 token，这也正是这个方法被叫做 tokenization 的原因。

★★ 请特别留意「任意的（arbitrary）」这个词，因为它是整段的钥匙：切法是人定的，不是语言自带的。⇒ 这意味着不存在「正确的切法」，只存在「各有利弊的切法」—— 而接下来一整段就是在比较这些利弊。

⚠ 而这个「任意性」在今天仍有实际后果，值得你知道：不同模型的分词器不一样，所以同一段文本在不同模型里 token 数不同。⇒ 这直接影响你的账单（按 token 计费）、也影响能塞进上下文的内容量。「这段文本有多少 token」不是文本的属性，是「文本 + 分词器」的属性。

23:54I guess the first way is doing it completely arbitrarily

第一种切法，而讲者举的例子里藏着一个重要的暗示。

他的话：「我想第一种方式是完全任意地切。比如这里，你会有「a」—— 那是一个文本单位；「cute」可以是另一个文本单位；「teddy bear」会是又一个，依此类推。」

★★ 请留意「teddy bear」被当成了一个 token —— 它是两个英文词。

⇒ 这个细节说明了「任意」是真的任意：token 的边界不必和「词」的边界对齐。而这在今天的分词器里是常态：常见的多词短语可能是一个 token，而一个罕见的长词可能被切成四五个 token。

⚠ 一个你可以自己验证的现象：常见词往往是一个 token，而生僻词、专有名词、数字、代码符号往往被切得很碎。⇒ 这意味着「一段文本有多贵」和它的内容强相关 —— 一段普通英文和一段同样长度的代码或化学式，token 数可以差好几倍。

⇒ 这一点在你做预算估算时会直接影响结论，值得记住。

24:25But I guess we would have always pros and cons

讲者在比较切法之前，先立了一个判断标准 —— 这一步很讲究，值得学。

他的话：「另一种方式是干脆按词来分。但我想我们总是会有利弊。我想我们想达成的目标之一，是接下来我们要能够「有意义地表示」这些 token。」

★★ 请注意他做了什么：他没有直接说哪种切法好，而是先说清「我们要拿切出来的东西干什么」。⇒ 有了这个标准，后面所有比较才有依据。这个习惯很值得照搬：比较几个方案之前，先把评判标准摆出来，否则讨论会变成各说各话。

⚠ 词级的坏处：「按词级切的一个坏处是：你最终会得到一些「看起来很像、但实际上被当作不同 token」的词。」⇒ 而这里的限制在于：你得为这些相似却不同的 token 都算出嵌入，然后还得想办法让它们的嵌入彼此相似。

★ 想清楚这个代价有多实在：模型并不知道 bear 和 bears 有关系。它们是两个独立的符号，各自有一个要从数据里学出来的向量。如果某个形式在训练数据里出现得少，它的向量就学不好 —— 而这纯粹是切法造成的，不是语言本身的问题。

25:27If we go ahead with the word-level tokenization, then we will end up with just two different entities

讲者给了两个最直白的例子，而它们说明了词级切法的结构性浪费。

他的话：「我给你举个例子。假设我有一个词「bear」，然后你有另一个词、它的复数形式「bears」。这两个词非常相似，只是一个单数、一个复数。而如果我们采用词级分词，那我们最后就只会得到两个不同的实体 —— 它们基本上就被当成不同的东西。」⇒ 「run」和「runs」也是同样的情况，动词的各种变形。

★★ 这个浪费是双重的，值得拆开看：① 词表空间 —— 每个变形各占一个位置，而词表大小直接决定模型输出层的大小；② 学习效率 —— 模型在 bear 上学到的东西，完全不会自动迁移到 bears 上。

⇒ 讲者自己说了这个代价：你得为这些相似却不同的 token 各算嵌入，还得想办法让它们相似。注意「想办法让它们相似」这件事是额外的负担 —— 而一个更聪明的切法可以让它免费发生。

⚠ 一个本讲没提、但值得你知道的事：英语的形态变化其实算少的。换成德语、俄语、芬兰语这类变位/变格丰富的语言，同一个词根能派生出几十上百个形式，词级切法在那些语言上几乎不可用。

25:42So for that reason, people have dug into a category of tokenizers that are called subword tokenizers

第三种切法，也是今天的主流。而它正是为了修掉上一条那个浪费。

讲者的话：「所以出于那个原因，人们深入研究了一类叫做 subword tokenizer（子词分词器）的东西 —— 它是围绕「利用词根」来做的：去找出我们能在这些词里找到的公共词根。」

例子：比如对 bear 和 bears，你会有一个「bear」这个部件是被共享的。

★★ 为什么这一下就解决了上一条的问题：既然 bear 和 bears 共享同一个部件，那模型在那个部件上学到的东西就自动被两者共享了。⇒ 不再需要「想办法让它们的嵌入相似」—— 相似性是切法本身送的。

★ 讲者的利弊总结：「我想好处是你得以利用词根。但这里的坏处是：你的序列会变长。而我们会看到为什么这是个坏处。」

⇒ 请注意他说「我们会看到为什么这是个坏处」—— 他知道「序列变长」这件事本身听起来不像个问题，所以他接下来专门解释。下一镜就是那个解释，而它引出了这门课最重要的一个量。

26:28I guess later on, I guess I can give you a preview

这一镜是讲者主动提前剧透的，而它剧透的东西会贯穿后面好几讲。

他的话：「我想在后面 —— 我想我可以先给你剧透一下。这些模型的复杂度也是序列长度的一个函数。所以你要处理的 token 越多，你的模型跑起来就越久，因为它基本上得处理所有这些 token。」

★★★ 这句剧透的分量远超它的篇幅，因为「复杂度是序列长度的函数」是这门课后面一长串内容的共同根源：

⇒ L1 后面你会看到自注意力要算 QKᵀ —— 那是一个 n×n 的矩阵，n 是序列长度，所以是平方级的。

⇒ L2 的滑动窗口注意力（sliding window）就是为了把这个平方级降下来。

⇒ L3 的 KV 缓存、PagedAttention、MLA，全都是在对付「序列一长、显存和时间就炸」。

⇒ L4 的 FlashAttention 更是直接冲着这个来的。

⇒ L7 的「上下文有限」「大海捞针」也是同一个限制的另一面。

★ 所以现在就把这句话记牢：token 数不是免费的。它既是钱（按 token 计费）、是时间（复杂度）、也是能力（上下文装得下多少）。

把这笔交易并排写清楚，子词级为什么成为主流就一目了然了。

讲者的小结：「所以 pro 是它利用了词根；con 是它让你的序列变长。」

★★ 换来的那一侧值得多说一句：除了「相似词的表示自动相关」，还有一个讲者没明说但很实在的好处：词表可以小得多。⇒ 因为你不必为每一个变形、每一个罕见词各留一个位置 —— 你只要存下那些部件。而词表大小直接决定模型输出层（softmax 那一层）的大小，所以这是实打实的节省。

★ 而为什么这笔交易划算，可以这么看：序列变长带来的代价是「线性到平方级」的计算增加，而它换来的是「表示质量」和「词表规模」上的根本改善。⇒ 前者可以靠工程优化（FlashAttention、KV 缓存）缓解，而后者是切法层面决定的、事后补不回来。

⇒ 这是一个在系统设计里常见的判断：宁可接受一个可以靠工程缓解的代价，也不要接受一个结构上补不回来的缺陷。

这一镜是方法论，不是新内容 —— 但我认为它值得占一镜。

观察：讲者对每一种切法都走同一个三段式：① 想法是什么；② pro 换来了什么；③ con 付出了什么。

★★ 而最值得学的是第 ③ 步里他多做的那一件事：他会解释「为什么这是个代价」。⇒ 「序列变长」听起来完全不像问题 —— 直到他说了「模型复杂度是序列长度的函数」。有了这句话，这个 con 才真的站得住。

⇒ 对比一下：如果他只说「子词级的缺点是序列更长」，你会点头，但不会真的在意；而他多说的那一句，让这个缺点有了量级、有了后果。

⚠ 而反过来读别人的论文时，这也是一个检验点：一个只列出局限却不说明后果的工作，往往是作者自己也没量过。

27:05You have a last category of ways of tokenizing things

第四种也是最后一种切法，而它的强项很具体。

讲者的话：「你还有最后一类切分方式，就是直接在字符这一级做 —— 就是把字符一个个取出来。」

★★ 为什么字符级对拼错鲁棒，值得想清楚机制：子词分词器的部件是从训练数据里统计出来的 —— 它只认识见过的那些片段。一个拼错的词（比如 teddi）可能没有任何一个它认识的部件能对上，于是会被切得乱七八糟，和正确拼写的 teddy 完全不像。

27:36And this is something that the character-level tokenizer can, I guess, take into consideration

字符级的第一个代价，而它正是上一条那句剧透的直接后果。

讲者的话：「但这里的问题是：你的序列长度会长得多得多，这会让你的模型处理这个序列花多得多的时间。所以这是一个坏处。」

★★ 把量级感受一下：同样一句 「a cute teddy bear is reading」，子词级大概切成六到八个 token，而字符级是二十八个字符（含空格）。⇒ 差了三四倍。

⚠ 而按上一条那句剧透（复杂度是序列长度的函数），这个差距的后果比看上去严重：你后面会学到自注意力要算一个 n×n 的矩阵 —— 序列长三倍，那个矩阵就大九倍。

⇒ 所以字符级的代价不是「慢三倍」，在注意力这一环是「慢九倍」。

★ 这就是为什么字符级虽然有明显优点，却没有成为主流 —— 它在最贵的那个环节上被惩罚得最狠。

⇒ 顺带一提：这也解释了为什么 L2 要花力气讲滑动窗口注意力 —— 那是在想办法让「长序列」这件事不那么贵。

27:55And then the other con is, I guess, when you want to represent each of these tokens

字符级的第二个代价，而它正好撞上了讲者一开始立的那个判断标准。

他的话：「然后另一个坏处是：当你想表示这些 token 中的每一个时，我想很难知道一个字母的表示究竟意味着什么。比如字母 U 的表示代表什么？这非常难。」

★★ 回想第 15 条里他立的标准：「我们想达成的目标之一，是能够有意义地表示这些 token」。⇒ 而字符级在这个标准上是明确输的 —— 「bear」这个部件可以有一个有意义的向量（关于熊的某种语义），而「b」这个字母的向量代表什么，确实说不出来。

★★★ 这一条揭示了分词这件事的一个核心张力，我建议你把它单独记住：切得越细，越不会遇到没见过的东西（OOV 风险低）、也越对拼写错误鲁棒；但切得越细，每一块本身就越没有意义。⇒ 反过来，切得越粗，每一块越有意义，但越容易碰到没见过的。

★ 而子词级之所以是今天的主流，正是因为它在这条轴上坐在中间：部件通常对应词根或常见片段（有意义），而罕见词可以被拆成已知部件（OOV 风险低）。⇒ 讲者后面回答学生提问时会把这一点明说：subword 是一个很好的折中。

28:37And I did not mention this, but there is a term

这一条是整个分词段落里最要紧的概念，而讲者是以「我刚才忘了说」的方式补上的。

他的话：「我刚才没提这个，但有一个术语。每当你切完东西，然后在推理时你想做预测，我想你有一个前提条件是：你在训练时见过的那个 token，你需要它在你的训练集里。」

⇒ 而问题是：假设在推理时你把文本切成词，再假设你碰到一个训练时没见过的词 —— 你就只能把它标成「未知」。而这个东西叫 OOV，Out Of Vocabulary（词表之外）。

★★ 请把 OOV 的机制想清楚，因为它不只是一个术语：模型的输入层是一张查找表：每个 token 对应一行向量。碰到表里没有的 token，就没有向量可查。⇒ 于是只能用一个专门的「unknown」槽位 —— 而那个槽位里所有不认识的词共用同一个向量。

⇒ 后果很直接：模型对那个词一无所知，而且把它和所有其它不认识的词混为一谈。

⚠ 所以 OOV 不是「少学到一点」，是「这个位置的信息被彻底抹掉了」。这就是为什么降低 OOV 风险是选分词器时的首要考虑。

29:09And let us suppose you have not seen a word at training time

三种切法在 OOV 上正好排成三档，而讲者在后面回答学生提问时又确认了一次。

他的小结：幸运的是，子词级的分词器缓解了那个问题。所以你有更低的 OOV 风险，但仍然可能有。

30:43Or I guess, in a more correct way, it should be token representation

分词完了，现在要给每一块一个数字表示。讲者从最朴素的做法讲起。

⭐ 留意「teddy bear」在这里仍然是一个 token（不是两个）—— 和分词那一段的设定一致。讲者在整讲里保持了这个一致性，这让例子可以一路用下去。

★★ 而「one-hot」这三个字本身就说明了做法：一个向量里只有一个位置是 1（hot），其余全是 0。⇒ 向量的长度就是词表大小，每个 token 占一个位置。

31:14That is 1, 0, 0 vector

三个具体的向量，以及这一讲的又一个缩写。

讲者的话：「我们会有，比如说 soft，那是 (1, 0, 0) 向量；teddy bear，那是 (0, 1, 0) 向量；而 book，那是 (0, 0, 1) 向量。所以这叫做 One-Hot Encoding，OHE —— 你会经常见到。」

★ 这是本讲的第三个缩写了（NLP、OOV、OHE），而它们正好印证了讲者开场那个免责声明：这个领域全是缩写。

⇒ 这说明了一件事：one-hot 向量里没有携带任何关于「这个 token 是什么」的信息。它只是一个编号的另一种写法。而「编号」这件事本身，就是下一条问题的来源。

31:37But basically what people want to do is compare these tokens

讲者在这里转了一个很关键的弯：他不问「这个表示好不好」，而是问「我们拿它干什么」。

★★ 请注意这个提问方式有多重要：如果只看 one-hot 本身，它没什么毛病 —— 每个 token 有一个唯一的向量，清清楚楚。⇒ 只有当你说出「我要用它来比较相似度」时，它的缺陷才暴露出来。

⇒ 这和第 15 条里他先立判断标准是同一个手法：一个表示的好坏，取决于你要拿它做什么。而这一次，用途是「比较相似度」。

32:14And if, I guess, they are pointing in the same direction, then maybe they are similar

余弦相似度的直觉，讲者讲得非常朴素 —— 他没有推公式，而是直接给几何图像。

他的话：「你可以把它想成：就是看这些向量在 n 维空间里成了什么样的夹角。而如果它们指向同一个方向，那也许它们是相似的；如果它们正交，那也许它们是独立的；而如果它们完全相反，那也许它们是相反的。这基本上就是我们想要进入的那个心智模型。」

★★ 三档值得按他的话记住，因为它们各有明确含义：同向（夹角 0°，余弦 1）⇒ 相似；正交（夹角 90°，余弦 0）⇒ 独立、无关；相反（夹角 180°，余弦 −1）⇒ 意思相反。

⇒ 注意中间那一档「正交 = 独立」是关键 —— 下一条的整个问题就建立在它上面。

⚠ 而讲者用词很谨慎，三次都说了「也许（maybe）」。这个谨慎是有道理的：余弦相似度只是一种度量，它和「语义相似」之间的对应关系是我们希望的，不是保证的。⇒ 他在后面回答学生提问时会把这个谨慎说得更明白：这是一种度量，不是完美的度量。

32:47So ideally, what we want is for tokens that mean the same or similar to basically have a high similarity

这是 one-hot 的致命伤，而它是上一条那个心智模型的直接后果。

讲者的话：「所以问题是：如果你用 one-hot 的方式表示你的 token，你最后会得到所有的向量彼此两两正交。所以这就是问题所在。」

★★ 为什么必然正交，值得自己算一遍：soft = (1,0,0)、teddy bear = (0,1,0)。点积是 1×0 + 0×1 + 0×0 = 0。⇒ 而这不是巧合：两个不同 token 的那个「1」一定在不同位置，所以逐位相乘必然处处为 0。

★★★ 把这个数学事实翻译回语义，问题的严重性就出来了：按上一条的心智模型，余弦为 0 意味着「独立、毫无关系」。⇒ 所以 one-hot 表示在说：词表里任意两个词之间都毫无关系。

⇒ 「cat」和「dog」毫无关系；「bear」和「bears」毫无关系（这正好接上分词那一段的抱怨）；「happy」和「joyful」也毫无关系。

★★ 而 Word2vec 的妙处在于它用同一个办法把两件事一起修了：⇒ 把 one-hot 向量乘上一个矩阵，得到一个低维的稠密向量（修掉 ②）；而这个矩阵是通过一个「预测上下文」的任务学出来的，于是经常一起出现的词会得到相近的向量（修掉 ①）。

问题：one-hot 里确实没有相似度。那我们希望的那个相似度，信息从哪来？

★★ 它不可能凭空出现。没有人会去手工标注「teddy bear 和 soft 相似度 0.8」 —— 那样的话词表几万，要标的对数就是几亿。

★★★ 线索就是那条著名的假设：意思相近的词，会出现在相近的上下文里。⇒ 「软的玩具」「软的枕头」「软的毯子」—— soft 周围反复出现一类词；而 teddy bear 周围也会出现 soft、cute、hug 这些。于是「谁和谁常一起出现」这件事，就隐含了「谁和谁相似」。

两个度量的实际差别：余弦相似度只看方向，所以两个向量不管多长，只要指同一个方向就是 1。点积则把长度也算进去，所以一个很长的向量和谁算都容易得到大值。

37:49So now that we know that the one-hot encoding is not a good way to represent tokens

这是整段的转折点，而它的形状比内容更值得记。

38:19And the reason why it was so popular is because they showed a very intuitive and interpretable way

Word2vec 为什么出名，讲者给的理由不是「效果好」，而是「它让人看懂了」。

★★ 这些类比之所以震撼，在于它们是向量运算上成立的：著名的那个形式是 king − man + woman ≈ queen。⇒ 也就是说，「性别」这个概念在向量空间里对应一个固定的方向；而 Paris − France + Germany ≈ Berlin 说明「首都关系」也是一个方向。

★★★ 而这件事为什么重要？回到上一镜的那个代价：学出来的维度本来没有人能解释。⇒ 而 Word2vec 显示：虽然单独一维没有名字，但向量之间的「方向」是有结构的。意义不在坐标轴上，在相对关系里。

当时的目标：teddy bear 和 soft 相似度高，teddy bear 和 book 接近 0。⇒ 也就是说，我们只要求「相似的靠近、不相似的远离」。

★★ 而这个「附带」的部分才是它出名的原因，这一点很值得体会：没有人在训练目标里要求过「性别方向要一致」。训练目标只是「用上下文预测词」。而类比结构是自己冒出来的。

38:51The other one was called skip gram

Word2vec 有两种算法，但讲者立刻强调了它们的共同点。

他的话：「所以现在的问题是：他们是怎么做到的？他们有两种计算这些 embedding 的方式。一种叫 continuous bag of words（连续词袋，CBOW），另一种叫 skip gram。」

两者的区别：比如 continuous bag of words，目标是把一个给定目标词「周围」的词考虑进来，而你的目标是预测那个目标词。⇒ 而 skip gram 正好相反：你从一个目标词出发，想预测它周围的那些词。

★★ 但讲者立刻把重点拉回共同点：「但它们都依赖同一个想法，那就是：让我们利用手上已有的文本，然后试着基于比如上下文，去预测文本的一部分。」

⇒ 请注意这句话里最关键的是「手上已有的文本」—— 不需要任何标注。⇒ 这正是第 11 条那个「数据代价梯度」里说的事：这类任务的标签是文本自己提供的，所以完全免费。

39:25And skip gram is the opposite

★★ 「proxy」就是「替身、代理」的意思。而要理解它，得先问：它在替谁？

⇒ 答案是：替「学出有意义的词表示」这件事。

⚠ 为什么需要一个替身？因为「有意义的词表示」没法直接拿来训练：你没法写出一个损失函数说「让这个向量更有意义一点」—— 「有意义」不是一个可以求导的量。

★★★ 所以代理任务的逻辑是：找一个「可以训练」而且「做好了就说明学到了我想要的东西」的任务，训它，然后把中间产物拿走。

⇒ 这个套路在机器学习里极其普遍，而且它正是这门课后面好几件事的原型：L2 的 BERT 用「填空」当代理学通用表示；L4 的预训练用「预测下一个 token」当代理学语言结构；L7 的 Sentence-BERT 用「相关的余弦高、不相关的低」当代理学检索用的嵌入。

41:01So here what we take is a very vanilla neural network model

网络本身极其简单，而它的要害在两个维度的关系上。

讲者的描述：「所以这里我们拿的是一个非常原味（vanilla）的神经网络模型，它基本上接收一个大小为 v 的向量，做一次乘法加一个偏置项得到一个隐状态，然后再做一组乘法得到我们的最终向量。所以这里基本上就是一个非常简单的神经网络。」

两个维度：输入的大小是 v（也就是词表大小，因为输入是 one-hot）。隐层的大小是 d，而 d 通常比词表小得多。

★★★ 「d 远小于 v」这一句就是整个设计的要害，值得停下来想清楚：⇒ 这意味着信息必须被压缩。几万维的 one-hot 要挤进几百维，而且还要能预测出下一个词。

⇒ 而正是这个「挤」的过程，逼出了我们想要的东西：既然维度不够，那就只能把「行为相似的词」安排到相近的位置上。⚠ 如果 d 和 v 一样大，网络完全可以把每个词放在互不相干的位置上 —— 那就学不出任何相似度。

★ 所以「压缩」不是为了省内存，它是学出相似度的必要条件。

41:33The hidden layer is of size d, which is typically much smaller than the vocabulary

两个维度的量级，而 768 这个数字你会一直见到。

讲者的话：「所以词表通常是几万或者几十万。而 d 通常是几百 —— 比如 768 就是一个维度的例子。所以它小得多、小得多。」

★ 768 这个数字值得记住，因为它在这个领域里几乎是个文化符号：⇒ 它是 BERT-base 的隐层维度，而因为 BERT 的影响力，后来无数模型和工具都沿用了它。⇒ 讲者在后面回答「隐层该多大」时会再提一次：768 这些数字是人们通常会取的。

★★ 压缩比值得算一下：词表五万、隐层 768 ⇒ 压缩了约 65 倍。而如果词表是几十万，压缩比还要高好几倍。

⇒ 想想这意味着什么：几十万个词，每个都要在 768 维里找到自己的位置，而且位置之间的关系要能反映语义。⚠ 这里有一个很容易被忽略的事实：768 维空间能装下的「彼此近似正交」的方向，远多于 768 个。⇒ 这就是为什么压缩这么狠还能工作 —— 高维空间比我们的三维直觉「宽敞」得多。

这一镜是我补的一层解释（讲者没有明说），但它能让后面那几镜一下变清楚。

观察：one-hot 向量 (0, 1, 0, 0, 0) 乘一个矩阵，结果是什么？⇒ 因为只有第 2 位是 1、其余全是 0，所以结果就是那个矩阵的第 2 行。

★★★ 所以「one-hot 乘矩阵」这个运算，实际上就是一次查表。⇒ 而那个矩阵，每一行正好对应词表里的一个 token。

⇒ 于是结论很漂亮：那个矩阵就是「嵌入表」，它的第 i 行就是第 i 个 token 的 embedding。

★ 这一点之所以重要，是因为它解释了第 27 条里那个关键动作：讲者会说「我们要把模型学到的那个表示拿走，就是绿色那些单元」。⇒ 而现在你知道了：所谓「拿走绿色单元」，就是把这个矩阵保存下来，以后直接查表用。

⚠ 而这也解释了为什么实现里根本不会真的去做那个矩阵乘法：既然是查表，直接按下标取那一行就行了。⇒ 这在代码里叫 embedding lookup，是个纯粹的索引操作。

41:33So vocabulary is typically like tens of thousands or hundreds of thousands

这一镜也是我补的，但它说明了一件对后面很有用的事：这个网络的代价不在输入端，在输出端。

输入端（v → d）：如上一镜所说，它只是一次查表。虽然嵌入表本身有 v×d 个参数（几万乘几百，也不小），但每次前向只取一行。

⚠ 输出端（d → v）：这一侧要算出词表里每一个词的概率。⇒ 所以它是一个 d × v 的矩阵，而且每次前向都要把全部 v 个输出算出来，再做 softmax。

★★ 于是词表大小的成本就清楚了：它不在「存」，在「算」。⇒ 词表从五万涨到五十万，输出层的计算量就涨十倍 —— 而这个开销每生成一个 token 都要付一次。

⇒ 这解释了第 22 条里那句话：词表大小直接决定输出层 softmax 的大小，这是生成的固定开销之一。

★ 顺带一提：这也是 Word2vec 原论文里有那么多「怎么避免算全部 softmax」的技巧的原因（负采样、层次 softmax）。讲者没有讲这些，因为它们不影响理解机制。

42:12So let us go with the first word of the sequence

现在走一个具体的前向，而讲者先打了个招呼。

他的声明：「顺便说，我把 token 和 word 混着用。」⇒ 这和第 18 条那个自我更正（「word representation 更正确地说该叫 token representation」）是一回事：术语是历史遗留的，而讲者选择不在措辞上纠缠。知道就行。

这一步做什么：「我们从序列的第一个词开始。假设我们有词「a」，而我们想预测下一个词，也就是词「cute」。所以我们做的是：拿词「a」，取它的 one-hot 编码表示，把它传进网络。」

★★ 请注意这个任务的设定有多朴素：输入一个词，输出下一个词。没有上下文、没有顺序信息、没有注意力 —— 就是一个词进、一个词出。

⇒ 而这个朴素正是后面一连串改进的起点：RNN 会加上「之前所有词的记忆」；注意力会加上「直接看任意位置」。⇒ 所以请记住这里的局限：这个网络对「a」的表示，和它出现在哪句话里完全无关。这正是本讲最后那个学生问到的问题（同形不同义怎么办）的根源。

前向的第一步，而这一步就是上一条讲的那个「查表」。

讲者的话：「所以这里，如果你熟悉神经网络的话 —— 这里你有一个矩阵和这个向量之间的乘法。于是你有一个隐状态的表示，它是一个大小为 d 的向量。所以这里，假设它是 0.2 和 0.9，也就是 d 等于 2。」

⚠ 请记住 d = 2 只是为了能画在幻灯上。真实的 d 是几百（讲者刚说过 768）。

★★ 而按第 25 条最后那一镜，这一步的实质是：把嵌入表里对应「a」的那一行取出来。⇒ 所以 (0.2, 0.9) 就是词「a」此刻的 embedding。

⇒ 「此刻」这两个字很重要：它现在还是随机初始化的、没有意义的；要经过大量训练之后，它才会变成有意义的那个向量。

★★★ 所以整个训练过程，本质上就是在反复调整这张表里的每一行。⇒ 而调整的依据，是「用这一行去预测下一个词，预测得准不准」。这就是代理任务起作用的地方。

43:07And then you get, after softmax, a set of probabilities

前向的第二步，输出端。

讲者的话：「然后你有另一次传递。然后在 softmax 之后，你得到一组概率，它们是关于「下一个词是什么」的。所以在这个例子里，我们有一个大小为 6 的词表。所以第一个词以 0.2 的概率被预测，第二个词 0.4，然后在这个例子里其它词都是 0.1。」

★ 验一下：0.2 + 0.4 + 0.1×4 = 1.0。⇒ 这是 softmax 的作用：把任意一组实数变成一个合法的概率分布（都非负、加起来是 1）。

★★ 这个输出的形状值得记住，因为它从这里一直延续到 LLM：输出永远是一个「词表大小」的概率向量。⇒ 本讲最后 Shervine 的端到端走查里，解码器的最后一步也正是这个：线性投影 + softmax，得到词表上的一个概率分布。

⇒ L3 讲解码策略（贪心、beam search、top-k、top-p、温度）时，所有策略都是在对这个向量做文章。

⚠ 而第 25 条最后说的那个成本也在这里：这个向量有多长，取决于词表多大，而它每一步都要算一遍。

43:36So let us suppose that we want to somehow be able to maximize our prediction

现在到了「教」的部分，而讲者把监督信号的形式说得很清楚。

他的话：「假设我们想要以某种方式能够最大化我们的预测，让它是词表里的第二个词，也就是那个 0.4。所以我们基本上是把预测结果和 (0, 1, 0, 0, 0) 去比较 —— 那是词表里第二个词的表示。然后我们做反向传播，更新权重。」

★★ 请看清这里的结构：「真值」也是一个 one-hot 向量。⇒ 模型输出的是一个概率分布 (0.2, 0.4, 0.1, 0.1, 0.1, 0.1)，而真值是 (0, 1, 0, 0, 0, 0)。训练就是让前者去靠近后者。

⚠ 注意一件事：真值要求的是「第二个词的概率是 1，其余全是 0」。也就是说，训练目标要求模型「完全确定」。

★★★ 而这件事在本讲最后会被专门拿出来质疑 —— 那就是 label smoothing。讲者会说：在 NLP 里，当你想预测接下来是什么时，通常不止一种可能（「what a great day / lecture / book」）。⇒ 所以逼模型说「就是这个、100%」其实是不合理的。label smoothing 就是把那个 1 改成 1−ε，把 0 改成 ε/(v−1)。⇒ 现在先记住这个「强行要求确定」的设定，等到那一条你会立刻明白它在修什么。

44:14But the idea here is, once you obtain a prediction, you compute the loss

反向传播这一段，讲者照例没有假设大家都懂。

他的话：「我不确定是不是每个人都熟悉那一部分。但这里的想法是：一旦你得到一个预测，你计算损失 —— 通常是交叉熵，它会决定你离真实答案有多远。而基于那个差距，你就去更新权重，好让你的预测更接近真值。所以这就是你做的事。然后你重复这个过程。」

★ 交叉熵在这里是自然的选择，理由值得点一句：⇒ 模型输出的是一个概率分布，真值也是一个（退化的）概率分布。比较两个概率分布的标准工具就是交叉熵。

⚠ 而交叉熵在真值是 one-hot 时会简化成一个很简单的形式：只剩下「−log(目标词的概率)」这一项。⇒ 因为真值里其余位置都是 0，乘进去就没了。

★★ 这个简化形式很好记，也很有解释力：你给正确答案的概率越高，损失越小。⇒ 而且因为是 log，当你给正确答案的概率接近 0 时，损失会趋于无穷大 —— 也就是说，「把正确答案判成几乎不可能」会受到极重的惩罚。

44:45So the one-hot encoding representation is 0, 1, 0, 0, 0

第二轮，而对照两轮的隐状态能看清嵌入表的结构。

讲者的话：「然后你重复那个过程。假设你拿词「cute」—— 如我们所说它是词表里的第二个词。所以 one-hot 编码表示是 (0, 1, 0, 0, 0)。你过一遍那个网络，你有一个隐状态，比如向量是 0.8 和 0.4。你再做一次。而你想做的是预测下一个 token，这里是 teddy bear。」

⇒ 而你看到现在在这个例子里，你的模型预测下一个词是均匀的，但你想以某种方式最大化 teddy bear 的概率。

★★ 对照两轮的隐状态：「a」是 (0.2, 0.9)，「cute」是 (0.8, 0.4)。⇒ 不同的词，不同的行 —— 这就是嵌入表。而训练要做的，就是让这些行慢慢移动到「有意义」的位置上。

⚠ 「预测是均匀的」这个细节也值得留意：它说明模型此刻什么都还没学会（均匀分布 = 完全没有偏好）。⇒ 训练的全部作用，就是把这个均匀分布推成「在正确答案上尖起来」的形状。

45:19So you go about doing this again and again for all the words

这是整段 Word2vec 的收官动作，也是「代理任务」这个概念最直观的体现。

讲者的话：「所以你就这样一遍又一遍地对所有的词做下去。而到最后，你得到一个学会了怎么预测下一个词的模型 —— 那基本上就是那个代理任务。而你要做的是：把模型学到的那个表示拿走，也就是那些绿色的单元。」

★★★ 请体会这个动作的果断：我们辛辛苦苦训了一个「会预测下一个词」的模型，然后把这个能力丢掉，只留下中间那一层。

⇒ 这正是第 24 条里「代理任务」定义的兑现：任务本身不是目的，它只是一个为了逼出好表示而设的借口。

★ 而「绿色的单元」具体是什么？按第 25 条最后那一镜：就是那张嵌入表 —— 也就是输入端那个矩阵。⇒ 所以「拿走绿色单元」= 把那个 v×d 的矩阵保存下来。

⚠ 一个有意思的对照：这个「训一个任务、丢掉任务、留下中间层」的套路，在今天仍然到处都是。L2 的 BERT 就是这么用的（预训练完，把 encoder 拿去做下游任务）；而 L4 的「预训练 + 微调」范式，本质上也是同一件事的放大版。

45:54And you just multiply this with these weights, and then you obtain the green representation

训完之后怎么用，讲者说得很简单。

他的话：「所以现在发生的事是：每当你有一个词，你就把它表示成 one-hot 编码表示，然后你把它和这些权重相乘，于是你就得到那个绿色的表示。而那就是你的词表示。」

★ 而按第 25 条那一镜，这一步的实质就是按下标取出嵌入表的那一行。⇒ 所以训练很贵，但使用几乎免费。

★★★ 这个「训练一次、到处复用」的性质值得单独点出来，因为它是一个范式的雏形：⇒ 你训一次 Word2vec，得到的词向量可以给任何下游任务用 —— 情感分析、NER、翻译，都能拿这些向量当输入起点。

⇒ 而这正是 L4 开头讲的那个迁移学习范式的早期形态：昂贵的那一步只付一次，成本被摊薄到无数个下游任务上。

⚠ 但也要看到它的局限（本讲稍后就会讲到）：Word2vec 的向量是「静态」的 —— 一个词永远是同一个向量，不管它出现在什么句子里。⇒ 这个局限正是学生马上要问到的那个问题，也是 L1 后半段（RNN → 注意力）要修的东西。

46:57So you can technically have many variations of words

学生问「v 是什么、为什么只有六个」，而讲者借这个问题回到了分词那一段的困难。

他先答了字面那一半：是的，在这个例子里我们只有六个可能的词，那基本上就是词表大小 —— 只是一个很玩具的例子，因为实践中要多得多。

★★ 然后他说了那句更有分量的：「所以我想这是语言的挑战之一：技术上说，你可以有一个词的很多很多变体 —— 而这就是为什么，如果你用词级的方式把文本切成 token，你最后可能得到一个非常大的词表，因为你需要把一个给定词的所有变体都算进去。」

⇒ 这正好印证了第 15 条那个 bear / bears、run / runs 的例子：每一个变形都要单独占一个词表位置。

★ 而把两段连起来看，一条因果链就完整了：词级切分 ⇒ 每个变形各占一位 ⇒ 词表很大 ⇒ 输出层 softmax 很大（第 25 条讲的那个成本）、而且每个变形各学一个向量、学得都不好。

⇒ 所以子词级要解决的不是一个问题，而是这一整串。

47:31And so the answer for that is typically what people do is they reserve a spot

第一个问答，它把第 18 条的 OOV 落到了实现上。

问题：学生问 v 是什么、为什么只有 6。讲者先答了玩具例子那一半，然后主动把问题推进了一步：假设你的词表大小是 6，就是你训练时见过的那六个词。那如果推理时你碰到一个训练时没见过的词，会发生什么？

★ 答案：「那个的答案是：人们通常会保留一个位置给他们所谓的 unknown token（未知 token）或者 out-of-vocabulary token —— 你基本上可以把它想成一个桶，装下所有我们没能识别出来的东西。所以假设推理时你有一个你没能识别的 token，它们全都会用那个表示，也就是 unknown token 的表示。」

★★ 「桶」这个比喻很准，而它正好说明了 OOV 的代价有多大：⇒ 所有不认识的词共用同一个向量。一个罕见人名、一个新造词、一个拼错的词 —— 在模型眼里它们是同一个东西。

⇒ 这正是第 18 条说的：OOV 不是「少学到一点」，是「这个位置的信息被彻底抹掉」。

⚠ 而讲者接着把三种分词的 OOV 风险又排了一遍：词级机会大得多、子词级更低、字符级没有这个问题。

48:53So the thing with the proxy task is when you train your model

第二个问答，而它之所以微妙，正是因为「代理任务」这个设定。

讲者的回答：「代理任务的问题在于：当你训练你的模型时，我想你真正的目标并不是去学会怎么预测下一个词 —— 你的目标是拥有有意义的表示。但你能做的，是去跟踪你所追求的那个代理任务的损失函数，同时也要记住这不一定是你的最终目标。」

★★ 请看清这个两难：你能测的东西（代理任务的损失）不是你要的东西（表示的质量）。⇒ 而你要的那个东西没法直接测（否则一开始就不用代理任务了）。

他给的实用办法：「我想一个非常合理的做法就是等到你的模型收敛。」具体是：把损失画成 epoch（你的模型看过训练集多少遍）的函数，比较这些曲线，当它收敛时通常就是个好的停止时机 —— 然后看看那样做是否说得通。⇒ 他还补了一句：当然这取决于你的下游任务。

★★★ 这个「代理指标和真实目标之间有缝」的问题，会在 L5 变成这门课最重要的一条警告 —— reward hacking。⇒ 那里讲者会说：优化一个不完美的代理优化得太狠，奖励最大化了而目标没达成。这里只是它温和的版本。

49:24So I guess one very reasonable way of going about doing this is just to wait until your model converges

上一镜说了「你能测的不是你要的」，这一镜是讲者给的实用出路。

他的话：「所以我想，一个非常合理的做法就是等到你的模型收敛。这里你做的是跟踪损失，把它作为 —— 有个术语叫 epoch，也就是你的模型把训练集看了多少遍 —— 的函数。然后你比较这些不同的曲线。而当它收敛时，这通常就是一个好的时机去停止训练过程，然后看看那样是否说得通。」⇒ 他补了一句：当然，这取决于你的下游任务。

★ 这里顺带引入了一个基础术语：epoch = 把整个训练集完整过一遍。⇒ 它会在后面反复出现（L4 讲预训练时就用它来计量）。

★★ 而「看看那样是否说得通」这半句值得留意，因为它承认了一件事：收敛只是一个停止的信号，不是「表示已经够好」的证明。⇒ 你最终还是得拿它去下游任务上试。

⇒ 这和他前一句「取决于你的下游任务」是一致的：代理任务的训练什么时候算完，最终只能由真实目标来裁决。

50:26So yeah, exactly

这个问题是学生插进来的，而它正好补上了第 7 条留下的那个洞。

问题：讲者复述：所以问题是：你怎么知道生成什么时候停？我想不然它就永远停不下来了。

★ 答案：「是的，正是。所以你有一些特殊 token。典型地，你有 end of sequence（序列结束）。所以通常当 end of sequence 这个 token 被生成出来时，那就是它停下来的时候。」

★★ 回想第 7 条：生成任务的定义里有「输出长度事先不知道」。⇒ 而既然不知道长度，就必须有一个「什么时候算完」的机制。EOS 就是那个机制。

⇒ 它的妙处在于：停不停这件事，本身也是模型学出来的。EOS 和别的 token 一样参与训练 —— 模型学会在「该结束了」的地方给 EOS 高概率。

★★★ 这个设计在本讲最后会被完整演示：Shervine 的端到端走查里，解码一个 token 就把它喂回去、再解码下一个，直到撞上 EOS 为止。他还会把「什么时候停」这个问题抛给学生，答案就是 EOS。

⇒ 而 BOS（begin of sequence）是它的对偶：解码的第一步需要一个起点，那就是 BOS。

50:59So for instance, if you want to somehow get an embedding of, let us say, your sentence

最后一个问答，而讲者把它处理成了一个标准的取舍问题。

他的两个因素：「我会说这是个取舍，因为你希望 embedding 足够丰富，丰富到它能对你的下游任务有信息量。」⇒ 比如如果你想得到你句子的一个 embedding，而你想做一个非常非常专门的任务、有很多不同的结果，那也许你想要一个能重新捕捉到那些的向量，所以也许你想要一个更大的向量；但如果你的任务很简单，也许小一点的向量就说得通。

⇒ 第二个因素：你隐藏维度的大小也影响你后面跑的任何东西的复杂度。因为当然，如果你有更长的向量，你会有更多计算，所以你的推理可能会更贵。

★ 他的小结：「所以我想就是：一是你的下游任务有多复杂；二是你对延迟、成本这些东西有多敏感。所以这真的是个取舍。」

量级：外面你通常会看到几百到几千的 embedding。当然这些模型一直在变大，所以这个数字可能会变。但那就是你要看的数量级。⇒ 他还说这确实是经验性的，而且你也可以依赖别人的发现、从那儿出发 —— 768 这些数字是人们通常会取的。

⚠ 最后还有个学生问「同一个词拼写一样但语境不同怎么区分？」—— 讲者说你远远跑在我前面了，我们后面会讲把词放进句子里做上下文化的方法。那正是本讲后半段的主线。

51:31Because of course, if you have longer vectors, you will have more computation

这一镜把那个取舍的另一半说清，而它的形状你在这一讲里已经见过好几次了。

讲者的话：「所以我想你隐藏维度的大小，也影响你之后跑的任何东西的复杂度。因为当然，如果你有更长的向量，你会有更多的计算，所以你的推理很可能会更贵。」

⇒ 他的小结：所以我想有很多因素。总结一下：一是你的下游任务有多复杂；二是你对延迟、成本这些东西有多敏感。所以这真的是个取舍。

★★ 把这个取舍和前面几个并排看，你会发现它们是同一个形状：chunk 大小（太小脱语境 / 太大代表不了）、子词 vs 字符（词根 vs 序列长度）、词表大小（覆盖 vs 输出层开销）、现在是嵌入维度（表达力 vs 计算）。

⇒ 四个取舍，一个共同结构：「表达能力」对「计算代价」。

★ 所以你可以把这当成一条默认的提问方式：每看到一个超参，先问「它往大了调换来什么、往小了调省下什么」。⇒ 答得出来，这个超参你就算理解了；答不出来，你只是记住了一个数字。

这是 Word2vec 那一段的最后一个提问，而它恰好问到了这一讲的下半场。

讲者的复述：「很好的问题。所以问题是：你怎么区分那些拼写相同、但处在不同语境里的词？」

★ 他的回答：「你远远跑在我前面了。所以这些基本上是基础。而我们接下来会去处理那些能解决「把词在句子里上下文化」这类问题的方法。所以我们待会儿就会看到。」

★★★ 「你远远跑在我前面了」这句话标记了这一讲的一个转折：⇒ 到此为止的所有内容（分词、one-hot、Word2vec）都有同一个局限：一个词永远是同一个向量。而这位学生直接问到了那个局限。

53:41So one very naive way to do that with what we saw before is to take something like the average

词的表示有了，但我们要的往往是整句话的表示。讲者先给最朴素的做法，再数它丢了什么。

★★ 三件事值得分开看，因为后面是被不同的东西修掉的：

① 丢掉意义（平均会把一切抹平）；

② 丢掉顺序 —— 「狗咬人」和「人咬狗」取平均后完全一样；⇒ 这一条由 RNN 来修。

③ 表示与位置/语境无关 —— 同一个词永远同一个向量；⇒ 这一条 RNN 修不彻底，要等到注意力。

⇒ 所以接下来的两段（RNN、注意力）正是在依次修 ② 和 ③。而讲者特意把 ③ 归功给了提问的学生。

54:20So we are going to talk about RNNs, which stands for Recurrent Neural Network

RNN 登场，而它的核心机制讲者一句话就说完了。

他的话：「所以有一类模型，目标是捕捉「文本出现的序列性质」。我们要讲的是 RNN，它代表 Recurrent Neural Network（循环神经网络）。」

★ 机制：「RNN 做的事是：它不是一次处理一个词（就那么孤立地），而是保留一个「到目前为止这个句子」的隐表示，然后一次考虑一个 token。」

⇒ 两个关键词：「保留一个隐表示」和「一次一个 token」。前者让历史被记住，后者让顺序有意义。

★★ 而讲者顺手接上了第 14 条那条时间线：如我之前提到的，这个技术其实是相当久以前引入的 —— 在 80 年代。⇒ 正好印证那条判断：想法很早就有，缺的是数据和算力。

★★★ 这里有一个对比很值得现在就想清楚，因为它预告了后面的全部故事：RNN 用「顺序处理」来获得顺序信息 —— 这是它的本事，也将成为它的死穴。⇒ 顺序处理意味着不能并行，而不能并行意味着训练慢、而且长序列时信息要走很远。这两件事会分别变成它的两个致命问题。

54:50So as I mentioned before, this technique was actually introduced a fair amount of time ago

RNN 怎么起步，以及一个你一定会撞上的术语混乱。

讲者的话：「在这个例子里，你从句子的最开头开始处理。你有某个 dummy（占位的）隐状态，通常记作 A 或者 H。它被叫做 hidden state（隐状态）、activation（激活），甚至有时候叫 context vector（上下文向量）。」

⚠ 三个名字，同一个东西。⇒ 这是本讲里术语混乱的又一个例子（前面有 word/token representation、word/token 混用）。★ 而讲者的做法值得学：他把三个名字都念出来，而不是只用自己习惯的那一个。因为你读别人的材料时，三个都会碰到。

⇒ 顺带说明三个名字各自的来历，这样你就不会被它们绕晕：「hidden state」强调它是网络内部的状态；「activation」强调它是某一层的输出值；「context vector」强调它承载了上下文信息。⇒ 三种叫法反映的是三种看问题的角度，而不是三种东西。

★ 至于为什么要一个「dummy 的」初始隐状态：因为第一个词之前没有历史，总得有个起点。通常就初始化成全零向量。

55:21It is called the hidden state, activation, or even sometimes a context vector

一个 RNN 模块的结构，极其简单 —— 两进一出，然后循环。

讲者的话：「你有某种模块，它把「到目前为止的隐状态」和「时刻 t 的那个词」都考虑进来 —— 这里是时刻 1。所以它做的事是：它接收「这个句子到目前为止的意思」，并把「此刻正在发生的那个词」也考虑进来。然后它产出一个输出向量，这里可以用来试着预测下一个词。」

⇒ 里面是什么：这里你有这个隐状态和那个词的表示，然后在这个蓝色盒子里有一些矩阵乘法，于是你有一个输出向量，你拿它去训练预测下一个词。

★★ 「两进一出，然后把新状态传给下一步」—— 这个循环结构就是 recurrent（循环）这个名字的来源。

⇒ 而讲者对隐状态的解释值得记：你解读这些隐状态的方式是：它是「到目前为止已处理序列」的一个表示。

★★★ 请注意这个设计里一个很强的假设：整句话到目前为止的全部信息，都必须被压进那一个固定大小的向量里。⇒ 句子一长，这个向量就要装下越来越多东西，而它的容量是不变的。⇒ 这正是后面那个「长程依赖」问题的根源，而讲者马上就会说到。

56:20And then you keep on doing that by keeping track of these hidden states

RNN 换来了什么，讲者说得很干脆。

他的话：「然后你就这样一直做下去，一路追踪这些隐状态。所以你重复这个过程。而我想你解读这些隐状态的方式是：它是「到目前为止已处理序列」的一个表示。所以 RNN 的好处是：现在词的顺序是算数的了。而且你也能够以一种更自然的方式去编码这个句子。」

★★ 「词序算数了」这件事为什么能成立，值得看清机制：⇒ 因为隐状态是按顺序累积的。处理「a → cute → teddy bear」时，每一步的隐状态都依赖于前一步；换个顺序，整条链路算出来的东西就完全不同。

⇒ 对照取平均：加法是可交换的，所以顺序天然被抹掉；而 RNN 的递推不可交换，顺序自然被保留。

★ 这是一个很干净的设计洞察：想保留某种信息，就让计算对那种信息敏感。⇒ 而反过来说，后面 transformer 放弃了顺序处理，于是顺序信息就丢了 —— 所以它必须另外加「位置编码」把顺序补回来。这个对照在本讲后半段会出现。

57:00So let us see roughly how it works

走一遍具体流程，而它和第 26 条那个 Word2vec 的前向只差一样东西。

讲者的话：「我们还是用那个最爱的例子：a cute teddy bear is reading。你会有 token「a」，你要一个 one-hot 编码向量，你把它过一遍你的网络，你算出隐状态，你试着预测 cute。但接着你保留那个隐状态，然后你把它输入到另一个模块里。而你也考虑接下来的那些词。所以你考虑的不只是那个词本身，还有这个句子到目前为止的隐状态。然后你再一次试着预测下一个词，一次又一次。」

★★ 和 Word2vec 的前向对照一下，差别就一目了然：Word2vec：一个词进 → 预测下一个词。每一步彼此独立。RNN：一个词 + 到目前为止的隐状态 → 预测下一个词。每一步依赖前一步。

⇒ 多出来的就是那条把隐状态往下传的线。而整个 RNN 的能力和问题，都来自这一条线。

★ 能力：历史被带下去了。问题：历史只能通过这一条线传，而且每传一步都要被挤压一次。⇒ 这正是下一条要讲的。

57:54So RNNs were used for a bunch of tasks

讲者把 RNN 挂回第 7 条那三个桶上，而这正是那个坐标系开始发挥作用的地方。

他的交代：「RNN 被用在一堆任务上，正好可以映射回我们之前看到的那些类别。」

① 分类：「出于分类的目的，你基本上可以用你句子里最后一个词的隐状态。比如如果你想预测一篇评论的情感，你基本上会取这里最后那个向量，然后试着把它投影到你想预测的那些预测/标签所在的空间。比如如果你要正面还是负面，你基本上就把那个向量投影到那个空间上。」

★★ 为什么取最后一个？因为按定义，隐状态是「到目前为止已处理序列」的表示。⇒ 处理到最后一个词时，那个隐状态承载的就是整句话。

⇒ 所以「取最后一个隐状态」= 「拿整句话的表示」。这比第 29 条那个「取平均」高明得多，因为它是按顺序累积出来的，不是抹平出来的。

⚠ 但也请记住它的脆弱之处：整句话的信息全压在这一个向量里。句子一长，这个向量就不堪重负 —— 而这正是下一条的主题。

58:33For multi-classification, so you would basically have the representation of the token of interest

另外两个桶，而三者的对照非常清楚。

② 多分类：「对多分类，你基本上会拿到你关心的那个 token 的表示，然后把它投影出去。」⇒ 对应第 8 条说的 NER：标签挂在词上，所以取那个词位置的隐状态。

③ 生成：「或者对生成，你基本上会处理完整个源文本，然后在处理结束时得到一个 context vector —— 也就是 activation vector、也就是 hidden state —— 它接着会被用来解码出输出的预测。」⇒ 讲者又一次把三个名字并列念了出来。

★★★ 把三者并排看，那个坐标系就完全活了：① 分类取「最后一个」位置；② 多分类取「你关心的那个」位置；③ 生成取「最后一个」然后拿它去解码。

⇒ 三个桶的差别，在模型层面就是「从这条隐状态链上取哪里、取完干什么」。⚠ 而 ③ 和 ① 的差别值得留意：两者都取最后一个，但 ① 是投影到标签、③ 是拿它当起点去生成。

⇒ 这个「编码完得到一个向量、再拿它解码」的结构有个名字叫 encoder-decoder，而本讲后半段的 transformer 架构仍然是这个结构 —— 只是中间那一环从 RNN 换成了注意力。

这一镜是我补的一个中途结账，因为它能让你看清后面注意力到底在补什么。

✓ RNN 解决了「顺序」：隐状态是按顺序递推的，换个词序结果就不同。这一条干干净净地解决了。

⚠ 但「上下文化」只解决了一半：⇒ 隐状态里确实带上了上下文（它是「到目前为止」的表示）；但每个词送进网络时，用的还是查表查出来的那个固定嵌入。也就是说，「bank」这个词在「河岸」和「银行」两句话里，输入端仍然是同一个向量。

★★ 而且还有一个方向上的缺陷：隐状态只包含「左边」的上下文。处理到「bank」时，右边的词还没被看到。而很多时候正是右边的词决定了词义（「river bank」里是 river 在前，但「bank of the river」里就是右边了）。

⇒ 这两个缺口，一个由自注意力修（每个词的表示直接由全句所有词算出来），一个由「双向」修（L2 的 BERT 就是双向的）。

★ 所以本讲后半段你要盯住的就是：注意力是怎么让「同一个词在不同句子里有不同表示」的。

59:09So the reason why you have not really heard of RNNs these days

讲者主动提出了那个该问的问题，而答案就是 RNN 退场的原因。

他的话：「你今天其实没怎么听说过 RNN 的原因是：它们有一些 pro，但有很多 con。其中一个 con 是：句子的意义基本上全部被封装在这个隐状态里。所以你有这个「长程依赖」的问题，它基本上影响你去「记住」模型过去看到了什么的能力。」

★★ 请把因果链看清楚，它只有两步：① 整句话的意义全压在一个固定大小的向量里（第 29 条就指出的那个强假设）；② ⇒ 句子越长，早期的信息越容易被挤掉。

⇒ 这就是「长程依赖（long-range dependencies）」这个名字的含义：当一个词要依赖很远之前的某个词时，RNN 做不好。

★ 举个很具体的例子你就明白了：「我在法国长大，……（中间一百个词）……所以我说一口流利的 ____」。要填「法语」，模型必须记住一百个词之前的「法国」。⇒ 而那条信息要在固定大小的隐状态里被挤压一百次才能到这里。

⇒ 讲者用了引号的「记住」（quote unquote「remember」），这个谨慎是对的：RNN 没有记忆器官，它只有一个被反复覆写的向量。

59:59So this one is called LSTMs, Long Short-Term Memory

对付长程依赖的第一个尝试，而讲者的评价很克制。

他的话：「这就是为什么你有另一类模型，它们试着在 RNN 的基础上建造。这一个叫 LSTM，Long Short-Term Memory（长短期记忆）。而那个扩展的目标，是在我们说过的隐状态之外，再有一种办法去追踪那些「重要到该记住」的东西。」

两个量：「所以这里你有 a of t，也就是你的 activation —— 基本上是到目前为止的序列被编码在里面。然后你还追踪另一个量，它叫 cell state，这里记作 c。」

★★ 直觉上，LSTM 的想法是把「工作记忆」和「长期记忆」分开：activation 是每一步都在剧烈变化的那个；cell state 则有机制让信息「不被覆写地」一路传下去。⇒ 名字里的「Long Short-Term」就是这个意思：一种「长的」短期记忆。

⚠ 而讲者的评价是：「这个架构的目标是改进那一块，但我想它也并不完美。」

⇒ 他没有展开 LSTM 的门控细节，因为这不是本课重点。但那句「并不完美」很重要：LSTM 缓解了长程依赖，没有解决它。真正解决它的是注意力。

60:45So this architecture aims at improving that piece, but I guess it was not perfect either

讲者给这个现象点了名，而且特意为它留出了时间。

他的话：「所以是的，那就是基于 RNN 的方法的主要问题 —— 它们有这个「忘记过去的东西」的毛病。而你会在文献里看到这个现象被称为 vanishing gradient（梯度消失）。而它为什么叫这个名字 —— 我知道我们时间不够了，但我还是要把那一部分解释一下。」

★ 留意他的选择：时间不够了，但他还是要讲为什么叫这个名字。⇒ 这和第 6 条那个「希望你有一张缩写的心智映射表」是一致的：名字里藏着机制，知道机制就不用死记。

⚠ 而这里有一个概念上的细节值得现在就说清：「忘记过去」是现象，「梯度消失」是机制。⇒ 两者不是同一件事，而是因果关系：因为梯度在往回传的过程中消失了，所以早期的权重得不到有效更新，于是模型学不会依赖远处的信息。

⇒ 下一镜讲者就会把这个机制推一遍，而推导的形状很简单：一串数相乘。

61:32And so whenever you want to update the weights of your model

推导只有两步，而第二步是关键。

第一步：「为了让你预测比如最后那些词，你基本上依赖于在那之前的每一个隐状态。」

第二步：「而每当你想更新模型的权重、好让这里的预测和实际的预测对上，当你做反向传播时，你某种程度上必须考虑到：这里的值不只是这一次计算的事，也是那一次计算、那一次计算的事 —— 它们基本上是以顺序的方式发生的。所以你有这个「按时间反向传播（back-propagate through time）」的现象。」

★★ 「按时间反向传播」这个名字说得很准：误差不只要往「层」的后面传，还要往「时间」的前面传。⇒ 而时间步有多少，这条链就有多长。

⇒ 然后他说出了关键：「但问题是，实践中当你把它写下来 —— 那是个非常丑的公式 —— 但当你写下来之后，它最后变成一堆量的乘积。」

★ 「一堆量的乘积」就是全部要害。下一镜就是这个乘积会怎样。

62:17But the problem is, in practice when you write that down

这是整个机制的落点，而它简单得只需要一点算术直觉。

讲者的话：「它最后变成一堆量的乘积 —— 而如果它大于 1，那它就是爆炸；如果它小于 1，那就是消失。因为如果你把很多小于 1 的东西乘起来，它就直接奔向 0 了。所以我想如果你有一个想用来做更新的东西却趋于 0，你基本上就很难做你的更新了。」

★★ 自己感受一下量级：0.9 的 100 次方 ≈ 0.000027。⇒ 也就是说，一百步之前的那个词，收到的梯度只有万分之零点二七。它实际上收不到任何有效的更新信号。

⇒ 反方向也一样极端：1.1 的 100 次方 ≈ 13780。梯度爆炸会让训练直接发散。

★★★ 所以问题的本质是：指数。只要是连乘，偏离 1 一点点，经过很多步之后就会变成天文数字或者零。而 RNN 的结构决定了它必须连乘。

⚠ 这也解释了为什么 LSTM 只是缓解而非解决：它通过 cell state 提供了一条「乘法更少」的通路，但只要还是递推结构，这个风险就还在。⇒ 真正解决它的办法是：别再让信息走那么长的路 —— 那就是注意力。

63:19So our goal is to represent text

讲完 RNN 的病，讲者先停下来把前面整条线收了一遍 —— 这个小结本身就是最好的复习。

他的话：「我希望下一个东西会更说得通一点。但在那之前，我先把我们看过的东西回顾一下。所以我们的目标是表示文本。我们首先从表示词、或者 token 开始 —— 那就是我们用 Word2vec 试图做的事。而我们看到，利用代理任务来学这个表示是一个好办法。」

⚠ 然后是局限：「但我们有一堆局限。而其中一个 —— 你提到过的 —— 是它不知道上下文。而且词的顺序也不算数。」

★ 请注意他又一次把这个洞察归给了学生（「you mentioned」）。这是第三次了（第 29 条、第 28 条末尾、这里）。

⇒ 这不只是礼貌，它说明那个问题确实是这条线上的关键缺口 —— 而且学生比课程进度先想到了它。

★★ 把 Word2vec 的两个局限记牢，因为它们正是后面两步各自要修的：① 不知道上下文（同一个词永远同一个向量）；② 词序不算数。⇒ RNN 修了 ②，而 ① 要等注意力。

63:51And so you have this other class of methods

小结的第二段，把 RNN 这一类也收了。

讲者的话：「所以你有这另一类方法，它能够把那些词考虑进来，但它们在序列变得很长的时候就有点追踪不住了。而你就有了这个梯度消失、或者说长程依赖的问题。所以每当你看到这个术语，它基本上指的就是那件事。」

★ 「每当你看到这个术语，它基本上指的就是那件事」—— 这又是一次「给术语建立心智映射」的动作。

⇒ 到目前为止这一讲已经建立了好几条这样的映射：NLP、OOV、OHE、proxy task、hidden state 的三个名字、long-range dependencies / vanishing gradient。

★★ 而值得注意的是：长程依赖和梯度消失这两个词，讲者是当成同一件事的两个名字在用的。⇒ 严格说它们是现象和机制的关系（第 31 条分过），但在文献的实际用法里，它们确实常被互换。⇒ 知道这一点，你读论文时就不会被绕住。

⇒ 而他接着要补的那个毛病，是本讲里 RNN 的「第三宗罪」，也是最后压垮它的那一条。

64:22So when you want to train these models, at training time

RNN 的第三宗罪，而它是最后压垮它的那一条。

讲者的话：「还有一件我没提过的事：那就是计算非常慢。所以当你想训练这些模型时，在训练阶段，为了预测这个词，你基本上需要先把前面所有这些隐状态都算出来。所以当你的序列变得很长，它就是要花非常长的时间。」

★★★ 请看清这一条的性质：它是结构性的，不是实现问题。⇒ RNN 第 t 步的输入里有第 t−1 步的输出，所以第 t 步在第 t−1 步算完之前根本没法开始。⇒ 这就是「不能并行」。你有一万块 GPU 也没用，因为它们只能排队等。

★ 而这正是第 29 条里那个预言的兑现：RNN 用「顺序处理」换来顺序信息，而顺序处理同时带来了「不能并行」和「信息要走很远」两个问题。

73:10So here, you will have something like you want to express this in terms of all the values

讲者给的解释层面的说法，正好印证了第 35 条那个「职责分离」。

他的话：「但从解释的角度，你可以这样理解：key 在那里，是为了让你弄清哪一个和 query 最相似；而 value 是和那个元素关联的实际的值。所以这里你会有类似「你想用所有这些 value 来表达这个东西」的情形。于是你那个加权平均里的权重，基本上就是 query 和 key 之间的点积。而 value 就是你会用到的那个实际的向量。」

★★ 注意他特意说了「从解释的角度（from an interpretation standpoint）」—— 这正是上一镜说的那个区分：⇒ 他给的是一个帮助理解的框架，不是一个数学上的定义。

★ 而公式对照一下就全通了：QKᵀ 就是「query 和 key 的点积」（权重的来源）；softmax 把它变成加起来为 1 的权重；乘 V 就是「用这些 value 做加权平均」。

⇒ 所以这条公式的每一部分，讲者都用大白话说过一遍了。公式只是把这段话写紧凑。

73:40And these projections are actually learned by the model

这是学生逼出来的最后一个关键细节，而它把 self-attention 的机制补全了。

讲者的话：「还有一件我没提到的事 —— 但你说对了 —— 我们实际上要做投影来得到这些量。而这些投影实际上是模型学出来的。」

★★★ 这句话补上的是一个结构性的事实：Q、K、V 全都来自同一份输入表示。⇒ 你有一串 token 的嵌入；把它们乘上 W_q 得到 Q，乘上 W_k 得到 K，乘上 W_v 得到 V。三者同源，只是被三个不同的、学出来的矩阵变换过。

★ 这正是「self」这个字的字面含义：⇒ 既然 Q、K、V 都来自同一个序列，那就是「自己看自己」。⇒ 而后面会看到 cross-attention：那里 Q 来自一个序列，K 和 V 来自另一个序列 —— 所以是「看别人」。

⇒ 这个对照是理解 transformer 架构里三处注意力的钥匙，而本讲最后的走查会把 W_q、W_k、W_v 明确画出来。

这一镜是我补的（讲者没展开），但它能让「为什么要投影」这件事变得理所当然。

反过来想：如果不投影，直接拿嵌入当 Q、K、V 会怎样？⇒ 那么 Q 和 K 就是同一组向量。算 QKᵀ 时，每个词和自己的点积一定是最大的（因为向量和自己最像）。⇒ 结果是：每个词主要在关注自己，这个机制就退化了。

★★ 而有了三个独立的投影，模型就有了三个自由度：W_q 决定「我以什么角度去找」；W_k 决定「我以什么角度被找」；W_v 决定「被找到后我贡献什么」。

⇒ 于是模型可以学出这样的行为：一个形容词去找它修饰的名词（用某种语法角度匹配），但贡献的是它的语义内容。匹配的依据和贡献的内容是解耦的。

★ 这正是第 35 条那个「职责分离」能真正实现的技术前提。没有投影，分离就只是说说而已。

74:12the authors propose an architecture that is composed of two parts

架构登场，而它的形状直接来自它要解决的那个任务。

讲者的话：「在一个很高的层面上，为了让自注意力机制发生，作者提出了一个由两部分组成的架构：一个 encoder，在左边；一个 decoder，在右边。他们的应用是翻译。所以走 encoder 的是你源语言的输入文本，而走 decoder 的是你正在预测的目标语言。」

★ 这个两段式结构其实你在第 30 条见过：RNN 做生成任务时，也是「先把整个源文本处理完得到 context vector，再拿它解码」。⇒ 所以 encoder-decoder 不是 transformer 发明的，transformer 只是把两边的内部从 RNN 换成了注意力。

★★ 高层任务讲者也说了：「高层的想法是：你要通过把输入文本过一遍 encoder，来算出有意义的嵌入。而你想让自注意力机制起作用 —— 意思是你想把每个 token 的表示算成其它 token 的函数。」

⇒ 「每个 token 的表示 = 其它 token 的函数」这句话，是自注意力最精确的一句定义。

75:13So multi-head attention layer, but multi-head is just doing this computation in different ways

encoder 内部只有两样东西，而讲者对 multi-head 给了一句先行解释。

他的话：「你用一个叫 attention layer 的层来做这件事 —— 是 multi-head attention 层，不过 multi-head 只是用不同的方式去做这个计算，好让模型学到不同的表示、不同的投影。但这里的想法是：你会输入你的输入文本，而你输入文本里的所有 token 都会互相 attend（关注）。」

⇒ 具体到例子：「a cute teddy bear is reading」，你要把这段文本里所有 token 的表示，都算成其它 token 的函数。

★ 然后是第二层：「然后你有一个 feedforward 层，它只是让模型学另一种投影。而在你编码过程结束时，你会得到输入句子那些 token 的丰富表示。」

★★ 注意 feedforward 层的定位：讲者两次都说它是「让模型学另一种投影 / 多一些自由度」。⇒ 它不像注意力那样有一个清晰的「它在做什么」的故事 —— 它就是加算力、加参数、加非线性。⇒ 而本讲最后 Shervine 会补一个有意思的细节：FFN 的隐层维度比输入输出「更大」，和 Word2vec 那里正好相反。

75:46you are going to compute the representation of all the tokens in this text basically as a function of others

这一镜把 encoder 在做的事落到那句老例子上。

讲者的话：「所以比如「a cute teddy bear is reading」，你要把这段文本里所有 token 的表示，基本上都算成其它 token 的函数。而你是用 encoder 来做这件事的 —— 这里就是用 multi-head attention。」

★★ 请留意一个这里没被强调、但很要紧的性质：encoder 的自注意力是「全看」的。⇒ 算 teddy bear 的表示时，它既看左边的 a、cute，也看右边的 is、reading。

⇒ 这和第 30 条那个 RNN 的局限正好对照：RNN 的隐状态只包含左边，而 encoder 的自注意力两边都看。

⚠ 而这个「全看」在 decoder 那边是不允许的，原因第 37 条会讲（生成时右边还不存在）。

★★ 所以同一个机制（自注意力）在两处有不同的约束，而这个差别后来长成了两条技术路线：⇒ L2 会讲 BERT（双向、全看，擅长理解类任务）和 decoder-only（单向、只看左边，擅长生成）。⇒ 它们的分野，就始于这里这个「看不看右边」的选择。

76:50So this what I just said is the cross-attention layer

这里讲者设计了一个很好的当堂提问，而这个问题值得你自己先想一想再往下看。

场景：现在你的目标是真的去翻译那个输入句子。你要做的是从「句首 token」开始你的翻译，然后用输入句子的所有表示，来弄清楚接下来该预测什么。

★ 这一层就是 cross-attention：讲者描述图上的箭头：有两个箭头来自 encoder，一个箭头来自 decoder。

★★ 然后他考学生：「谁能告诉我 decoder 那个箭头代表什么？decoder 是 query、key 还是 value？我猜有三分之一的概率。谁想试试？」⇒ 有人答 key，有人答 query。

⚠ 在往下看之前，建议你自己想一下。提示：回到第 35 条那个定义 —— query 是「你想表达的那个东西」。

⇒ 而现在你想表达/弄清楚的是什么？是「译文的下一个词该是什么」。那个东西在 decoder 这一侧。

⇒ 答案在下一镜。

77:36So the way to think about it is you are trying to ask yourself, what are the words from the input that matter

答案和它的推理方式，讲者说得很清楚。

他的话：「思考的方式是：你在问自己 —— 输入里的哪些词才是要紧的？对吧？所以基本上，给定你的 query，你想知道输入里哪些元素是要紧的。所以这里，这个箭头确实是 query，因为这就是你想弄清楚的那个东西。而 key 和 value 实际上来自 encoder，也就是来自输入序列。」

★★★ 记法很简单，而且通用：谁在「提问」，谁就是 Q；被查询的那一方提供 K 和 V。

⇒ 用这个记法回头看 self-attention：那里提问的和被查的是同一个序列，所以 Q、K、V 同源（第 36 条讲的）。⇒ 而 cross-attention 里提问的是 decoder、被查的是 encoder，所以 Q 来自 decoder、K 和 V 来自 encoder。

★ 这个结构在 L7 还会以另一个面貌出现：RAG 的检索里，query 是用户的问题、而文档库提供「被查的那一面」。⇒ 同一个「提问方 vs 被查方」的结构，换了一层皮。

78:17And that one is trying to figure out what other tokens of the output sentence

第三处注意力，而它的名字 masked（被遮住的）说明了一切。

讲者的话：「然后你有另一个 attention 层，就是这个。那一个在试图弄清楚：你正在解码的那个输出句子里，还有哪些 token 会对预测下一个 token 有用。假设你开始解码，你说了「un ours en peluche」（法语）。要预测下一个词，你基本上想弄清楚：到目前为止已经翻译出来的那些 token 里，哪些会对预测下一个词有用。所以这就是这一层在做的事。」

★★ 名字的由来：「而它被叫做 masked，是因为它只看到目前为止已经翻译出来的那些 token。它不看那些没被翻译的 —— 当然啦，因为它们还没被翻译出来。所以在你试图预测的那个 token 的右边，是没有办法（看到东西）的。」

★★★ 这个限制不是可选的，它是生成任务的逻辑必然：⇒ 生成第 5 个词时，第 6、7、8 个词还不存在。如果训练时让模型看到它们，那就是作弊 —— 模型会学会「抄答案」，而推理时根本没有答案可抄。

⇒ 这个性质在 L3 会有个名字叫因果（causal），而 L7 的 prompt caching 正是建立在它上面（只看左边 ⇒ 相同前缀必然相同激活）。

79:28So the attention layer here aims at computing embeddings from the input sentence as a function of themselves

这是讲者对三处注意力的完整总结，而我认为它是全讲最该记住的一张表。

他的话：「所以在一个很高的层面上，你有这个 attention 层，它在 encoder 里出现、也在 decoder 里出现，但它有好几种用法。这里的 attention 层，目标是「从输入句子算出嵌入，而这些嵌入是它们自己的函数」。然后 decoder 里那些 —— 第一个，masked 自注意力层，目标是「把东西表达成到目前为止已经解码出来的一切的函数」。而第二个，cross-attention 层，试图把东西表达成「输入里见到的东西」的函数。」

★★★ 三句话的句式完全一样，只有「拿什么来表达」不同：① 用「输入自己」表达输入；② 用「已解码的部分」表达当前；③ 用「输入」表达当前。

⇒ 这正好回到第 35 条那个定义：注意力就是「用别的东西来表达某个东西」。三处注意力的差别，只在于「别的东西」指的是谁。

★ 而用第 37 条那个记法对一遍，三处的 Q/K/V 来源也就清楚了：① Q、K、V 全来自输入；② 全来自已解码部分；③ Q 来自已解码部分，K 和 V 来自输入。

⇒ 一个机制，三种接线方式。记住这张表，transformer 的结构你就拿住了。

80:10So here, given that you are having direct links to different tokens, you do not have this sense of order

第 34 条欠下的那笔债，讲者在这里点名还了。

他的话：「所以这里，既然你和不同的 token 之间有直接链接，你就没有那种顺序感。因为在 RNN 里，你基本上是一次一个地表达东西，所以你有某种词序的感觉；但这里你没有了，因为它是直接链接 —— 这就是为什么你有 position encodings（位置编码），它们在那儿是为了告知「这个词在序列里的位置」。」

★★★ 请看清这个因果：并行处理（所有位置同时算）和「知道顺序」是天然冲突的。⇒ 如果你把句子里的词打乱顺序再送进自注意力，算出来的每个词的表示完全一样 —— 因为注意力是对集合的操作，它不知道谁在前谁在后。

⇒ 所以位置信息必须被显式加进去。而加的办法就是：给每个位置一个向量，加到那个位置的词嵌入上。

★ 讲者在这里没有展开：我们今天不会深入那个，但我只是想把它点出来。⇒ 而本讲最后 Shervine 会提一句原论文的做法（正弦余弦，逐元素相加），而 L2 会用一整段讲「位置嵌入换了五代」，终点是 RoPE。

80:40So we are not going to dig into that today, but I just want to call that out

讲者在这里完整走了一遍流程，而这正好是本讲前面所有内容的串联。

他的话：「在一个很高的层面上 —— 我们会在那个详细例子里看到 —— 为了把一个句子从源语言翻到目标语言，我们首先要把文本分词，也就是切成任意的单位。我们要为这些 token 学一个嵌入，这就是 input embedding 的意思。然后我们要加上关于位置的某种编码 —— 今天不讲，但知道就好。然后我们过 encoder。」

⇒ encoder 试图把东西表达成输入里其它东西的函数，它在 multi-head attention 层里做这件事。然后它过一个前馈神经网络，那只是一种把向量投影一下、好有更多自由度去学东西的方式。

⇒ 然后一旦你有了输入的这些表示，你就开始翻译。你从 BOS token 开始。你要弄清下一个词是什么，所以你看「到目前为止翻译出来的哪些词对翻译有用」—— 这就是 masked multi-head attention 层做的事。然后你有另一个 attention 层，是关于「把东西表达成输入里有什么的函数」，那就是 cross-attention 层。然后再一个前馈网络，又给一些自由度。最后你有一个向量，过 softmax —— 它就是让你猜下一个词的办法。

★ 他的收口很俏皮：你有一个词表大小的向量，你用这些值来决定你的下一个词是什么。简单吧？

81:35And then it goes through a feedforward neural network

讲者在这里完整走了一遍流程的前半截，而它正好把前面所有内容串起来。

他的话：「在一个很高的层面上 —— 我们会在详细例子里看到 —— 为了把一个句子从源语言翻到目标语言，我们首先要把文本分词，也就是切成任意单位。我们要为这些 token 学一个嵌入，这就是 input embedding。然后我们要加上关于位置的某种编码 —— 今天不讲，但知道就好。然后我们过 encoder。encoder 试图弄清怎么把东西表达成输入里其它东西的函数，它在 multi-head attention 层里做这件事。然后它过一个前馈神经网络，那只是一种把向量投影一下、好有更多自由度去学东西的方式。」

★★ 请对照一下这条流程和本讲的章节：分词（第 15–18 条）→ 嵌入（第 23–27 条）→ 位置编码（刚讲）→ 自注意力（第 34–36 条）→ FFN。

⇒ 一个半小时的内容，在这里被压成了五个词。

★ 这正是「走查」这种讲法的价值：它不引入新知识，但它把所有旧知识排成了一条执行顺序。⇒ 而「能按顺序说出来」和「每一块都懂」是两种不同的掌握程度。

82:46So you have a vector of vocabulary size

流程的后半截，而最后那个向量的形状值得专门记一下。

讲者的话：「然后一旦你有了输入的这些表示，你就开始你的翻译。你从 BOS token 开始。而你想做的是弄清下一个词是什么。所以你要看：到目前为止翻译出来的哪些词对翻译有用 —— 这就是 masked multi-head attention 层做的事。然后你有另一个 attention 层，是关于把东西表达成输入里有什么的函数，那就是那边的 cross-attention 层。然后又一个前馈神经网络，再给一些自由度。而到最后，你有一个向量，你让它过 softmax —— 它就是让你猜下一个词的办法。」

★★ 最后那句最该记：「所以你有一个「词表大小」的向量。而你要用这些值来决定你的下一个词是什么。」

⇒ 回想第 26 条：Word2vec 的输出也是一个词表大小的概率向量。⇒ 从 Word2vec 到 transformer，输出端的形状一点没变 —— 变的全在「怎么算出那个向量」。

★ 而这个形状会一直延续到今天的 LLM：L3 讲的所有解码策略（贪心、beam、top-k、top-p、温度），都是在对这个向量做文章。

⇒ 讲者的收口很俏皮：简单吧？有什么问题吗？

83:16So I guess I went too fast

最后一个提问，而讲者又一次坦白了自己的疏漏。

他的话：「那是个很好的问题。问题是：head 是什么意思？我想我讲太快了，我把那部分忽略掉了。」

⇒ 他的解释：当你做自注意力计算时，你基本上让 query 和 key 互动，然后取对应的 value。但没有什么能阻止你把这件事做好几次。所以 head 这个词，是给「你用来得到 query、key 和 value 的那些投影矩阵」的名字。

★★ 把它和第 36 条接起来就完全通了：第 36 条说 Q、K、V 是由三个学出来的投影矩阵得到的。⇒ 而「多头」就是：不只有一组 (W_q, W_k, W_v)，而是有 h 组。每一组各算一次注意力，然后把结果拼起来。

⇒ 讲者说了它的好处：当你有好几个 head 时，你是在允许你的模型学到不同的投影。所以这基本上是给你的模型一个额外的自由度，去学你那些向量之间的不同关联。

★ 记号：通常记作小写 h，表示 head 的数量。

83:46And when you have several heads, what you are doing is you are allowing your model to learn different projections

多头的直觉，而讲者给了一个很好用的类比。

他的话：「所以这就是你提到的那个多头。我们基本上是在并行地把自注意力计算跑好几次，还是用模型学出来的不同投影矩阵。如果你有计算机视觉的背景，这类似于在你的卷积里有多个 filter（滤波器）。所以是同一个想法，不过这里是不一样的东西。」

★★ 这个类比为什么好用：卷积网络里每个 filter 学一种模式（边缘、纹理、角点），多个 filter 就能同时捕捉多种模式。⇒ 多头注意力同理：每个 head 可以学一种「关注的角度」 —— 比如一个头关注语法依存、另一个关注指代、再一个关注语义相关。

⇒ 讲者说「不过这里是不一样的东西」是对的：filter 是在空间上滑动的，而 head 是在同一组输入上做不同的投影。类比只到「多个并行的特征提取器」这一层。

⚠ 而学生紧接着追问了一个很尖锐的问题：这些投影是不同的吗？会不会学成一样？⇒ 讲者先给了一个简短回答（我们通常不约束，就让模型学；而实践中它往往会学出不同的说法），而更完整的回答由 Shervine 在最后的走查里给出 —— 那是下一个模块。

85:07So the question is, are the projections different?

这个追问问到了多头机制最脆弱的一环，而讲者的回答很坦率。

他的话：「很好的问题。所以问题是：那些投影是不同的吗？我们通常不去约束任何东西 —— 我们就让模型去学。但实践中，它就是倾向于学出「说同一件事的不同方式」。所以是的，典型地你没有任何约束。」⇒ 当然，也有论文深入研究「如果你改动这个会怎样」。但典型地你没有任何约束。

★★ 请体会这个回答里的张力：多头的全部价值建立在「不同的头学到不同的东西」上；而这件事没有任何机制保证。⇒ 它纯粹是「实践中它就这样」。

⚠ 这类「没有保证，但实践中有效」的情形在深度学习里非常多，而知道哪些属于这一类很重要：⇒ 它意味着当它失效时，你不会有任何理论能告诉你为什么。（后来的研究确实发现：一部分头是冗余的，剪掉它们对性能影响很小。）

★ 而 Shervine 在最后的走查里会给这个问题一个更完整的回答 —— 那个回答比这里的更有说服力，我们到第 44 条再看。

85:39OK, I will just mention one trick, another trick that the transformer authors use

这是本讲最后一个技术点，而它修的正是第 26 条留下的那个别扭。

讲者的引入：「我就再提一个技巧，transformer 作者用的另一个技巧。它叫 label smoothing。谁听说过 label smoothing？」

它要处理的事实：「这里有个新东西：在 NLP 里，当你想预测接下来是什么时，通常不止一种方式。当你说「what a great day」「what a great lecture」「what a great book」「what a great ——」总是有多个选择。填那个空的方式不止一种。」

★★★ 请回想第 26 条那个设定：训练时的真值是一个 one-hot —— 目标词概率 1、其余全 0。⇒ 也就是说，我们在要求模型断言「接下来一定是 day，绝不可能是 lecture 或 book」。

⇒ 可事实上 lecture 和 book 都是完全合理的。所以这个训练目标本身就是错的 —— 它在教模型说一句不真实的话。

★ 而 label smoothing 就是对这件事的一个直接修正，下一镜看它怎么做。

86:44And instead of saying it is a 1, 0, 0, 0, that you need to predict

做法本身只是改标签，一行就说完了。

讲者的大白话：「它做的事是：不是说「100% 预测这个词、没有别的词」，而是说「预测这个词，但有一定机会它不是这个词」。」

具体怎么改：「实践中它做的是：它拿那个 one-hot 编码，而不是说你需要预测的是 (1, 0, 0, 0)，它说其实是 1 减去 epsilon，然后那些是 epsilon 除以 v 减 1。」

⇒ 读一遍这个式子：目标词分到 1−ε，剩下那 ε 被平均分给其余的 v−1 个词。★ 注意它仍然是一个合法的概率分布（加起来是 1）。

★★ 它的效果，讲者说得很准：「实践中，这是一个倾向于让你的模型「更不确定」的方法。再说一次，是让它对这个预测不那么笃定，因为你总是在告诉它：试着预测这个，但其实有可能它不是正确的值。」

⚠ 而这是一个很有意思的训练哲学：我们在主动地教模型「别太自信」。⇒ 这和一般「让模型更准」的直觉相反，但它对应的是真实世界的性质：语言本来就有多个合理的续写。

87:19But in practice, the authors see that it tends to improve metrics like BLEU

它管用吗？作者给的是经验证据。

讲者的话：「但实践中，作者们看到它倾向于提升像 BLEU 这样的指标 —— 而 BLEU 是翻译任务的一个代理指标。所以是的，我觉得这个方法对 NLP 来说是相当通用的。所以它是个值得知道的东西。」

★ 注意他用了「代理指标（proxy metric）」这个词来形容 BLEU：⇒ 这和第 24 条的「代理任务」是同一个词根，而含义一致：BLEU 不是我们真正关心的（翻译质量），只是一个能测的替身。

⚠ 于是这里有一个值得想一层的细节：label smoothing 提升的是 BLEU，而 BLEU 本身是个不完美的代理。⇒ 所以严格说，这个证据证明的是「它让 BLEU 上去了」，而不是「它让翻译变好了」。

★★ 这不是在质疑 label smoothing（它确实被广泛采用），而是提醒你留意这类证据的形状：⇒ 整个领域的进步大量依赖这种「在某个代理指标上变好了」的证据。而 L5 的 reward hacking、L6 的长度膨胀，讲的都是这种依赖出问题的时候。

88:32So question is, is there a relation with explore and exploit?

这个追问很有意思，因为它把 label smoothing 和强化学习里的一个概念联系了起来。

学生的问题：讲者复述为：所以问题是，这和「探索与利用（explore and exploit）」有关系吗？⇒ 他的第一反应：这是个有意思的问题。

★ 这个联想其实有道理：「探索 vs 利用」说的是「要不要偶尔试试不是当前最优的那个选项」；而 label smoothing 做的事是不让模型把全部概率押在一个词上。⇒ 表面上都在「保留一点不确定性」。

⚠ 但讲者没有顺着这个类比走，而是把话题拉回了那个更基本的区分：他反问「那为什么 softmax 会免费给你这个呢？」然后落到：归根结底，你想做的是把你的预测和标签做比较。所以问题是：你想和 (1,0,0,0) 比，还是想和某个不是 (1,0,0,0) 的东西比。

★★ 我认为他不顺着类比走是对的：两者「看起来像」，但机制完全不同。⇒ 探索发生在行为选择这一侧（要不要试别的动作）；label smoothing 发生在监督信号这一侧（标签该多硬）。⇒ 把它们混为一谈会让你在两边都想不清楚。

89:02So I guess the question here is, do you want to compare with 1, 0, 0, 0

学生的追问抓住了一个真实的混淆点，而讲者的回答把两侧分清了。

来回的过程：学生问「softmax 不是已经免费给了这个吗？」讲者反问「softmax 为什么会免费给它呢？」

★★ 然后他点破了关键：「我想归根结底，你想做的是把你的预测和标签去比较。所以我想这里的问题是：你是想和 (1, 0, 0, 0) 比，还是想和某个不是 (1, 0, 0, 0) 的东西比？所以我想 softmax 不让你做那件事。」

★★★ 这个区分非常要紧：softmax 管的是「预测」那一侧，label smoothing 改的是「标签」那一侧。⇒ 模型的输出确实是个软的分布（softmax 保证的）；但损失是拿它去和标签比的，而标签原来是硬的。⇒ 只要标签是 (1,0,0,0)，损失就会一直推着模型把那个概率往 1 顶 —— 哪怕输出端是软的。

★ 讲者最后又强调了一遍：「我不确定这说清楚了没有，但这实际上是标签。你试图预测的不是 (1, 0, 0)，而是我们改变了标签，好让模型去预测一个不那么笃定的东西。」

最后二十分钟交给 Shervine，而他要做的事是把前面所有零件装起来。

90:06So as we said, we can use any arbitrary decomposition to decompose this into tokens

第一步是分词，而 Shervine 特意呼应了 Afshine 那个「任意」。

他的话：「所以我们先从分词开始。如我们所说，我们可以用任意的分解方式把它分解成 token。」

⇒ 这正好接上第 15 条：切法是人定的，不存在「正确的切法」。所以在走查里用哪种切法并不重要。

★ 然后他引出了一个之前没提过的必需品：「然后，正如有人提到的，你需要有某种办法去指明一个序列的开始和结束。」

⇒ 「正如有人提到的」—— 这又是一次对学生提问的呼应。第 28 条那个「生成什么时候停」的问题，答案是 EOS。

★★ 而这里把这件事补完整了：不只需要「结束」，还需要「开始」。⇒ 为什么需要「开始」？因为解码的第一步要有个输入 —— 还没生成任何词时，你得喂给 decoder 点什么。那就是 BOS。

90:17So typically, this is done with the BOS and EOS tokens

两个特殊 token，而它们是生成任务能自洽运转的最后两块拼图。

Shervine 的话：「所以典型地，这是用 BOS 和 EOS token 来做的。所以你把它们加上去。」

⇒ BOS = beginning of sequence（序列开始），EOS = end of sequence（序列结束）。

★★ 两者的角色是对称而不同的：EOS 回答「什么时候停」（第 28 条那个学生的问题）；BOS 回答「从哪儿开始」。

⇒ 后者容易被忽略，但它同样必要：解码的第一步，模型还一个词都没生成，可自注意力总得有个输入。BOS 就是那个「我要开始说话了」的信号。

★★★ 而它们能工作的原因很妙：它们就是词表里普通的两个 token。⇒ 模型通过训练学会「在该结束的地方给 EOS 高概率」—— 没有任何特殊机制，就是正常地学。

⇒ 这是一个很优雅的设计：把一个控制问题（什么时候停）变成了一个预测问题（下一个 token 是不是 EOS）。

90:25So now let us focus on the composition of each token representation

分词完成，现在看每个 token 送进网络时携带的是什么。

Shervine 的话：「现在让我们聚焦在每个 token 表示的组成上。你有它的 embedding —— 那是学出来的。」

⇒ 「学出来的」这三个字接上了整段 Word2vec：这就是那张嵌入表，第 i 行对应第 i 个 token。⇒ 区别只在于：Word2vec 里这张表是用代理任务单独训的，而在 transformer 里它和整个模型一起训。

★ 但 token 的表示不止这一个成分：⇒ 还有第二个，而它正是第 38 条欠下的那笔债 —— 位置信息。

⇒ 下一条就讲它怎么被加进来，而「加」这个字是字面意义的。

⭐ 顺带值得点一句：到这里为止，前面讲过的东西已经开始各就各位了 —— 分词（第 15–18 条）、嵌入（第 23–27 条）、BOS/EOS（第 28 条的伏笔）、马上要来的位置编码（第 38 条的伏笔）。这正是走查这种讲法的价值。

90:42you have some added information that is in the form of a position embedding

第 38 条欠下的那笔债，在这里被具体地还上了。

Shervine 的话：「而如 Afshine 提到的，为了有一个关于「这个词、或者说这个 token 在序列里处于什么位置」的概念，你有一些额外加上去的信息，形式是一个 position embedding（位置嵌入）。而这里原论文用的约定，是一组正弦和余弦，它把它们「加性地」加到那个表示上。所以这就像一次逐元素的加法。」

★★★ 请特别留意「加」这个字 —— 它是字面意义的逐元素相加，而这件事值得想一想：⇒ 直觉上，「内容」和「位置」是两种不同的信息，把它们直接加在一起似乎会混在一起分不开。

⇒ 但它确实能工作，原因在于高维空间足够宽敞：在几百维里，「内容方向」和「位置方向」可以基本互不干扰，模型能学会把它们分开读。

⚠ 不过这个设计并不是唯一的、也不是最好的。L2 会专门讲「位置嵌入换了五代」—— 从学出来的、到正弦余弦、到 T5 的偏置、到 ALiBi、最后到 RoPE。⇒ 每一代都在修前一代的具体毛病，而「直接加上去」正是最早那一代被诟病的地方之一。

91:07So now you have a position-aware embedding for your token

两个成分合起来，就得到了送进 encoder 的东西。

Shervine 的话：「好，所以现在你有了一个位置感知的（position-aware）嵌入，属于你的那个 token。然后你对你的每一个 token 都重复这件事。」

★ 「位置感知的嵌入」这个说法很准：它既携带「我是哪个词」，也携带「我在第几位」。

★★ 而这正好补上了第 38 条指出的那个缺口。回顾一下那条因果链，你会发现它非常干净：⇒ ① 为了能并行和直连，transformer 扔掉了顺序处理；② 于是失去了顺序信息（注意力是对集合的操作）；③ 所以要显式地把位置加回来。

⇒ 三步，每一步都是上一步的必然后果。

⚠ 一个值得留意的推论：如果你把输入序列打乱，同时也把对应的位置嵌入一起打乱，模型的输出应该完全一样。⇒ 因为位置信息现在完全由那个加上去的向量携带，而不是由「在数组里的次序」携带。这正是它能并行的技术基础。

91:07So now you can see all of these embeddings in the format of a matrix

这是走查里第一个要记住的形状，而后面每一步都在这个形状上做文章。

Shervine 的话：「所以现在你可以把所有这些嵌入看成一个矩阵的格式 —— 它的大小是 d_model，也就是你嵌入的大小；而另一个维度是序列的长度，通常是 n。」

★★ 两个符号现在正式登场，它们会用到整门课结束：d_model = 嵌入维度（就是第 25 条那个 d，比如 768）；n = 序列长度（有多少个 token）。

⇒ 所以输入是一个 n × d_model 的矩阵：n 行，每行是一个 token 的位置感知嵌入。

★★★ 请把这个形状记牢，因为第 16 条那句剧透（复杂度是序列长度的函数）从这里开始就变得具体了：⇒ n 是会变的（句子有长有短），而 d_model 是固定的。⇒ 后面你会看到 QKᵀ 是 n × n 的 —— 那是唯一一个「两个维度都是 n」的东西，也正是平方级复杂度的来源。

⇒ Shervine 在这里停下来问了一句：到目前为止都说得通吗？关于输入有什么问题吗？

这一镜是我补的，把接下来几镜会出现的形状先列出来，你可以边听边对。

① 输入 X：n × d_model（n 个 token，每个一行）。

② Q、K、V：各自 n × d_k（由 X 分别乘 W_q、W_k、W_v 得到；行数还是 n，因为每个 token 都要有自己的 query/key/value）。

③ ⚠ QKᵀ：n × n —— 这是全场唯一一个两个维度都是 n 的矩阵。⇒ 它的第 (i, j) 个元素是「第 i 个 token 的 query 和第 j 个 token 的 key 的相似度」。⇒ 序列长一倍，这个矩阵大四倍 —— 第 33 条那个「n² 条线」就是它。

④ softmax(QKᵀ/√d_k)·V：n × d_k —— n×n 的权重矩阵乘 n×d_k 的 V，又回到每个 token 一行。

★★ 请留意这个「进出形状一致」的性质：进去是每 token 一行，出来还是每 token 一行。⇒ 正因为如此，这些层才能一层层堆起来（后面会讲 N 层堆叠）。

91:39So now we will send this representation through the encoder

进 encoder 的第一步，而它把第 36 条那个抽象说法变成了三个具体的矩阵。

Shervine 的话：「所以现在我们要把这个表示送进 encoder。如 Afshine 所说，你有自注意力这个概念。而你执行自注意力的方式是：你拿这个输入，把它投影到三个空间上。你把它投到空间 W_q，得到 queries；你把同样的那些嵌入投到空间 W_k，得到 keys；你对 values 做同样的事，得到你的 values。而 W_q、W_k 和 W_v 是模型学出来的 —— 它们基本上就是投影矩阵。」

★★ 三个要点，每个都接上了前面：① 「同一份输入」投三次 —— 这正是第 36 条说的「三者同源」，也是「self」的含义；② 三个矩阵是学出来的 —— 这正是 Afshine 回答学生时说的；③ 它们是投影矩阵 —— 也就是第 36 条最后补的那个细节。

⇒ 所以这一步没有新东西，它只是把前面说过的话画成了图。

⭐ 而这正是走查的价值：同一件事，先用语言说一遍，再用形状走一遍。两遍之后它才真的变成你的。

92:21you can apply the formula that Afshine mentioned, that is the self-attention formula

公式正式登场，而 Shervine 把它念了一遍 —— 建议你也跟着念，因为念出来比看着记得牢。

他的话：「所以现在把这一切放在心上，你就可以应用 Afshine 提到的那条公式，也就是自注意力公式：softmax of Q K transpose over square root of d_k, times V —— 它从这一切里给你另一个矩阵。」

★ 「另一个矩阵」这句话里有信息：输出还是一个矩阵，而且它的形状和输入那个是一致的（n 行，每个 token 一行）。

⇒ 这正是第 41 条最后一镜说的「进出形状一致」，也是这些层能堆叠的原因。

★★ 而 Shervine 接下来做了一件非常可贵的事：他说：现在让我们停一秒，看看这个计算在实践中是怎么做的，以及每一步意味着什么。

⇒ 也就是说，他不满足于「套公式」，而要把这个矩阵乘法一层层拆开看。⇒ 接下来那几镜是整讲最有价值的部分之一 —— 因为理解这条公式的关键，全在「每一行每一列代表什么」上（这正好印证了第 2 条里说的那个先修要求）。

92:42Now let us pause for a second and look at how this computation is done in practice

拆解从 Q 开始，而 Shervine 的问法很好：你得到了什么？

他的话：「我们先看 Q。当你计算 Q 时，你基本上是把你的嵌入投影到那个空间里。你得到了什么？你得到一个矩阵，它的每一行代表一个给定的 query。」

★★ 「每一行代表一个 query」—— 请把这句话和形状对上：⇒ Q 是 n × d_k：n 行（序列里每个 token 一行），每行是 d_k 维的一个 query 向量。

⇒ 也就是说，序列里的每一个 token 都在「提问」。这正是自注意力和 cross-attention 的区别所在：这里提问的和被问的是同一批 token。

★ 而我建议你现在就在脑子里具体化一下：「a cute teddy bear is reading」加上 BOS、EOS，假设是 7 个 token，那 Q 就有 7 行。⇒ 第 3 行是 teddy bear 的 query，它在问「句子里谁和我有关」。

93:07When you say k transpose, it is basically the same matrix, but transposed

第二步看 Kᵀ，而转置这个动作的意义正在于让后面的乘法说得通。

Shervine 的话：「当你说 K transpose 时，它基本上是同一个矩阵，只是被转置了 —— 在那里，每一列代表每个 token 的 key 表示。」

★★ 把两个形状并排放，矩阵乘法的意义就出来了：Q 是 n × d_k：每一行是一个 query。Kᵀ 是 d_k × n：每一列是一个 key。

⇒ 矩阵乘法的规则是「左边的行 × 右边的列」。所以 Q 乘 Kᵀ 的第 (i, j) 项 = 第 i 个 query 和第 j 个 key 的点积。

★★★ 而点积正是第 36 条里讲者说的那个东西：加权平均里的权重，基本上就是 query 和 key 之间的点积。

⇒ 所以「为什么要转置」有了一个干净的答案：因为我们要的是「每个 query 对每个 key」的全部两两点积，而矩阵乘法恰好一次把它们全算出来。

⚠ 这也正是第 35 条那句「GPU 爱矩阵」的具体兑现：n² 次点积，被写成了一次矩阵乘法。

93:25So when you multiply each of them, you see that each row represents the projection of the query over each key

相乘之后的结果，Shervine 一句话就说清了它的结构。

他的话：「所以当你把它们各自相乘时，你会看到：每一行代表「这个 query 在每一个 key 上的投影」。」

★★ 把这句话翻译成具体的：⇒ 第 i 行有 n 个数，第 j 个数是「第 i 个 token 和第 j 个 token 有多相关」。

⇒ 所以整个矩阵是 n × n，它完整地记录了「每个 token 对每个 token」的关系。

★★★ 这就是第 33 条那个「n² 条线」的真身：注意力说「任意两个位置直接连」—— 而这个 n × n 矩阵就是那些连线的强度。

⇒ 于是「序列长一倍，这个矩阵大四倍」就不再是抽象的说法了，你能看见它。

⚠ 而所有对付长序列的工作，本质上都是在对付这个矩阵：滑动窗口（只算对角线附近那一条带）、FlashAttention（不把整个矩阵存下来）、MLA（压缩 K 和 V）。⇒ 心里有了这个 n×n 的图像，后面那几讲会好懂很多。

93:32such that when you take the matrix multiplication and get the softmax of all of this

softmax 之后发生了什么，Shervine 说得很准确。

他的话：「这样当你做完矩阵乘法、再对这一切取 softmax 时，你就得到：对每一个 query，一个「query 在那些 key 上的投影」的概率分布。每一行都会有这个。」

★★ 「每一行一个概率分布」这句话值得咀嚼，因为它说明了注意力到底在做什么：⇒ 第 i 行是一组加起来为 1 的权重，告诉你「第 i 个 token 应该把多少注意力分给每一个 token」。

⇒ 这正是第 33 条那个「瞥一眼」的量化版本：它不是瞥向一个地方，而是把注意力按比例分配给所有地方。

★ 而「分配」这个性质有个重要含义：总量是守恒的。⇒ 多关注某个 token，就必然少关注别的。这是 softmax 强加的约束，而它让注意力成为一种「取舍」而不是「随便加强」。

⚠ 一个顺带的实际后果：序列越长，平均每个位置能分到的注意力就越少（因为要分给 n 个地方）。这是长序列变难的另一个角度。

93:55And I do not know if anyone asked the question regarding why do we scale by square root of dk

这是 Shervine 主动补的一个点，而且他特意说「不知道有没有人问过」—— 说明他认为这个值得讲。

他的话：「我不知道有没有人问过「为什么我们要除以 d_k 的平方根」这个问题。其实写成 d_q 也可以，因为矩阵乘法 —— 也就是这里的点积 —— 强制了 d_q 等于 d_k。」

★ 先把这个澄清理解了：⇒ query 和 key 要做点积，而点积要求两个向量维度相同。⇒ 所以 d_q 必然等于 d_k，写哪个都一样。⇒ 这是个小细节，但它说明了一件事：W_q 和 W_k 投出来的空间维度必须一致，而 W_v 可以不一样。

⚠ 顺带：这也解释了为什么 L2 讲 MQA/GQA（多个 query 头共享 key/value 头）时，共享的是 K 和 V 而不是 Q —— 结构上 K 和 V 是「被查的那一侧」，可以被多个 query 复用。

⇒ 而真正的理由，下一镜。

94:16And basically, what you see is that these dot products has the dimension of key and queries grows

这就是那个缩放因子的理由，而它比看上去重要。

Shervine 的话：「而基本上你看到的是：随着 key 和 query 的维度变大，这些点积也会倾向于跟着变大。所以你想把这些点积归一化。而这就是为什么你要除以 key 的维度的平方根。」

★★ 为什么点积会随维度增长？直觉是这样的：点积是 d 个乘积项加起来。如果每一项的量级差不多，那加的项越多，和就越大。而对随机的、独立的项，和的标准差大致按 √d 增长 —— 所以除以 √d_k 正好把它拉回来。

★★★ 而不归一化会有什么后果？这一点 Shervine 没展开，但值得知道：⇒ 点积太大 ⇒ softmax 的输入太大 ⇒ softmax 会变得极度「尖锐」（几乎把全部权重给一个位置、其余接近 0）。⇒ 而 softmax 在那种极端区域梯度几乎为零（回想第 12 条讲 sigmoid 时说的「两端很平」）。⇒ 于是训练就学不动了。

★ 所以这个 √d_k 不是美化，它是让训练能进行下去的必要条件。

94:37And this is Afshine explained as having the query projected on the space of keys

最后一步，而它正好闭合了第 35 条那个「比 key、给权重、取 value」。

Shervine 的话：「然后现在你有了这一切的 softmax，你把它乘上矩阵 V。而这就是 Afshine 解释的那个：把 query 投影到 key 的空间上，然后乘以对应的 value。所以 value 是我们投上去的那个对应 key 的表示。于是你对每一个 query，最后得到一个 value 的加权和。」

★★★ 「对每一个 query，一个 value 的加权和」—— 这就是自注意力输出的一句话定义。

⇒ 把形状对上：n×n 的权重矩阵 乘 n×d_k 的 V，得到 n×d_k。每一行是一个 token 的新表示，而它是全句所有 token 的 value 按权重混合出来的。

★★ 到这里，第 34 条那个「teddy bear 的表示对它所处的上下文是独一无二的」就有了完整的机制解释：⇒ teddy bear 那一行的新表示 = 句子里每个词的 value，按「teddy bear 和它们各自有多相关」加权平均。⇒ 换一句话，周围的词变了，权重变了，混出来的东西自然就不同了。

⇒ 这就是「上下文化」四个字的全部数学内容。

95:20So you are right, it is not just single one, one time that it is done

多头在这里被完整交代了一遍，而重点在最后两步（拼接与投回）。

Shervine 的话：「有人问过 multi-head 是什么东西。所以你说得对，它不是只做单独一次。它实际上是每次都做。而你得到的是 —— 所有这些是并行做的。最后你得到 h 个这样的矩阵。然后你把它们按列拼接起来。」

★ 三个动作：① 做 h 次（每次用自己的那组 W_q、W_k、W_v）；② 并行做（互不依赖，所以能同时算）；③ 按列拼接（concatenate）。

★★ 形状对一下：每个头输出 n × d_k；h 个头按列拼接 ⇒ n × (h·d_k)。⇒ 行数仍然是 n（每个 token 一行），但宽度变成了 h 倍。

⚠ 而这就带来一个问题：进来的是 n × d_model，出去的是 n × (h·d_k) —— 形状对不上了。⇒ 而第 41 条说过，形状必须进出一致，这些层才能堆起来。

⇒ 下一镜就是解决这个问题的那一步。

95:37And at the end of this, you have another projection matrix that you call Wo

这一步解决了上一镜那个形状问题，而它的意义比看上去大。

Shervine 的话：「而在这一切的最后，你有另一个投影矩阵，你叫它 W_o，它会把所有这些投影回嵌入原来的维度。所以这是一种办法，让网络有一个维度不变的方式 —— 从原来的维度出发，再回到原来的那个。」

★★ 「维度不变（dimension-invariant）」这个说法点出了要害：⇒ 多头注意力这一整块，是一个「n × d_model 进、n × d_model 出」的模块。

⇒ 中间它内部膨胀成了 h 倍宽，但出口被 W_o 压回原尺寸。

★★★ 而这就是「能堆叠」的技术前提：既然进出形状一样，你就可以把同样的模块一个接一个地叠起来。⇒ 下一镜 Shervine 就会说：你不是只有一个 encoder 模块，而是有 N 个。

⇒ 如果没有 W_o 这一步，每叠一层维度就乘 h，叠几层就爆炸了。

★ 所以 W_o 看起来只是「一个投影」，实际上它是整个架构能变深的那块基石。

96:24So what makes it different?

这个追问在第 39 条出现过，Afshine 给了个简短回答；而 Shervine 这里给的回答完整得多。

学生的问题：关于 h —— 有没有可能每次得到一样的结果？如果那样，拼接同一个东西会有帮助吗？

★ Shervine 的回答：「那么是什么让它们不一样？那是梯度下降的魔法。网络在最后有一个目标函数。它有自由度。它的激励是去建出一个有助于学习下一个词的表示。」

★★★ 这个论证的结构值得学，因为它不是「因为设计是这样」，而是「因为激励是这样」：⇒ 没有任何机制禁止两个头学成一样；但两个一样的头不会让损失更低。⇒ 而梯度下降在找更低的损失，所以它没有动力让它们一样。

⇒ 下一镜 Shervine 会把这个论证说完，而他的收尾非常诚实。

96:57So what makes it such that you do not have the same thing?

这是对那个追问的完整回答，而它的诚实程度和第 21 条那个「我没有好答案」是一个级别的。

Shervine 的话：「它没有动机去复制同一个东西、或者做同样的机制。而这就是为什么实践中你看到模型会收敛到建出不同的表示，然后它可以把它们拼接起来、再投影成有用的东西。」

⇒ 那么是什么让你不会得到同样的东西？什么都没有。就像，你没有任何约束。但「你让模型去进行的那种学习」的性质，使得它实践中就这么做了。

★★★ 请把这两句话放在一起体会：「什么都没有」+「但实践中它就这么做了」。

⇒ 这是深度学习里一类非常典型的情形：行为不是被设计保证的，而是被优化压力诱导出来的。

⚠ 而知道一个性质属于「保证的」还是「诱导的」，在实践中非常重要：保证的性质你可以依赖；诱导的性质在分布变了、规模变了、目标变了的时候可能就不成立了。

⇒ 他最后半开玩笑地说：我是说，梯度下降通常会创造奇迹。这句玩笑背后是实话 —— 这个领域有相当多东西是靠「它就是能 work」支撑的。

把多头这一整块的形状串一遍，你就能完整地画出它了。

① 输入 X：n × d_model（n 个 token，每个 d_model 维）。

② 每个头各自用自己的 W_q、W_k、W_v 投影，各算出一个 n × d_k 的输出。⇒ h 个头并行做。

③ 把 h 个 n × d_k 按列拼接 ⇒ n × (h·d_k)。

④ 乘上 W_o ⇒ 回到 n × d_model。

★★ 于是整块是「进出同形」的，而这正是能堆 N 层的原因。

⭐ 顺带一个常见的设置值得知道（Shervine 没说，我补的）：通常取 h · d_k = d_model。⇒ 也就是说，把 d_model 维切成 h 份，每个头分一份。⇒ 这样多头几乎不增加计算量 —— 它是「把同样的维度分给几个头各用各的」，而不是「把计算量乘 h 倍」。

★ 这个设计很巧：多头换来的是「多个不同的关注角度」，而代价接近于零。这也解释了为什么多头几乎是标配。

97:27So now that we have gone through the self-attention layer, you have another component that is the FFN

Shervine 在这里回答了之前那个关于隐层维度的问题，而答案很有意思 —— 它和 Word2vec 正好相反。

他的话：「现在我们过完了自注意力层，你有另一个部件，就是 FFN。而我想刚才这里有个问题，是关于「怎么相对于输入和输出来选隐层的维度」。所以当 Afshine 讲 Word2vec 时，你通常有一个比输入输出更小的维度。但这里，实际上隐层的维度比输入和输出都更大。而这样做的道理是：你想有足够的自由度让模型去学有用的表示。所以这是一种把你学到的特征复杂化的方式。」

★★ 两者方向相反，因为目的不同：Word2vec 的隐层是「要被拿走当表示的那一层」—— 所以要小，压缩才能逼出相似度（第 25 条）。而 FFN 的隐层只是中间计算 —— 它不会被拿走，所以可以放大，给模型更多转圜空间。

⇒ 所以「隐层该大还是该小」没有统一答案，取决于那一层是「瓶颈」还是「中转」。★ 这是个很好的判断依据，值得带走。

98:11And you do not have just one encoder module

堆叠这一步，以及一个容易搞错的连接方式。

Shervine 的话：「而你不是只有一个 encoder 模块 —— 你实际上有 N 个，原论文里是大写的 N。而在这一切的最后，你得到一组编码过的、上下文感知的嵌入。然后这些被编码的嵌入，会是那些被喂给 N 个 decoder 的东西。所以你有一串堆叠的 N 个 encoder，你有一串堆叠的 N 个 decoder。」

★★★ 而最关键的那个细节是：「而 encoder 的最后那个表示，就是你会喂给每一个 decoder 的 cross-attention 的东西。」

⇒ 请把这个连接方式想清楚，因为它很容易被想错：不是「第 1 个 encoder 接第 1 个 decoder、第 2 个接第 2 个」。⇒ 而是：N 个 encoder 先串着跑完，得到一份最终表示；然后这一份表示被送给每一个 decoder 层的 cross-attention。

★ 所以 encoder 和 decoder 的关系是「一对多」的：一份编码结果，被所有解码层共用。⇒ 这也意味着 encoder 只需要跑一次，而 decoder 要跑很多次（每生成一个 token 跑一轮）。

98:57So how do we even start the decoding process?

解码起步，而这里的「因果」正是第 37 条那个 masked 的另一个名字。

Shervine 的话：「那我们到底怎么开始解码过程？你从 BOS token 开始，基本上是在跟模型说：嘿，我们需要预测下一个词了，咱们开始吧。那么一开始 BOS token 会发生什么？你把它喂给 decoder。然后和之前 encoder 那里类似，你有一个自注意力层。而如 Afshine 提到的，这个自注意力层是因果的（causal）。」

★★ 「因果」的定义他说得很准：「所以注意力会在同一个 token 和它前面的那些 token 上做。」⇒ 也就是：第 i 个位置只能看 1 到 i，不能看 i+1 以后。

⇒ 这正是第 37 条那个 masked self-attention，「masked」和「causal」是同一件事的两个名字（又一组同义词）。

★ 而他观察到一个有意思的边界情形：「所以在这第一个 BOS token 上，你看不出区别，因为它只会 attend 它自己。但当你有别的要解码的 token 时，你就会在「你 attend 到哪里」上看到这个区别。」

⇒ 第一步时 mask 不起作用（因为只有一个 token），从第二步开始才显现。

99:51And then you have what I mentioned to be the cross-attention

decoder 里的三件事，而第 ② 件正好印证了第 37 条那个记法。

Shervine 的话：「然后你有我提到的那个 cross-attention，它把这些编码过的嵌入作为 key 和 value 输入。而 query 是从自注意力层出来的那些。好，然后一旦你做完这个 cross-attention，你就像在 encoder 里一样，有一个 FFN 部件，让表示更丰富。然后在最后，你把这一切做 N 次。」

★★ 对照第 37 条那个记法：谁在提问谁就是 Q。⇒ 这里提问的是 decoder（我要决定下一个词），所以 Q 来自 decoder 的自注意力输出；被查的是源句子，所以 K 和 V 来自编码过的嵌入。⇒ 完全一致。

★ 而 decoder 的结构比 encoder 多一层：encoder 是「自注意力 → FFN」两件事；decoder 是「因果自注意力 → cross-attention → FFN」三件事。⇒ 多出来的正是那层「看源句子」的 cross-attention。

⇒ 这也说明了为什么只有 encoder-decoder 架构才有 cross-attention：纯 decoder-only 的模型（也就是今天的 LLM）没有一个独立的源序列要看，所以它只有因果自注意力。

100:32And at the very end of the decoding process, you have a linear projection and a softmax layer

最后一步，整个循环闭合，而本讲的所有伏笔都在这里收完。

Shervine 的话：「而在解码过程的最末尾，你有一个线性投影和一个 softmax 层，把「下一个词的预测」变成词表上的一个概率分布。好，所以我们看了怎么对这里的下一个词做这件事。而基本上你一遍又一遍地做。」

⇒ 你找到了你的下一个 token，它基本上是你想要的那个东西的 one-hot 编码。然后你拿那个嵌入，把它放回 decoder，继续这个过程。

★★ 然后他把那个问题抛给学生：「那什么时候停？这是个留给你们所有人的问题。」答案是：当你撞上 EOS token 的时候。

⇒ 这正是第 28 条那个学生提问的闭环：当时有人问「生成什么时候停，不然它不就永远停不下来了吗」，Afshine 答了 EOS；而现在你看到它在完整流程里的位置。

★ 他的收口：「而用这个过程，基本上就是这篇原始的里程碑论文的作者们做机器翻译的方式。所以这通常就是当时被呈现的那个用例。」

⇒ 全讲到此结束。从「NLP 是什么」到「一个 token 怎么被生成出来」，111 分钟。
