00:13a topic that has been trending over the past year or so which is LLM reasoning

开场就说了两件事：这个话题很新，而且它直接接着上一讲。

⭐ 「一个很好的衔接」这句话不是客套，它是一个很实在的提醒：这一讲的核心算法 GRPO，是 PPO 的一个变体。它的 advantage、它的 clip、它的 KL 项，全部来自 L5。所以 L5 那一段 RL 如果没过，这一讲会很吃力。

而「过去一年左右」这个时间范围也值得记：这节课录于 2025 年春。所以「过去一年」指的是 2024 年到 2025 年初。而那正好是 o1 和 DeepSeek-R1 出现的那一年。

讲者接下来会说：几乎所有内容都来自 2024 或 2025 年。

⚠ 这是这门课里时效性最强的一讲 —— 而它也是最接近今天研究前沿的一讲。

01:29it only knows how to autocomplete a sequence

回顾第一步，而这句话已经是第三次出现了。

⭐ 「只知道怎么自动补全一个序列」这句话在这门课里出现了三次：L4：用泰迪熊那个失败的例子演示出来。L5：「它是一个很棒的自动补全器，但还不是一个有用的模型」。这里：又说了一遍。

所以请留意：这一讲的主角不是流水线上的第四步，而是「推理模型」这个新物种。

⚠ 而「最耗算力的一步」在这一讲结尾会被挑战 —— 因为推理模型把算力挪到了推理端。

02:02which is a high quality, curated data set that we can use to teach our model on how to behave

回顾第二步，而这三步回顾里他只说「教什么」。

⭐ 请注意这三步回顾的详略：每一步他都只说「教什么」，不说「怎么教」：预训练：教文本和代码的结构。SFT：教怎么表现。偏好调优：教该偏好什么（下一镜）。

而他完全没提 LoRA、损失掩码、数据混合 那些细节：因为这一讲用不上它们。他唯一讲得细的，是 RL 那一段 —— 因为 GRPO 要用。

所以你从回顾的详略，就能预判这一讲要用哪些旧知识。

这是一个很实用的听课技巧：看讲者复述什么、跳过什么：他复述的，接下来一定会用；他跳过的，接下来一定用不上。

⚠ 而「高质量、精心策展」这两个词在 L4 和 L5 里都强调过 —— 这是 SFT 数据唯一的要求。

02:47learning to distinguish good from bad using human preference data

回顾第三步，而他明确点出了「哪一部分今天要用」。

⭐ 「那一步今天会有用」是一个非常明确的指路：RLHF 的第一段（训奖励模型）：这一讲用不上。RLHF 的第二段（RL）：这一讲的核心。

而「第一段用不上」这件事本身就很有信息量：它暗示：这一讲的奖励不来自一个学出来的奖励模型。那它来自哪？

答案是「可验证的奖励」—— 数学题对不对、代码跑不跑得过，直接用程序判。而这正是 L5 开场那句「或者对齐到我们定义的某个指标」留下的那扇门。

所以这一讲在 L5 的框架里只换了一个零件：把「学出来的奖励模型」换成「程序判定的奖励」：而那一个零件的替换，带来了整个推理模型这一类东西。

⚠ 请带着这个预判往下听 —— 它会让后面的内容容易很多。

03:31a policy, which is nothing else than just a probability distribution over actions

先把传统 RL 那一边复述一遍，而这次的措辞比 L5 更干脆。

⭐ 「policy 不过就是动作上的一个概率分布」—— 这句话值得单独记：在 L5 里他是先写公式 π_θ(a|s)，再解释。这里他直接给了那句大白话。复述时往往比第一次讲时更精炼 —— 因为他知道你已经见过了。

而这个定义之所以重要，是因为它让「训练一个策略」变得具体：策略是一个概率分布。分布由参数决定。所以「训练策略」= 「调参数，让那个分布变成我们想要的样子」。

而在 LLM 里，那个分布就是模型输出的 softmax。

⚠ 这一段回顾讲得比 L5 快得多 —— 他默认你刚听过。

04:11the environment that it interacts with is just a set of tokens that it can predict over

那张对照表再过一遍，而他给 agent 加了引号。

⭐ 「引号，agent」这个小动作值得注意：他在 L5 里也做过同样的事：「我指的是 RL 术语里的 agent」。因为今天「agent」这个词已经被 LLM 圈用成别的意思了。而那个意思是 L7 的主题 —— 下一讲。

这个小心翼翼在这一讲里尤其必要：因为这一讲讲的是推理模型，而推理模型常常被叫做「agentic」。但那是另一回事：推理是「想得久」，agent 是「会调工具、会行动」。

两者今天经常被混着说，而这门课把它们分成了两讲。

请把这个区分记住，因为它会帮你读懂今天大量混乱的宣传：L6 讲「想」，L7 讲「做」。

⚠ 而 environment 那一格在 L5 里讲者自己就说过有点牵强 —— 这里他直接略过了那个保留。

05:08the human preferences is encapsulated in the reward

最后一格，而今天要换掉的正是这一格。

⭐ 「被封装在奖励里（encapsulated in the reward）」这个说法很准，而它正是今天要动的地方：L5 的做法：人类偏好 → 训一个奖励模型 → 奖励。L6 的做法：正确答案 → 程序判定 → 奖励。「奖励」这个接口没变，变的只是它背后插的是什么。

这是一个很漂亮的工程性质：RL 那一整套机器完全不用改：它不关心奖励从哪来。它只要一个数。

所以把「人评」换成「程序判」，是一次「插拔式」的替换。

而这次替换带来了一个巨大的好处，请先想一下是什么：程序判定的奖励没有 reward hacking 的空间（代码跑过了就是跑过了）。而且它不要钱、不要人、可以无限地产生。

于是 L5 里那些关于「奖励模型不完美」的顾虑，一下子都不见了。

⚠ 这就是为什么推理模型这条线能走得这么快 —— 它站在一个干净得多的奖励上。

05:32it has some baseline to just reduce the variance of the gradient

一句话复述完了 L5 讲了十分钟的东西。

⭐ 这句复述里压缩了 L5 的三个知识点，请都认出来：advantage 而不是奖励：我们最大化的是「比预期好多少」。基线：那个「预期」就是基线。降方差：减基线不改变梯度的期望，但减小方差。

而「基线」这个词在这一讲里会变得格外重要：L5 里的基线来自一个单独训练的价值模型。而 GRPO 的全部创新，就在于换了一个基线。

它用「同一个 prompt 采样一组回答的平均分」当基线 —— 于是价值模型整个被去掉了。

所以请把「基线」这两个字记牢，它是这一讲最关键的那个接口：GRPO 这个名字里的 G，就是 Group —— 指的正是那「一组」采样。

⚠ 讲者这里完全没提 value function —— 而那正是因为今天要把它拿掉。

06:09the reason why we don't want to change too much is because our model has already learned a lot

第二部分，而那两个参照物正是 L5 里那个最容易混的地方。

⭐ 两个参照物，这正是 L5 里那个最容易混的地方：π_old（上一次迭代）⇒ 管「速度的上限」⇒ 对应 clip。π_ref（SFT 模型）⇒ 管「位移的上限」⇒ 对应 KL 惩罚。

而「它已经相当能打」这个理由，在这一讲里会被重新审视：L5 的逻辑是：模型已经很好了，别弄坏它。而这一讲要做的，恰恰是让模型学会一个它原来不太会的行为（长链条推理）。

所以「别跑太远」这个约束，在推理训练里的分寸和 L5 不完全一样。

请带着这个疑问往下听：如果我们要模型学会一个新行为，那「别跑太远」还对吗：而后面会看到：有些 GRPO 的变体干脆把 KL 项去掉了。

⚠ 这是这一讲和 L5 之间一个很微妙、但很重要的张力。

07:03R is actually not the reward, it is the ratio

讲者主动承认那一段「有点吓人」，然后又把那个记号陷阱提了一次。

⭐ 这是 L5 那三个符号陷阱里的第二个，而讲者隔了一周又主动提了一次：他在 L5 里说过「这当初也把我搞糊涂了」。而现在他在复述时还要再说一遍 —— 这说明他真的认为这是最容易绊人的地方。

把那两个符号再分清楚一次：r(x, y)：奖励模型给的分 —— 这条回答好不好。R(θ)：两个策略的概率比值 —— 策略变了多少。一个关于「内容」，一个关于「变化」。

而「旧策略是上一次 RL 迭代的那个」也是 L5 那第三个陷阱：它不是 SFT 模型。讲者在 L5 里把这句话连说了两遍。

⚠ 这一讲的 GRPO 会沿用同一个 R(θ) 记号 —— 所以现在把它钉死，后面会省很多事。

08:14this KL divergence is typically applied to the base model, which is the SFT model

两个变体，以及那处 2017 年碰上 2025 年的历史错位。

⭐ 这就是 L5 里讲过的那处历史错位，而它值得再想一遍：2017 年的 PPO 是为机器人和游戏设计的 —— 那里没有「基座模型」这个东西。所以它唯一能参照的只有「上一轮的自己」。而 LLM 场景多了一个很宝贵的东西：一个已经很好的起点。

所以参照物换掉是有道理的：参照上一轮 ⇒ 只能防「步子太大」。参照基座 ⇒ 还能防「走着走着忘了自己是谁」。

而在 LLM 这里，后者是更紧要的那个风险。

请把这个模式再记一次：借用一个成熟算法时，要问「它原本的场景和我的场景差在哪」：而差别最大的那个地方，往往就是你该改的那个零件。

⚠ 而这一讲的 GRPO 正是这个模式的又一个例子 —— 它改的是「基线」那个零件。

08:36we typically have some combination, some mix of these two loss functions

回顾收口，而这八分钟几乎全在讲 RL —— 这本身就是一个信号。

⭐ 这段回顾一共八分钟，而它的详略分布非常说明问题：预训练：三句话。SFT：四句话。偏好调优 + RL + PPO：将近六分钟。

所以从回顾的分配上你就能预判这一讲的结构：它会大量使用 PPO 那一套机器。而它基本不碰 SFT 和预训练。

事实也确实如此：这一讲的核心 GRPO，就是 PPO 换了个基线。

请把「看回顾的详略来预判课的结构」这个习惯带走：讲者花时间复述的，是他接下来真的要用的。这比看提纲准确得多，因为提纲是写课之前定的，而回顾是讲课当天定的。

模块 bvanilla LLM 的四个弱点，与「推理」的定义09:15–15:27

09:15they know a lot about structure, of the text, they know a lot about codes

先给旧模型一个名字，然后老老实实地列它的强项。

⭐ 「vanilla（原味）」这个词在系统和机器学习里是固定说法：它指「最基本、没有加任何花样的那个版本」。L4 里讲 FlashAttention 时也用过这个词（「原味的注意力实现」）。

而讲者先列强项再说弱点，这个顺序是有意的：它避免了一个常见的误导：让你以为「推理模型出来了，普通 LLM 就过时了」。事实恰恰相反：绝大多数日常任务用普通 LLM 更合适，因为推理模型又慢又贵。

而这一点在这一讲最后讲「思考预算」时会再回来。

请把这个列表记一下，因为它定义了「推理模型不需要解决的问题」：写代码、找 bug、写文章、写诗 —— 这些普通 LLM 已经很好了。

⚠ 注意这四项全是「生成类」任务 —— 而它们的共同点是：答案没有唯一标准，而且不需要多步演算。

09:44they have, quote unquote, limited reasoning

第一个弱点，而讲者给的理由非常到位。

⭐ 「没有什么大的理由说它应该能」—— 这句话是整个论证的核心：它用的还是那个老句式：模型只会它被优化的那件事。训练目标是「预测下一个 token」。而「解一道多步数学题」从来不在目标函数里。

所以推理能力在 vanilla LLM 里是一个副产品，不是一个被优化的目标：它能做一点，是因为训练数据里有大量人类的推理过程。但它没有被专门训练去做这件事。

于是碰到够难的题，它就「在半路上迷失」。

这就直接给出了这一讲要做的事：把「推理」从副产品变成一个被直接优化的目标：而这正是 GRPO 那一段在做的。

⚠ 「在半路上迷失（get lost in the way）」这个说法很形象 —— 它描述的是「前几步对了，后面跑偏了」这种典型的失败。

10:40the knowledge that the LLM has acquired is bound to the cutoff date

第二个弱点，而讲者用一个刚发生的事举了例。

⭐ 「静态（static）」这个词是这个弱点的根：预训练数据是某个时刻的一个快照。而模型的知识就冻在那个快照上。世界继续往前走，而模型不会。

这个弱点的解法不是「更频繁地重训」：重训一次要几千万美元（L4 算过）。而世界每天都在变。

所以解法是让模型「去外面查」—— 那就是 L7 的 RAG 和工具调用。

这个例子也顺带透露了录课时间：一场刚过去几天的选举：而讲者稍后会说「今天是 2025 年 11 月 7 日」。

⚠ 请注意他举的是一个「你无法靠推理补上」的例子 —— 再会推理也猜不出谁当选了，这说明弱点二和弱点一是两类不同的问题。

11:17it's all talk, no action

第三个弱点只有一句话，而它是下一讲的全部主题。

⭐ 「全是说，没有做（all talk, no action）」是一句英语习语：它原本是用来说人的：只会讲，不会干。用在 LLM 上非常贴切：它能告诉你怎么订机票，但它订不了。

这个弱点和前两个性质完全不同：弱点一（推理）：是能力问题 ⇒ 靠训练解决。弱点二（知识过时）：是信息问题 ⇒ 靠检索解决。弱点三（不能行动）：是接口问题 ⇒ 靠给它工具解决。

三种问题，三种完全不同的解法 —— 所以它们被分到了三讲。

而这三者在今天的产品里是叠在一起用的：一个能推理、能检索、能调工具的模型 ⇒ 那就是今天说的「agent」。

⚠ 讲者说「你就只能自己去做」—— 这正是 agent 这个概念要消除的那一步。

11:38contrary to traditional NLP models LLMs, they generate free form texts

第四个弱点，而它在这门课里已经被铺过两次了。

⭐ 这一条在这门课里已经被铺过两次了，每次角度都不同：L4：从「没有哪一个数字能告诉你你关心的东西」那个角度。L5：从「BLEU/ROUGE 比的是和参考答案的字面重合，而偏好调优根本没有参考答案」那个角度。这里：从「自由形式的输出装不进旧框架」这个角度。

而这一讲马上要给出一个很重要的例外：数学题和编程题是可以被自动判对错的。所以「难评估」这件事，在推理这个场景里恰好不成立。

而正是这个例外，让 RL 在推理上变得异常好用。

请把这个因果链记住：推理任务可验证 ⇒ 奖励可以程序化 ⇒ RL 可以大规模地跑：这就是为什么「推理」成了 RL 在 LLM 上第一个真正成功的大规模应用。

⚠ 讲者没有点破这个对比 —— 但它就埋在这里。

12:57almost everything that we will see is either from 2024 or 2025

四个弱点的分工，以及一句关于「为什么现在讲正合适」的话。

⭐ 把四个弱点和后面三讲对上，整门课的结构就清楚了：弱点一（推理） ⇒ L6，就是今天。弱点二（知识过时）+ 弱点三（不能行动） ⇒ L7（Agentic LLMs）。弱点四（难评估） ⇒ L8（LLM Evaluation）。

而「我们很幸运，因为现在有足够的后见之明」这句话很诚实：它承认了：一年前讲这个，你分不清哪些方法会活下来。而现在（2025 年春）已经能看出来了。

这也是为什么这一讲讲的是 GRPO 和 R1，而不是 2024 年那一堆已经被淘汰的尝试。

对你这个「为科研看课」的用途，这一讲的时效性是双刃的：好处：它离前沿最近。坏处：它也最容易过期 —— 一年后这些细节可能就变了。

所以听的时候要分清：哪些是「这一年的做法」，哪些是「不会过期的判断」。

⚠ 我会在这部片子里尽量把这两类标出来。

13:13the goal for today is going to be to know what reasoning models are

今天的两个目标，而讲者把验收标准也说了。

⭐ 这两个目标正好对应这一讲的两半，而它们的性质不同：目标一（是什么）：一个概念和定义的问题。目标二（怎么训）：一个算法和工程的问题。

而「怎么训」那一半会占掉这一讲的大部分时间：因为它要讲 GRPO、讲可验证奖励、讲 DeepSeek-R1 的流水线。而「是什么」那一半其实很短 —— 它基本上就是「把 CoT 放大」。

13:47there's not a commonly agreed upon definition out there of what reasoning is

坏消息先说：这个领域最核心的那个词，没有公认的定义。

⭐ 「没有公认定义」这件事值得停一下，因为它有实际后果：不同论文说「推理能力提升了」时，说的可能不是同一件事。有人指数学题准确率，有人指逻辑一致性，有人指能不能分解问题。所以读论文时，第一件事是看它怎么量「推理」。

而讲者给的定义「解决一个问题的能力」是一个操作性定义：它不试图说清「推理在本质上是什么」。它只说「我们用什么来判断有没有推理」。

这是一个很工程的处理：绕开哲学争论，直接给一个能测的标准。

请注意这个做法和 L4 结尾那段是一脉相承的：量不清的东西，就先定义一个能量的代理。而代价是：你从此只能谈那个代理 —— 以及它会被 hack 掉。

⚠ 讲者说「我会尽我所能」—— 他明确标注了这是他自己的定义，不是领域共识。

14:29we typically need a multi-step reasoning process

定义的第二半才是关键：它需要多步。

⭐ 完整的定义是两半，而第二半才是真正起作用的那一半：① 解决一个问题的能力。② 而解决它需要一个多步的过程。第一半太宽（什么都算），第二半才把范围收住。

「多步」这个特征为什么是关键：它正好解释了为什么「让模型多生成一些 token」会有用。如果答案是一步就能得到的 ⇒ 多想没用。如果答案需要多步 ⇒ 给它空间把这些步写出来，就真的有用。

所以「推理模型」这个方案，和「推理问题」这个定义是配套的。

而「数学题和编程题」这个范围限定，其实暴露了一个更深的原因：这两类题不只是「需要多步」，它们还「可以被自动判对错」。而后者才是它们成为训练场的真正理由。

⚠ 讲者说「希望这些能力也能扩散到别的领域」—— 这是一个期望，不是一个已经被证实的结论。

15:27how old is that bear now in 2025

两个例子一摆，区别就一眼看出来了。

⭐ 这两个例子的差别，用一个词就能说清：查表 vs 演算：课程代码：答案已经在模型里了，只需要取出来。熊几岁：答案不在模型里，必须现场算（2025 − 2020）。

而这个区别直接对应两种不同的失败模式：知识题答错 ⇒ 要么没学过，要么记混了 ⇒ 靠检索解决。推理题答错 ⇒ 知识都有，但步骤走错了 ⇒ 靠推理训练解决。

所以这两类问题要用完全不同的办法修 —— 这正是四个弱点被分到三讲的原因。

不过讲者很诚实地加了一句：「这个超级简单」：2025 − 2020 确实不需要什么推理模型。他只是在演示那个「模式」，而真正的推理题是竞赛数学那个量级的。

⚠ 而「熊」这个例子也延续了这门课的传统 —— L1 到 L5 一直在用泰迪熊。

模块 c核心想法：把 chain of thought 放大15:59–22:09

15:59the core idea here is to leverage a concept we saw earlier in the class

这一讲的核心想法，一句话就说完了：把一个旧技术放大。

⭐ 这句话的分量请不要低估：推理模型的起点不是一个新架构。它不是一个新的注意力机制、不是更多参数、不是更长的上下文。它是一个 2022 年的 prompting 技巧（Wei et al.，Chain-of-Thought Prompting）。

而「借用一个前面看过的概念」这个说法说明了这门课的设计：L2/L3 讲 CoT 时，它只是「prompting 的一个技巧」。到了这里，它成了「一整类模型的定义特征」。

同一个东西在两个尺度上的意义完全不同 —— 这正是「放大」这个词的含义。

请先把这条路线图记住，因为这一讲剩下的全部内容都挂在它上面：① CoT 是一个 prompting 技巧 ⇒ ② 把它放大 ⇒ ③ 怎么让模型「自己就这么做」而不用你 prompt ⇒ 那就是训练的部分。

⚠ 而讲者又在用提问的方式开场 —— 这门课里他每次要引入一个关键概念，都先把它交给学生说一遍。

16:32thinking in steps instead of just giving just a blanket answer

学生给了一个很精炼的回答。

⭐ 「thinking in steps instead of just giving a blanket answer」这十来个词，就是 CoT 的全部定义：「blanket answer」= 一个笼统的、不带过程的答案。「thinking in steps」= 把中间过程写出来。

而请注意这里什么都没变：模型没变、权重没变、架构没变。变的只是「输出的形状」—— 从「答案」变成「过程 + 答案」。

而这个输出形状的改变，就让准确率显著提升了。这件事在 2022 年是相当令人意外的。

为什么写出过程会让答案更准？讲者马上会给两个直觉：① 把难题分解成模型见过的小题。② 多生成 token = 多给算力。

这两个直觉值得分开记，因为后面的「思考预算」只建立在第二个上。

⚠ 讲者话说一半被打断了（「就为了说明 —— 对。哦，对」）—— 又有学生举手，而那个追问很好。

17:18typically LLMs they have something that we call preamble

这个追问抓得很准，而它正好戳在刚才那个例子上。

⭐ 这个学生发现了那个熊的例子里的一个漏洞：「2020 年出生的熊在 2025 年多大」要算 2025 − 2020。但如果题目只说「现在」呢？模型怎么知道「现在」是哪一年？

而「preamble（前言）」这个词值得记一下，因为它是一个实际的工程细节：它是系统 prompt 的一部分，由服务方自动塞在你的输入前面。里面典型地有：当前日期、模型自己的身份、一些行为约束。

所以「今天是哪天」这件事，模型不是「知道」的，是「被告知」的。

这也顺带把录课日期钉死了：2025 年 11 月 7 日：而前面那场「几天前的选举」就是美国 2025 年 11 月 4 日那场。

⚠ 注意这和弱点二（知识截止）是同一个问题的两个解法 —— preamble 解决「静态的一小块」（日期），而 L7 的检索解决「动态的一大块」（新闻、文档）。

17:48in lecture 7, we will see how we can fetch that

而讲者把边界划得很干净。

⭐ 「扩展」和「基础性」这个区分非常重要，而它正是这一讲和下一讲的分界线：基础性（今天）：模型自己能不能把一个难题分步走完。扩展（L7）：模型能不能去外面取它没有的东西。

为什么这个顺序是对的：一个不会推理的模型，就算给它检索也用不好（它不知道该查什么、查到了也不会组合）。而一个会推理的模型，加上检索就立刻强一个量级。

所以推理是底座，检索是放大器 —— 顺序不能倒。

而这也解释了今天的 agent 为什么都是推理模型：「决定下一步该调哪个工具」本身就是一个多步推理问题。

⚠ 讲者说「绝对是一个会非常有用的东西」—— 他在给下一讲打广告，但这个判断是对的：RAG 和工具调用是今天落地最多的那一块。

18:34the way chain of thought did that was by having some in-context learning examples

CoT 的机制，以及这一讲的全部纲领。

⭐ 注意 CoT 原始版本的机制：它完全不训练任何东西：它只是在 prompt 里放几个例题，而例题的答案里带着解题过程。模型看到这个格式，就照着这个格式输出。

这是纯粹的 in-context learning（L2 讲过）：不改一个权重，只改输入。

而讲者那句自我更正很有意思：「那就是粗略的想法 —— 不，那不是粗略的想法，那就是那个想法」：他本来想说「大致是这样」，然后自己改口说「就是这样，没有更多了」。意思是：CoT 真的就这么简单，没有隐藏的复杂性。

「在一个大得多的尺度上」—— 这七个字是这一讲的全部纲领：「尺度」指什么？指推理链的长度（从几句变成几千 token）、指它的来源（从 prompt 示例变成模型自己学会）。

⚠ 所以「推理模型」的一句话定义是：把 CoT 从「你 prompt 它」变成「它自己就这么做，而且做得长得多」。

19:36there are very few chances that that problem appeared in the training sets

第一个直觉，而它本质上是一个「覆盖率」论证。

⭐ 这个论证的结构非常清楚，而它完全建立在「下一个 token 预测」这一件事上：模型只会重现它见过的模式。一道难题整体：训练集里几乎肯定没有。但这道题的每一个小步骤：训练集里有成千上万个例子。

所以把难题拆开，就把「没见过的东西」换成了「见过很多次的东西」。

这是一个覆盖率论证，而它解释了一个具体的现象：为什么 CoT 在多步算术上提升巨大？因为每一步单独看都是模型早就会的。为什么 CoT 在需要新知识的题上没用？因为分解不出模型见过的子问题。

「听起来可信（sound plausible）」这个措辞请留意：它诚实地说明了模型的默认行为：它优化的是「像人会说的话」，不是「对」。

⚠ 而这正是为什么推理需要被单独训练 —— 「可信」和「正确」不是同一件事。

20:06you try to link it back to something that you know

讲者又把这个直觉接到你自己的考试经验上。

⭐ 这个类比其实比它看起来更准确：你做一道没见过的难题时，你做的事情是什么？你不是「凭空想出一个解法」。你是在回忆：「这一步像我做过的哪道题」。

而把题拆成几步，正是为了让每一步都能对上你记得的某个套路。

而这个类比也点出了 CoT 的一个限制：如果某一步完全不像任何你学过的东西 ⇒ 拆得再细也过不去。模型也一样：分解只能把问题移到「它熟悉的区域」，移不进去就还是解不出。

讲者把「你学习的时候」直接叫成「训练时（at training time）」：这个人—模型的类比在这门课里反复出现。L5 讲偏好调优时他用过「你怎么学会写得像个人」。

它好用，但也要小心：类比能帮你记住机制，不能当成证据。

⚠ 下一个直觉会完全不同 —— 它不靠类比，而是一个硬的计算量论证。

20:37when you let the LLM generate more tokens, you're just giving it more compute

第二个直觉，而这一条最硬 —— 它不是类比，是一个计算量恒等式。

⭐ 请把这一条和上一条分开记，因为它们的性质完全不同：第一个直觉（分解）：一个关于「模型见过什么」的论证 —— 是启发式的。第二个直觉（算力）：一个关于「花了多少 FLOPs」的论证 —— 是恒等式。

这个恒等式为什么成立：一个标准 LLM 对每一个输出 token 做一整次完整的前向传播（L1/L4 讲过）。所以N 个 token = N 次完整前向传播。生成 1000 个 token 的「思考」= 比直接答一句话多花了几百倍的计算。

而一个固定大小的模型，想在一次回答里多花算力，唯一的办法就是多生成 token。

这一条是后面一整块内容的地基：它直接定义了「test-time compute（推理期算力）」这个概念。它让「思考预算（compute budget）」成为一个可以调的旋钮。而它也解释了推理模型为什么又慢又贵 —— 慢和贵不是实现问题，是这个方案的本质代价。

⚠ 讲者在这里就把「compute budget」这个词预告了 —— 记住它，这一讲后面会回来。

21:45we don't want to directly generate an answer

讲者先确认大家跟上了，然后把两种模型并排摆出来。

⭐ 「We first want to think」—— 四个词，而这就是全部的结构差别：vanilla LLM：问题 ⇒ 答案。推理模型：问题 ⇒ 思考 ⇒ 答案。

就这一处差别。没有新架构，没有新的层，没有新的注意力机制。

而这件事值得你停下来想一想，因为它违反直觉：一个让模型在同一个自回归通道里多写一段话的改动。却造就了 2024–2025 年最大的一次能力跃升。

而这说明：瓶颈从来不在模型能表达什么，而在它被允许花多少步去表达。

请注意讲者又用了一次「引号，vanilla LLM」：他加引号是因为这不是一个标准术语，是他自己为了对比而起的名字。

⚠ 而他每次引入关键对比都会先确认一句「大家清楚了吗」—— 这是一个教学信号：下面这句话很重要。

22:09it's the reasoning plus the answer

一个式子就能写完这一讲的上半场。

⭐ 「输出 = 推理 + 答案」这个式子是整个下半场的前提：它使得「思考摘要」成为一个问题（推理那一段要不要给用户看）。它使得「思考预算」成为一个旋钮（推理那一段允许多长）。它使得「只奖励答案」成为可能（答案可以自动判对错，而推理过程不用管）。

而最后那一点是 GRPO 能工作的全部原因，所以请现在就记住：既然输出被分成了两段。而我们只需要判「答案」那一段对不对。那就不需要任何人标注「推理过程好不好」—— 奖励可以完全程序化。

而这正好绕开了 L5 里「偏好数据贵、奖励模型会被 hack」那一整套麻烦。

对比一下 L5 和 L6 在这件事上的处境，差别巨大：L5（偏好调优）：输出是自由文本 ⇒ 只能靠人标注偏好 ⇒ 训一个奖励模型 ⇒ 会被 hack。L6（推理）：输出末尾是一个可判定的答案 ⇒ 奖励直接算 ⇒ 不会被 hack（至少不容易）。

⚠ 这就是为什么 RL 在推理上的成功，比在对齐上的成功来得更干脆。

24:33when the model that you're interacting with is a reasoning model

24:58the key word here is thinking

答案是一个词，而全行业用的是同一个词。

⭐ 请注意这个用词的一致性，它在整个行业里出奇地统一：ChatGPT：「Thinking…」/「Thought for 8 seconds」。Gemini：模型名字里就带「Thinking」。Claude：「extended thinking」。

而这不是巧合。

为什么大家都要在界面上显式地标出来：因为推理模型有一段明显的空白等待（几秒到几十秒）。而一个没有解释的等待会被用户读成「卡住了」。

所以「Thinking…」这三个字其实是在做一件产品设计的事：把一个技术代价翻译成一个用户能接受的叙事。

而它顺带还做成了一件事：它把「我花了更多算力」变成了一个可见的卖点，而不是一个缺点。「它在认真想」比「它比较慢」好听得多，而两句话说的是同一件事。

⚠ 下一镜会给出一个更重要的事实：这个界面给你看的「思考」，并不是模型真正的推理链。

25:29that time thinking is actually the time that is needed to produce the reasoning chain

这里埋了一句伏笔，而顺带给出了「思考预算」的产品形态。

⭐ 两件事在这一镜里被串起来了，请分别记：① 界面上的「思考」是一个摘要，不是原始链 ⇒ 下一个知识点会讲三个理由。② 「standard / extended」这个开关，就是前面预告的「compute budget」。

第二点值得多说一句，因为它把一个抽象概念落到了你见过的界面上：你在 ChatGPT 里选 extended thinking。你做的事情就是「把思考预算调大」。而代价是：更慢、更贵。

所以这个旋钮不是一个「要不要开更好的模型」的开关，而是一个「花多少算力买多少准确率」的滑块。

而「思考的时间 = 产生推理链所需的时间」这个等式也值得记：它说明那个等待时间不是在「搜索」，不是在「查资料」。它就是在一个 token 一个 token 地写。

⚠ 所以等待时间长短基本上正比于推理链的 token 数 —— 而这正是第二个直觉的直接推论。

25:59thought summary that you see is not the raw reasoning chain

一个很多人每天用却不知道的事实，以及前两个理由。

⭐ 先把这个事实本身记住，因为它经常被误解：你在界面上看到的那几行「我在考虑…」。不是模型真的生成的那条链。它是另一个（通常更小的）模型对那条链做的摘要。

所以你无法从界面上读出模型真实的推理过程。

而讲者在这里非常明确地加了一句「我在做假设」：这三个理由是他的推测，不是任何官方声明。而他在这门课里每次给推测都会这样标注（L5 讲 reward hacking 时也是）。

这个习惯值得学：区分「我知道」和「我猜」，比两者都说得斩钉截铁要有用得多。

前两个理由各自的性质：理由一（不可理解）：一个关于原始链真实样子的技术观察 —— 它可能语法破碎、反复自我纠正、夹杂无意义的试探。理由二（太长）：一个纯粹的产品理由。

⚠ 而第三个理由完全不同 —— 它是一个商业理由，而且讲者说「这将是我们要看到的东西」。

26:29you can maybe train a model that is trained on these chains

第三个理由的分量最重，而它是后面「蒸馏」那一段的全部前提。

⭐ 这个理由为什么比前两个重得多：前两个理由说的是「给你看也没好处」。第三个理由说的是「给你看对我们有坏处」。

而后者才是一个真正的、不会被产品改版推翻的理由。

这里的机制你已经有能力理解了：一条高质量的推理链 = 一条完美的 SFT 训练样本（L4 讲过）。收集几万条 ⇒ 在一个小模型上做 SFT。小模型就能「模仿」出大模型的推理行为。

这件事有名字，叫「蒸馏（distillation）」，而这一讲后面会专门讲 —— DeepSeek-R1 正是这么把能力传给一系列小模型的。

所以「不给你看原始链」这个决定，本质上是在保护一份资产：原始链不是日志，它是「最值钱的那份训练数据」。把它公开，等于把你最贵的训练成果免费送给竞争对手。

⚠ 而讲者说「这将会是我们要看到的东西」—— 他在明确告诉你：这个理由不是闲话，它后面会变成一个正式的技术话题。

27:18those output tokens, they also include reasoning tokens

一个你会在账单上直接看到的后果，而它有一处不太对称的地方。

⭐ 请把两句话摆在一起读，那个不对称就出来了：「你不一定能拿到全部的推理链」。「但你是按输出 token 收费的，而输出 token 包括推理 token」。

所以你为一批你看不到的 token 付了钱。

这不是在指控谁，它只是这个方案的必然结果：那些 token 真的被生成了 ⇒ 真的烧了 GPU ⇒ 成本真实存在。而出于上一个知识点的第三个理由，它们不能给你看。

于是「付费却看不到」就成了唯一可能的安排。

实际影响有多大？这个数要有概念：一道难题的推理链可以是几千个 token。而最终答案可能只有几十个 token。

所以你的账单上，可能 95% 以上是「看不见的思考」。

⚠ 讲者说「总是有一句或两句话」—— 他的意思是：这件事写在文档里，但不显眼。

27:33this also gives an incentive to have the maximum reasoning ability for a minimum amount of reasoning token

一个优化目标在这里自己浮出来了，而它是被定价逼出来的。

⭐ 这句话的形状请看清楚，它是一个标准的约束优化：最大化：推理能力（准确率）。最小化：推理 token 数。

而这正是「思考预算（compute budget）」那一整块内容要解决的问题。

而我想强调它是从哪里来的：它不是从一个学术好奇心来的。它是从一张账单来的。

这件事在这门课里出现过不止一次：L4 的量化和 FlashAttention 也是被成本逼出来的，不是被理论逼出来的。

对你的课题，这个形状应该看起来很熟悉：「在给定算力预算下最大化解的质量」= 你那个「最便宜可行配置」的搜索。「每一步要不要再想一下」= 你那个「要不要再展开这个节点」。

而推理模型这边的做法（固定预算、提前停止、按难度分配）在你那边几乎可以直接搬。

⚠ 讲者说「我们后面会看怎么应对那个」—— 记住这个欠条，这一讲后面会还。

模块 e怎么量推理：benchmark、可验证，与 pass@k28:05–35:08

28:05some of the benchmarks that people use to quantify reasoning abilities

第一块讲完了，现在换到「怎么量」这个问题。

⭐ 讲者自己把那个定义叫「尝试性的（tentative）」：他没有假装那是一个定论。而这和他前面说「外面并没有一个被普遍同意的定义」是一致的。

而这个顺序值得注意：先定义，再量化：定义（tentative）：推理 = 解决一个需要多步的问题。量化：那就找一堆需要多步、而且能判对错的题。

所以 benchmark 的选择不是任意的，它是从那个定义直接推出来的。

请带着一个问题听接下来这一整块：为什么偏偏是「编程」和「数学」？答案不是「因为它们难」，而是下一镜那句话。

⚠ 「修一个 bug」也被列成了目标 —— 注意它比「写一段代码」更接近真实工作。

28:50this is our way of verifying that a response that was generated is actually a correct one

这一句话是这一讲后半场的全部地基，请单独记住它。

⭐ 表面上这是在讲 benchmark，实际上它在讲「奖励从哪来」：有测试用例 ⇒ 答案能被程序判对错。能判对错 ⇒ 奖励可以是一个函数，而不是一个模型。奖励是一个函数 ⇒ 不需要标注、不会被 hack、可以无限量地生成训练信号。

这条链是 GRPO 和 R1 能成立的全部原因。

请把它和 L5 的处境对照一下，差别是结构性的：L5（偏好调优）：「这段话写得好不好」没有程序能判 ⇒ 只能请人标 ⇒ 训奖励模型 ⇒ 会被 hack。L6（推理）：「这段代码对不对」跑一下测试就知道 ⇒ 奖励直接算。

所以「为什么偏偏是编程和数学」的答案是：因为它们是极少数「机器能判对错」的任务。

这也给了一个重要的边界：这一讲的全部方法，都依赖「答案可验证」这个前提。换到「写一封好邮件」上，整套东西就不成立了。

⚠ 讲者在这里说得很平淡 —— 但这是整讲最关键的一句话，请划下来。

29:14a set of 100 something coding problems that were human written

三个编程 benchmark，而它们的来源不同、意思也不同。

⭐ 这三个的排列顺序正好是「越来越像真实工作」：HumanEval（164 道）：人手写的小函数题，每题几行。「Human」指的是题目是人写的，不是从网上爬的 —— 这是为了避免训练集污染。CodeForces：竞技编程题，需要算法设计。SWE-bench：真实 GitHub 仓库里的真实 issue，要在一个大代码库里改对地方。

「所以它才叫 HumanEval」这个解释值得记一下：它不是说「由人来评测」。它是说「题目由人原创编写」。

而原因很实际：如果题目是从网上抓的，模型可能在预训练时就见过答案 —— 那测的就不是能力，是记性。

SWE-bench 的意义和前两个完全不同：前两个测「会不会写算法」。SWE-bench 测「能不能在一个你没写过的大项目里找到该改的地方并改对」。

而后者才是工程师真正在做的事，所以它也是今天被引用最多的那个。

⚠ 讲者两次说「我相信（I believe）」—— 他在凭记忆说数字，所以具体数值你最好自己核一下。

29:38these are real practical problems

从编程换到数学，而验证方式必须换一套。

⭐ 数学和编程在「怎么验证」上有一个实际差别：编程：有测试用例可以跑 ⇒ 验证是「执行」。数学：没有东西可跑 ⇒ 验证只能是「比较字符串」。

而「比较字符串」比「跑测试」脆弱得多 —— 下一镜就会看到为什么。

而「在报告里」这个措辞请留意：它指各家发布模型时的 technical report / model card。那里面典型地就是一张表，列着这些 benchmark 的分数。

所以认识这些名字有一个很实际的用处：你看一份模型报告时能知道它在测什么。

请注意「你是让你的模型生成一些推理的」这句的位置：它是顺口说的，但它意味着：评测时推理链是被允许、甚至被期待的。换句话说，benchmark 只看最终答案，不看过程。

⚠ 而「只看答案不看过程」这件事后面会变成一个问题 —— 一个过程全错但答案蒙对的回答，和一个过程正确的回答，拿到的奖励是一样的。

30:16by parsing the answer like so and then comparing it with some ground truth

数学的验证方式，而「怎么解析」是一个真问题。

⭐ 这个细节听起来很琐碎，但它是实际做这件事时的第一个坑：模型输出的是一大段自由文本。你要从里面把「那个答案」挑出来。如果挑错了，一个对的回答会被判成错 —— 而这会直接污染你的奖励信号。

「放在 box 的括号里」指的是 LaTeX 的 \\boxed{...}：这是数学竞赛题的惯例写法，而所有主流数学 benchmark 都沿用它。于是流程变成：prompt 里要求「把最终答案放进 \\boxed{} 里」⇒ 正则抓出 \\boxed 的内容 ⇒ 和标准答案比。

所以「可验证奖励」不是免费的：它需要一个格式约定，而那个约定要靠 prompt 强加给模型。

注意讲者用的词是「force（强迫）」，而他马上自己解释了：不是改架构、不是加约束解码，就是「在 prompt 里要求」。而模型会不会听？大部分时候会，但不保证 —— 这也是一处噪声来源。

⚠ 「有很多不同的方式做这件事」是一句委婉话 —— 实际含义是：没有统一标准，各家的解析脚本不一样，所以跨报告比分数要小心。

31:04you can let your model generate some reasoning chain along with the answer

一道数学题在 benchmark 里的完整形状，而请注意哪一列需要人。

⭐ 请盯着这三列看一眼，然后数一下「哪些需要人」：问题：需要人（但题库是现成的，一次性成本）。推理链 + 答案：模型自己生成，完全不需要人。ground truth：需要人（但同样是现成的，一道题只要一个答案）。

所以训练时的边际标注成本是：零。

把这个和 L5 的偏好数据摆在一起，成本差距是几个数量级：L5：每一对回答都要请人读两遍再选一个 ⇒ 边际成本随样本数线性增长。L6：题目和答案是现成的，模型可以对同一道题采样一万次 ⇒ 边际成本是 GPU 时间。

而 GPU 时间可以靠买卡解决，人工标注不能。

这就是「可验证奖励（RLVR, RL with Verifiable Rewards）」这个词的全部含义：「可验证」= 不需要人来判，程序能判。而这一讲后面 GRPO 那一整块，都建立在这件事上。

⚠ 注意中间那一列「推理链 + 答案」里，只有「答案」被检查 —— 推理链本身没有任何监督。

31:31it's a math exam to qualify for the US math olympiads

两个数学 benchmark，而它们的难度差得非常远。

⭐ 这两个 benchmark 分处难度的两端，而它们的用途也不同：AIME（American Invitational Mathematics Examination）：美国数学奥林匹克的资格考，15 道题、答案是 0–999 的整数。GSM8K（Grade School Math 8K）：八千多道小学应用题，几步算术。

为什么两个都还在用，这件事反映了这个领域的进展速度：GSM8K 在 2021 年是一个很难的 benchmark。到 2025 年，好模型在它上面已经 95% 以上 —— 也就是「饱和」了。于是大家转向 AIME，而 AIME 现在也在被逼近。

这是一个反复出现的模式：benchmark 被刷满 ⇒ 换更难的 ⇒ 再被刷满。

而 AIME 的「答案是 0–999 的整数」这个格式不是巧合：它恰好让「解析答案并比较」变得极其可靠 —— 一个整数，没有歧义。所以 AIME 流行，一半是因为它难，另一半是因为它好判。

⚠ 讲者说「并不那么平凡」—— 这是在回应他自己前面那个「2020 年出生的熊」的例子：真正用来评测的题，不是那个量级的。

32:22a metric that tries to estimate the probability that at least one of k attempts succeeds

有了题库，还得有一个指标，而讲者提前打了招呼说它不那么显然。

⭐ 这个定义里有三个要素，请分开记：① 「至少有一次」：不是「平均对几次」，是「有没有对过」。② 「k 次尝试」：你允许模型试 k 次。③ 「试图估计」：它是一个「估计量」，不是一个直接数出来的比例。

第三点是讲者说「不那么显然」的原因，而他会为它花一整段：为什么「估计」会难？因为你不能真的跑无限次。你跑了 n 次，想推断「如果只给 k 次机会，成功率是多少」。

而最朴素的做法（直接跑 k 次看有没有成功）方差大得没法用 —— 下一个知识点会给出正确的估计量。

先把 pass@1 这个特例记住，因为它最常被引用：pass@1 = 只给一次机会的正确率 = 日常意义上的「准确率」。而 pass@k（k 更大）总是不小于 pass@1。

⚠ 讲者说「我们现在就要看它」—— 这是一个信号：下面是一段真正的数学，不是一句定义就完事。

32:45the probability that at least one of these k answers passes the tests

用一个具体例子把定义坐实，然后讲者又抛了一个问题。

⭐ 讲者抛的这个问题其实很尖锐，值得你自己先想一秒：「至少一次对」这个指标，听起来像是在放宽标准。如果一个模型要试 100 次才对一次，它真的「会」做这道题吗？

所以 pass@k 凭什么是一个有意义的指标，而不是一个粉饰数字的办法？

答案在下一个知识点，但我先把形状告诉你：它的正当性不是统计上的，是「使用场景」上的。如果你在一个「能检查答案对不对」的场景里，那「试 k 次取对的那个」是一个真的能用的做法。

于是 pass@k 衡量的就不是「它会不会」，而是「在这种用法下它有多有用」。

而这就把指标和部署方式绑在了一起：pass@1 对应「只问一次就用」的场景。pass@k 对应「可以多试几次再筛」的场景。

所以报哪个指标，取决于你打算怎么用这个模型 —— 这和 L4 说「没有哪一个数字能告诉你你关心的东西」是同一件事。

⚠ 「它不是超级平凡的」—— 讲者在承认这个指标确实需要辩护，而他马上就会辩护。

33:36in a problem like coding, the good thing is you can check whether your answer is correct or not

辩护来了，而它的关键一环是「你能检查答案对不对」。

⭐ 这个辩护的结构请看清楚，因为它有一个必要条件：生成 k 个答案 ⇒ 其中至少一个对的概率更高。但「至少一个对」要变成「我拿到了对的那个」，你必须「能认出哪个是对的」。

而在编程和数学里你能认出来（跑测试、比答案）—— 所以 pass@k 在这里是一个真实可用的指标。

把这个条件去掉，pass@k 立刻变成一个假指标：假设任务是「写一封好邮件」。生成 100 封，其中「至少有一封好的」概率当然很高。但你分不出哪一封好 ⇒ 这个高 pass@k 对你毫无用处。

所以 pass@k 不是一个通用指标，它是「可验证任务」专属的指标。

这一镜和前面「这就是我们验证的方式」那一镜是同一件事的两面：可验证 ⇒ 奖励能算（训练那边的好处）。可验证 ⇒ 多试几次能筛（部署那边的好处）。

⚠ 「你负担得起（you can afford）」这个说法出现了两次 —— 它在提醒你这是一个花钱买准确率的交易。

34:18best of n is this method that we saw last week

讲者自己把它接回上一讲，而这个对照非常有用。

⭐ 先把 L5 的 Best-of-N 完整回忆一遍，因为对照全在细节里：做法：采 n 个回答 ⇒ 用奖励模型给每个打分 ⇒ 返回分最高的。卖点：一个权重都不训。代价：每一次服务都要生成 n 遍 ⇒ 永久变贵。

而那个最漂亮的论证是：就算钱无限，「n 条里最慢那条」的延迟也救不回来。

而 pass@k 和 Best-of-N 在形式上几乎一样：都是「采 k/n 个候选，然后挑一个」。差别只在「怎么挑」。

而下一镜会说清这个差别，它比看起来重要得多。

请注意讲者在这门课里反复做这种跨讲的连接：L5 结尾预告 GRPO ⇒ L6 开头回顾 PPO ⇒ 这里回顾 Best-of-N。而每次连接都不是客套，是真的在用上一讲的结论。

⚠ 学生说「对，大致记得」—— 而讲者立刻就把它完整复述了一遍，没有让这个「大致」糊过去。

34:38we do not have a reward model, we have a deterministic, verifiable way of checking whether something is correct

唯一的差别只有一句话，但它消掉了 L5 的两大麻烦。

35:08do you choose a particular temperature

⭐ 这个学生抓到了 pass@k 的一个要害：pass@k 的前提是「生成 k 个答案」。但如果这 k 个答案一模一样呢？那「至少一个对」就等于「那一个对」—— pass@k 退化成 pass@1，整个指标失效。

36:07you typically generate not k, but n answers

⭐ 这一招值得单独说清楚，因为它是整段推导的全部聪明之处：n：你实际生成了多少个答案（可以很大，比如 100）。c：这 n 个里对了多少个。k：你想报的那个指标里允许几次尝试（通常是 1、5、10）。

37:28the probability that at least one attempt out of k that we select out of these n samples is correct

先把要求的东西老老实实写下来。

⭐ 请注意他用的词是「估计（estimate）」：真正的 pass@k 是一个关于「模型在这道题上的分布」的量，我们永远不知道它。我们能做的只是从 n 个样本里估它。

所以这个公式是一个「估计量（estimator）」，不是一个「概率」—— 而这正是讲者说「不那么显然」的那一点。

在往下走之前，请先把三个符号在脑子里固定住：n = 一共生成了多少个答案。c = 其中正确的有几个（c = correct）。k = 指标里允许试几次。

⚠ 混淆 n 和 k 是读这个公式时最常见的错误 —— 而它们在公式里出现的位置完全不同。

38:14if you have a probability of at least one, it's 1 minus the probability of having all of them being incorrect

第一步是整段推导里唯一的技巧，而它很标准。

⭐ 为什么「至少有一个」几乎总要取补，原因是算数量级的：直接算：「正好 1 个对」＋「正好 2 个对」＋ … ＋「正好 k 个对」⇒ k 项相加，每项都是一个组合数。取补算：「全都不对」⇒ 只有一种情况，一个式子。

而两者的答案一样 —— 所以当然选后者。

这个技巧的一般形式你应该背下来，它在概率题里出现的频率极高：P(至少一个 A) = 1 − P(没有一个 A)。而它成立只需要一件事：「至少一个」和「一个都没有」互为补事件。

不需要独立性，不需要同分布 —— 这就是它为什么这么好用。

39:04what is the probability of you finding an unsuccessful attempt

第一次抽，而它简单到不需要解释。

⭐ 这一步就是最朴素的「有利情形 / 全部情形」：不成功的答案有 n − c 个。一共有 n 个答案。随机抽一个，抽到不成功的概率 = (n − c) / n。

不过请停一下，注意这里悄悄做了一个假设：「随机抽一个」意味着这 n 个答案是等可能被选中的。也就是说：我们把「生成 k 个答案」建模成「从那 n 个里均匀随机取 k 个」。

而这正是为什么这个估计量成立：它假设那 n 个样本是从同一个分布独立采出来的。

这个假设有一个实际的含义，而它和那个被按住的温度问题有关：n 个样本必须用「同一个温度、同一个 prompt」采出来。如果你中途改了温度，这个估计量就不成立了。

39:42you have n minus c minus 1 other unsuccessful attempts over n minus 1 because you already took one

第二次之后，分子分母都要少一个 —— 而原因讲者说得很清楚。

⭐ 「因为你已经取掉了一个」这一句话解释了全部的减一：第 1 次抽完，池子里只剩 n − 1 个。而不成功的也只剩 n − c − 1 个（因为刚才抽走的那个就是不成功的）。所以第 2 次的概率是 (n−c−1)/(n−1)。

所以「全都不对」的概率就是这 k 项连乘。

41:49it's factorial n minus c over factorial n minus c minus k

⭐ 先把温度是什么快速过一遍（L1 讲过）：模型在每一步给出一个 logits 向量。采样前把它除以温度 T，再做 softmax。T 小 ⇒ 分布变尖 ⇒ 几乎总选最可能的那个 token。T 大 ⇒ 分布变平 ⇒ 不那么可能的 token 也会被选中。

所以「生成 100 个答案」其实是「把同一个答案抄了 100 遍」。

于是 pass@k 退化成什么：那一个答案对 ⇒ pass@k = 1（对所有 k）。那一个答案错 ⇒ pass@k = 0（对所有 k）。

所以曲线是平的 —— 而这正是讲者说的「它不变」。

而 T = 0.2 就开始涨了，这个变化说明了一件重要的事：只需要一点点随机性，「多采几次」就开始有回报。因为不同的采样会走进不同的推理路径，而其中某些路径能走通。

这就是「多样性有价值」的机制：不是答案本身变好了，是你多了几次走对路的机会。

⚠ 实际工程含义：要报 pass@k（k > 1），温度绝不能设成 0 —— 否则你在花 k 倍的钱买同一个答案。

46:41maybe the tokens that were not that likely will become likely

高温那一端：多样性有了，但每一个答案都变差。

⭐ 「本来不那么可能的 token 会变得可能」—— 这一句就是全部的机制：温度把分布压平。于是本来概率 1% 的那个 token，可能变成 5%。而一条几千 token 的推理链里，只要踩错一步，整条就废了。

所以高温对「长输出」的伤害是累积的 —— 这一点对推理模型格外要命。

请把两端的失败方式对照记，它们的形状完全不同：低温：每一条都是同一条好路 ⇒ 不敢走岔路 ⇒ 多采无用。高温：每一条都走不同的路 ⇒ 但每一步都可能踩错 ⇒ 没一条走到底。

而这个张力你应该已经认出来了：它就是「探索 vs 利用」（exploration vs exploitation）。低温 = 纯利用；高温 = 纯探索。

而最优点在中间，这是所有搜索问题的共同结构 —— 你的课题里也是。

⚠ 「t = 1.2 在这个例子里是极端的」—— 注意他说「在这个例子里」，这不是一个普适的阈值。

47:40consensus at k, which is the answer that is coming from the highest number of times

另一个指标，而它和 pass@k 的前提不同。

⭐ 请把两个指标的前提对照一下，差别很重要：pass@k：「k 个里至少一个对」⇒ 需要你「能认出哪个对」 ⇒ 只能用在可验证任务上。consensus@k：「出现最多的那个答案对不对」⇒ 不需要你能验证，只需要能数票。

所以 consensus@k 适用范围更广，但它也更弱：如果模型系统性地错在同一个地方，多数票会一致地错。

而 self-consistency 就是把 consensus 当成一个推理策略来用（L3 讲过）：采 k 条推理链 ⇒ 取每条的最终答案 ⇒ 投票 ⇒ 返回票数最多的。它比贪心解码好，而且不需要任何验证器。

所以 self-consistency 是「部署时就能用」的方法，pass@k 更多是「评测时用的指标」。

一句很实际的提醒：这三个很容易混：pass@k = 指标，要验证器。consensus@k = 指标，要投票。self-consistency = 方法，就是投票那件事本身。

50:04the way the model reasons may be different from the way we reason

第二个事实比第一个深，而讲者说得非常克制。

⭐ 两条反驳的性质完全不同，请分开记：第一条：「做不到」—— 那份数据太贵，凑不出来。第二条：「就算做到了也不一定好」—— 人类的推理路径未必是模型的最优路径。

所以第二条即使在钱无限的情况下仍然成立，而第一条不成立。

为什么「模型推理的方式可能和我们不同」是合理的：人类推理受工作记忆限制，所以我们会尽量少写中间步骤。模型没有这个限制：它可以把中间结果全写在上下文里。所以模型的最优策略可能是「写得极其啰嗦、反复验算、把失败的尝试也写出来」。

而一个人类专家绝不会那样写题解 —— 太难看了。

这一条后来被 R1 的结果强烈证实了，而这是这一讲最有意思的发现之一：R1 自己学出来的推理链里，有大量「等一下，我再检查一遍」式的自我纠正。那种写法没有任何人类会写进题解，但它确实提高了正确率。

所以「让它自己摸索」真的比「让它学人类」更好 —— 这一条讲者这里只是猜，但后来被验证了。

⚠ 注意他的措辞：「可能不同」「也许不是最好」—— 他没有断言人类的方式更差，只说不一定最好。

51:48we first want to have a reward that checks whether the reasoning chain is there

第一个奖励简单到让人意外：它只检查两个标签在不在。

⭐ 请注意这个奖励检查的是什么，以及不检查什么：它检查：输出里有没有 <think> … </think> 这一对标签。它不检查：标签里面写的推理「对不对」、「好不好」。

所以它是一个纯粹的「格式奖励（format reward）」。

而后者零成本、零噪声、完全确定。

为什么特殊？因为通常它们是分开的：一般情形：你用交叉熵训练，用准确率评测 —— 训的和测的不是一回事。这里：你直接优化那个评测指标。

所以这里有一个真实的风险，讲者没有在这里点：你在 AIME 风格的题上做 RL ⇒ 它在 AIME 上涨。但它在「没见过的那类推理」上涨多少？这是一个开放问题。

54:29there are some prompts that do not need the model to think too much

所以「想多久」不是「越多越好」，它是一个真正的最优化问题。

55:24those LLMs, they have a limited context window

59:11GRPO stands for group relative policy optimization

名字里的三个词，每一个都在说一件事。

⭐ 把名字拆开读，整个算法就说完了一半：「Policy Optimization」：和 PPO 一样 —— 优化策略（也就是你的 LLM）。「Relative」：advantage 是「相对的」—— 相对于某个参照。「Group」：而那个参照是「同一个 prompt 的一组 completion」。

所以名字本身就是算法的定义：在一组里相对地算优势，然后优化策略。

请把 advantage 的定义再确认一遍（L5 讲过），因为它是全部重点：advantage = 「实际拿到的」−「本来预期的」。它为正 ⇒ 这次比预期好 ⇒ 把这个行为的概率往上调。它为负 ⇒ 这次比预期差 ⇒ 往下调。

而「本来预期的」是什么，就是 PPO 和 GRPO 唯一的分歧点：PPO：预期由一个专门训练的 value function 给出。GRPO：预期就是同一组其它 completion 的平均奖励。

请把这一句记住，这一整块的内容都是它的展开。

⚠ 「比你会预期的更好」—— 注意 advantage 关心的从来不是「好不好」，而是「比预期好不好」。

60:16there is a key difference

第二件事，然后是这一整块的那句关键的话。

⭐ 他把 L5 那两层「别跑太远」又说了一遍，而这两层很容易混：偏离「旧模型」（π_old，上一轮 RL 迭代） ⇒ 由 clip 管 ⇒ 管的是「速度的上限」。偏离「基础模型」（π_ref，SFT 阶段的那个） ⇒ 由 KL 惩罚管 ⇒ 管的是「位移的上限」。

两条约束并存，不是二选一 —— 这是 L5 里反复强调过的那个符号陷阱。

所以 GRPO 的「继承清单」现在很清楚了：目标：最大化 advantage ✓ 和 PPO 一样。约束一：clip（别一步走太大） ✓ 和 PPO 一样。约束二：KL 惩罚（别离参考模型太远） ✓ 和 PPO 一样。advantage 怎么算：✗ 不一样。

这个「只改一处」的结构本身值得学：GRPO 不是一个新框架，它是对一个成熟算法的一处替换。而那一处替换省掉了一整个要训练的模型。

这是最好的那种论文：改动最小，收益最大，而且你一眼就能看懂改了什么。

60:50along with something else that it was training jointly at training time, which was called the value function

先把 PPO 那一套完整回忆一遍，不然下一镜的对比没有意义。

⭐ 请把 value function 的那个定义原样记住，它在 L5 里出现过：输入：一段部分生成（prompt + 已经写了一半的回答）。输出：「如果按当前策略把它写完，最终奖励大概是多少」。

所以它是一个「预期」的估计器 —— 而 advantage 就是「实际 − 预期」。

为什么 PPO 需要这个东西：奖励只在整条 completion 写完之后才有一个数。但 RL 要对每一个 token 决定「该上调还是下调它的概率」。

所以你需要一个东西，告诉你「写到这里为止，形势是好还是坏」—— 那就是 value function。

而这件事在 L5 里有一个名字：功劳分配（credit assignment）。

注意「联合训练（training jointly）」这四个字，它是下一镜那个瓶颈的源头：value function 不是现成的，它要和策略一起训。而它典型地和策略一样大（因为它也得读懂整个上下文）。

⚠ 所以 PPO 训练时显存里要放两个大模型的梯度 —— 而那正是 L5 说的「四个模型」里最贵的一笔。

61:37you had to train a value function jointly with your policy

那个瓶颈，而讲者顺手承认了 L5 跳过了 GAE 的公式。

⭐ 先替你确认一件事：L5 真的跳过了 GAE：L5 讲了 advantage 是什么、讲了 value function 是什么。但没有写出 GAE 那个公式 —— 讲者这里说「我们其实没有看过」，他记得没错。

而这不影响你理解 GRPO：因为 GRPO 恰好是把 GAE 整个扔掉了。

把那个瓶颈的代价算一下，你就知道为什么这是个大问题：value function 典型地和策略一样大（比如 7B）。它要存参数 + 梯度 + 优化器状态（Adam 要两份动量）。所以它大致把训练显存需求翻了一倍（L4 算过这笔账）。

而它还要调超参、还可能训不稳 —— 它自己就是一个会出问题的模型。

请注意这个瓶颈是两重的，而两重都值得记：计算上：多一个和策略同等大小的模型要训。方法上：value function 自己估不准时，advantage 就错，而策略会跟着错。

所以去掉它不只是省钱，也去掉了一个误差来源。

⚠ 「一个非常复杂的公式」—— GAE 的公式确实不短，但它的想法只是「把不同步数的回报按指数加权平均」。

61:59compare it with the average of rewards of completions for that same prompt

整个 GRPO 的核心，就这四句话。

⭐ 请看清这一招的本质，它只换了一样东西：advantage 需要一个「预期」作为基线。PPO：那个预期由一个模型「预测」出来。GRPO：那个预期由同组其它样本「当场测」出来。

也就是：用「蒙特卡洛估计」替换「学出来的估计器」。

为什么这招在 LLM 上特别合适，而在传统 RL 上不行：传统 RL：一个状态只能走一次（你没法把机器人倒回去重走）。LLM：同一个 prompt 可以采样无数次 —— 每次都是一个完整独立的轨迹。

所以「同一个起点重开 g 次」这件事在 LLM 上是免费的，在机器人上是不可能的。

而这正是为什么 GRPO 必须等到 LLM 时代才被发明。

请注意那句「同一个 prompt」，它是全部的关键：比较只能在同一道题内部进行。跨题比较没有意义（难题的奖励本来就低）。

而这一点正是下面那个「简单题 vs 难题」例子要说的事。

⚠ 「我们不要那么做」—— 讲者在用 GRPO 作者的口吻说话，而这个语气很准确：GRPO 的论文正是这么论证的。

62:35a relative measure of the reward for that completion and all the other rewards of the other completions

一个具体例子，把「组」这个词坐实。

⭐ 用一行把它写清楚，这就是 GRPO 的 advantage:⇒ 对第 i 条 completion：A_i = r_i − mean(r₁ … r_g)。其中 g 是这一组的大小（典型地 8 到 64）。

而稍后会看到实际还除了一个标准差 —— 讲者自己会说那一处可能不是最好的做法。

「那个 prompt 是共享的」这句话请不要跳过：一组里的 g 条 completion，回答的是同一道题。它们唯一的差别是采样的随机性（所以温度又回来了）。

于是「比较」是公平的：难度相同、prompt 相同，只有运气和走法不同。

这个设计有一个漂亮的副作用，请自己想一下：如果一组里 g 条全对 ⇒ 平均 = 满分 ⇒ 所有 advantage 都是 0 ⇒ 这道题不产生任何梯度。如果一组里 g 条全错 ⇒ 同样，所有 advantage 都是 0。

所以 GRPO 自动忽略「太简单」和「太难」的题，只从「有的对有的错」的题上学。那正是信息量最大的那些题 —— 一个免费得到的课程学习（curriculum）效果。

⚠ 不过这也是一个已知缺点：全对或全错的那一组算力完全白费了，而后续的变体（如 DAPO）专门在修这件事。

63:02the big benefit here is that we do not use value functions

好处用一句话说完，而那个交换非常清楚。

⭐ 请把这笔交换完整地算一下，因为它不是「净赚」：省下：一个和策略同等大小的 value function（参数 + 梯度 + 优化器状态 + 调参 + 不稳）。付出：每个 prompt 要生成 g 条 completion 而不是 1 条（推理算力 × g）。

所以它是「把训练成本换成了推理成本」。

为什么这笔交换是划算的，而理由很具体：生成 completion 是「推理」 ⇒ 不需要存梯度、可以大批量并行、可以用量化和 FlashAttention（L4 那一整讲）。训练一个 value function 是「训练」 ⇒ 要存梯度和优化器状态，显存占用是推理的好几倍。

所以「多生成几条」比「多训一个模型」便宜得多，而且工程上简单得多。

而「我们做的唯一一件事」这个说法值得记住：GRPO 的全部实现差异，就是「采 g 条，然后减去均值」。没有新的网络、没有新的损失项、没有新的超参（除了 g）。

这就是为什么它被这么快地普及：改动小到几十行代码。

⭐ 这是一个很有用的思维习惯，请记下来：一个方法的设计假设，来自它被发明时的那个问题。而不是来自你现在的问题。

而 LLM 的世界恰好反过来：一条轨迹只有一个终局奖励（答案对不对）。而「重开一局」几乎免费（同一个 prompt 再采一次）。

⚠ 「也许在语言这个世界里不是」—— 这句话很克制，但它其实是在说「PPO 的 value function 在 LLM 上是一个多余的复杂度」。

64:51use that as some kind of baseline to put this reward into context

高层直觉，而「把奖励放进上下文」这个说法非常准。

⭐ 「把奖励放进上下文（put the reward into context）」—— 这个说法值得单独记：一个奖励数字本身没有意义。「这条回答拿了 1 分」告诉你什么？什么也不告诉你。除非你知道「同一道题的其它尝试拿了多少分」。

所以「上下文」= 同组的其它尝试，而 advantage 就是把奖励放进这个上下文之后得到的量。

这个想法其实在统计上有一个标准名字：它就是「减去基线以降低方差」（L5 讲 advantage 时讲过）。而 GRPO 的贡献不是提出这个想法。

而这个比值乘上 advantage，就是「往好的方向推，推多少由 advantage 定」。

而 clip 在做什么，也一句话说清：它把这个比值截断在 [1−ε, 1+ε]（典型 ε = 0.2）。于是「一次更新最多把概率改变 20%」。

目的：防止一次大步长把策略推到一个坏区域，而 RL 从坏区域很难回来。

所以 clip 的作用是「单边封顶」：往对的方向走可以，但一步走太远就没有收益了。

也就是「不罚你，只是不再奖励你」—— 一个更温和的约束方式。

请停一下，想清楚为什么这本身就不该发生：一个 token 好不好，应该只取决于「它是不是一个好的选择」。而不应该取决于「它所在那条回答恰好有多长」。

为什么作者要这么做？因为这是唯一干净的实验：如果先做 SFT 再做 RL ⇒ 你分不清推理能力是哪一步给的。而跳过 SFT ⇒ 能力只可能来自 RL。

所以「还没见过任何监督」不是为了省事，它是为了让结论无可争辩。

⚠ 「有意思的地方开始了（this is where the fun starts）」—— 讲者在这里语气明显兴奋起来。

92:39all they incentivize the model to do is to increase the rewards based on the outputs

奖励只有两样，而论文把 prompt 模板的原文都给出来了。

⭐ 「全部事情（all they incentivize）」这个说法请留意：两个奖励，没有第三个。没有「推理过程要清晰」、没有「步骤要正确」、没有「不要太长」。

而就这两个，长出了一整套多步推理行为。

而「论文给出了模板的确切内容」这件事本身值得一提：这是 R1 之所以能被复现的关键之一。算法公开 + 奖励公开 + prompt 模板公开 ⇒ 任何人都能照着跑。

而 o1 一样都没给 —— 所以前面讲者说「他们真的在论文里描述出来了」是有分量的。

请注意「格式奖励」在这个配方里的地位比你想的重要：没有 SFT ⇒ 模型不知道该怎么组织输出。而格式奖励就是那个替代 SFT 的东西：它用奖励（而不是示范）教会模型输出格式。

所以「格式奖励」不是一个附属的小项，它承担了原本属于 SFT 的职责。

⚠ 讲者说「输入-答案（input answer）」—— 这里他口误了，他指的是模型给出的那个答案。

93:33whatever you want to think about, just do it, but put it into think boxes

模板的内容真的就是几句大白话，而这件事比它看起来重要。

⭐ 请注意这里的分工，它是整个配方的关键设计：prompt 负责「说清要求」：把中间过程放进 <think>，最终答案放进 <answer>。奖励负责「逼它遵守」：标签不在就没有格式奖励。

两者缺一不可：光有 prompt 它会忘，光有奖励它不知道要什么格式。

而「不管你想想什么，就去想」这句话里有一个很重要的留白：它没有规定「要想什么」。也没有规定「要怎么想」。只规定了「想的内容放哪里」。

所以 think 标签提供的是「一个被允许自由发挥的空间」—— 而模型在那个空间里自己摸出了推理。

这个设计思路非常漂亮：不规定内容，只划出场地。

对你的课题，这个「划场地而不规定内容」的思路可以借：你不需要告诉搜索「该怎么剪枝」。你只需要给它一个「可以自由尝试并被评分」的结构，然后让奖励塑形。

⚠ 「搭好场子（set up the stage）」—— 指 system prompt 那几句「你是一个助手」之类的开场。

94:21without any prior supervision, just having these as a reward increases scores

模板讲完，然后那张图第二次出现 —— 这次是从 R1 论文的角度。

⭐ 请注意这张图在这一讲里出现了两次，而两次的用途不同：上半场（Afshine）：用它证明「可验证奖励 + RL 真的有效」。下半场（Shervine）：用它说「这就是 R1-Zero 这个概念验证的全部成果」。

同一个证据，在两个论证里各起一次作用 —— 这说明它确实是整件事的核心证据。

「你给模型一个回应的机会」指的是模板最后那一步，我说清楚：prompt 的末尾留一个「Assistant:」或类似的开头。于是模型的任务就是「续写这个位置之后的内容」。

而这正是为什么一个基础模型也能被 RL 训起来：它做的事还是「续写」，只是续写的内容被奖励塑形了。

把 R1-Zero 的完整配方收一次，它只有四样东西：① 一个预训练基础模型（没有 SFT）。② 一个 prompt 模板（说清格式要求）。③ 两个可验证奖励（格式 + 答案）。④ GRPO。

就这四样。而它拿到了接近 o1-preview 的数学表现。

⚠ 「红色部分」—— 幻灯上用红色标出模板里要被实际题目替换的占位符。

94:40all is solved, it's great, no SFT, and we already have the best performance possible

讲者先替你说出那个过于乐观的结论，然后立刻推翻它。

⭐ 请注意这两个问题的性质，它们有一个共同点：混语言：推理链里中英文混着写。语法问题：句子不完整、标记错乱。

而这两个都「不影响答对率」—— 答案照样是对的。它们只影响「人能不能读」。

所以这是一个benchmark 测不出来的问题，而这件事本身很值得记：你的奖励只看「答案对不对」+「标签在不在」。那么「推理链好不好读」就完全不在优化目标里。

于是模型在那个维度上自由漂移 —— 而漂到哪里都不会被惩罚。

这正是 L4 和 L5 反复说的那件事：你没量的东西，模型不会替你保住。

而「混语言」为什么会发生，有一个很具体的解释：预训练数据是多语言的 ⇒ 模型内部的「想法」本来就不绑在某一种语言上。而没有任何奖励要求它「用一种语言」。

所以它会挑「在那一步最顺手」的语言 —— 对某些数学表达，中文可能真的更短。

也就是说：混语言不是一个错误，它是一个在没有约束下的最优行为。

⚠ 「没那么容易（not so easy）」—— 讲者在用这个转折引出 R1（而不是 R1-Zero）存在的理由。

95:23it doesn't really have, as a background, a strong supervision signal to anchor on

讲者给的解释，而「锚」这个词用得极好。

⭐ 「锚（anchor）」这个词值得单独记，它说出了 SFT 的第二个作用：SFT 的第一个作用（大家都知道）：教模型「怎么回应」。SFT 的第二个作用（这里揭示的）：给后面的 RL 一个「合理的原点」。

而那个原点就是 π_ref —— KL 惩罚要求 RL「别离它太远」。

把这件事和 L5 的 KL 惩罚连起来，整个逻辑就通了：正常的 RLHF：π_ref 是一个「已经会好好说话」的 SFT 模型 ⇒ KL 把你拉在一个好区域里。R1-Zero：π_ref 是一个「只会续写互联网文本」的基础模型 ⇒ KL 把你拉在那个区域里。

而那个区域里本来就包含混语言、语法混乱的文本 —— 所以 KL 不但没有阻止这些问题，它甚至是容许的。

所以 R1 的修法现在可以预测了，你自己应该能猜到：把 SFT 加回来。但不是「用几十万条数据正经做一遍 SFT」。而是「用很少量的、人工整理过的推理链，先给它一个锚」。

而这个东西在论文里叫「冷启动数据（cold start data）」—— 下一个知识点就是它。

⚠ 「去优化任何它想要的东西」—— 这是一个很准确的描述：没有锚的 RL 就是在一个没有边界的空间里优化。

模块 nR1 的四个阶段，与蒸馏95:49–106:48

95:49with RL only, you can get reasoning level performance

R1-Zero 证完了，现在做产品 —— 而注意起点是一样的。

⭐ 请注意这个细节，它经常被误解：R1 不是「在 R1-Zero 上继续训的」。它是从「同一个 V3 base」重新开始的。

所以 R1-Zero 对 R1 的贡献不是权重，而是「它生成的那些推理链」—— 下一镜就会用到。

这个设计其实很聪明，值得单独说：R1-Zero 的权重有问题（混语言、语法乱）⇒ 在它上面继续训，问题会被带下去。但 R1-Zero 的「输出」很有价值 ⇒ 挑出好的、让人改一改，就是最好的 SFT 数据。

所以 R1-Zero 被当成了一个「数据生成器」,而不是一个「模型检查点」。

把 R1 的四个阶段先列出来，这样接下来你有一张地图：① 冷启动 SFT（少量、人工整理过的推理链）。② RL（推理奖励 + 格式奖励 + 语言一致性奖励）。③ 大规模混合 SFT（推理 + 非推理，3:1，拒绝采样）。④ 最后一个 RL（有帮助 + 无害）。

而这四步的形状是：SFT → RL → SFT → RL。

⚠ 「V3 base」—— 指 DeepSeek-V3 的基础版（没做过对齐的那个），671B 的 MoE。

96:36they try to align it in a way that will nicely try to alleviate the issues we have seen

这一次不直接上 RL —— 先给它一个锚。

⭐ 「冷启动（cold start）」这个词值得说一下，它是借来的：它原本来自推荐系统：一个新用户什么行为都没有，你怎么给他推荐。借到这里：一个基础模型完全不会写推理链，你怎么让 RL 起步。

而答案一样：先用一点点人工数据把它推过那个起步门槛。

请注意 R1 和 R1-Zero 的结构差别只有这一处：R1-Zero：基础模型 ⇒ RL。R1：基础模型 ⇒ 一小段 SFT ⇒ RL ⇒ …。

而就这一小段 SFT，解决了混语言和语法混乱。

这件事对「SFT 还有什么用」这个问题给了一个很好的答案：R1-Zero 证明了「SFT 不是必需的」（能力上）。R1 证明了「SFT 仍然是必要的」（可用性上）。

两个结论不矛盾：SFT 不负责「会不会推理」,它负责「推得人能不能看」。

而这正好是前一个知识点那个「锚」的含义。

⚠ 「非推理版本」—— 强调这个起点和 R1-Zero 的起点完全一样，是同一个未对齐的基础模型。

97:02they used humans to rewrite some of these

冷启动数据是怎么来的 —— 而这是一个很聪明的循环。

⭐ 请看清这个循环，它解决了前面那个「数据不存在」的死结：① R1-Zero 生成推理链（质量不稳，但内容是对的）。② 人去「重写」—— 修格式、统一语言，而不是从零写。③ 得到合规的推理链 ⇒ 变成 SFT 数据。④ 用它训出 R1 的起点。

请注意第 ② 步里的那个词：「重写（rewrite）」,而不是「写（write)」：前面讲者说过：从零写推理链「非常难」—— 那是不可行的。但「修改一条已有的、内容正确的链」容易得多。

所以 R1-Zero 真正的贡献在这里：它把「写」这个不可行的任务，变成了「改」这个可行的任务。

这个思路值得你记住，因为它有很强的一般性：当你需要一份「没人写得出来」的数据集时。先用一个不完美的自动方法生成草稿。再让人去修 —— 人的成本从「创作」降到「编辑」。

而这在今天已经是标准做法了（叫 human-in-the-loop 数据生成）。

⚠ 讲者说「prompt 和重写过的 prompt」—— 他这里口误了，第二个应该是「重写过的回答」。

97:35it could have been several orders of magnitude less than some of the other stages

这一步有多小 —— 而「小」正是它的要点。

⭐ 请把这个量级对比记住，它是整条流水线最漂亮的一处：方案 A（前面被否掉的）：从零写几十万条推理链 ⇒ 不可行。方案 B（R1 实际做的）：让模型生成，人改几千条 ⇒ 可行。

而这几千条就足够了 —— 因为它的任务不是「教会它推理」,只是「给它一个锚」。

为什么几千条就够，这件事有一个很好的解释：模型「怎么推理」已经在 RL 里学了 —— 不需要 SFT 教。SFT 只需要告诉它「用一种语言、把句子写完整」—— 这是一个很窄的要求。

而很窄的要求，用很少的数据就能传达。

这一点对你用 LLM 做事也很实用：要改「能力」⇒ 需要海量数据或 RL。要改「格式 / 风格 / 语言」⇒ 几百到几千条就够了。

所以在动手之前先分清：你想改的是能力，还是形式？

⚠ 「没有给出数字」—— 讲者在诚实地说明这是他从措辞推测的，不是论文明写的。

98:28there was something called a language consistency reward

三个奖励，而第三个是专门为了那个毛病加的。

⭐ 请注意这个解法有多直白，而这正是它的优点：问题：模型混语言。解法：加一项奖励 = 「这条链里，目标语言的 token 占多少比例」。

一个比例，一个数字，不需要任何模型 —— 它仍然是「可验证奖励」。

把三个奖励摆在一起，你会看到一个很清楚的分工：答案奖励：管「对不对」（能力）。格式奖励：管「有没有按结构写」（结构）。语言一致性奖励：管「能不能读」（可读性）。

而三个都是程序能算的 —— 所以仍然「不需要一个奖励模型」。

这一处最值得学的，是那个工作方法：① 观察到一个具体的失败模式（混语言）。② 设计一个最简单能量它的指标（目标语言 token 比例）。③ 把那个指标直接加进奖励。

这是 RL 最直接的用法：你能量的，你就能优化 —— 而反过来，你不量的，它就会漂走。

⚠ 不过这也带来一个新的权衡：强制单一语言可能让模型在某些步骤上用一个不那么顺手的表达，从而轻微损失准确率 —— 这是一笔真实的交易。

99:15they mix both reasoning and non-reasoning data

第三步又是一次 SFT，而这一次解决的是一个还没被提过的问题。

⭐ 请先想清楚这一步在解什么问题，讲者没有明说：第二步的 RL 只在数学题和编程题上做。而 RL 会把模型往奖励高的方向推。

所以一个只练数学和代码的模型，可能变得「只会做题」—— 你问它别的，它答得反而变差了。这个现象有名字：alignment tax（对齐税），或者更一般地说，就是灾难性遗忘。

而解法就是「混数据」,这是一个很标准的做法：推理数据：保住刚学到的推理能力。非推理数据：把写作、问答、常识这些能力找回来。

所以这一步不是在「提升」什么，它是在「补回」被 RL 挤掉的东西。

请注意这四个阶段的节奏，它很有意思：SFT（窄，给锚）⇒ RL（窄，长能力）⇒ SFT（宽，补回通用）⇒ RL（宽，对齐偏好）。

每一次 RL 之后都跟一次 SFT 来「拉回来」—— 这是一个「先专精、再拓宽」反复交替的结构。

而这个结构在今天的后训练流水线里已经很常见了。

⚠ 「一个非常有意思的策略」—— 讲者指的是下面那个「3 比 1」的配比和拒绝采样。

99:42about 200k pairs

非推理数据是「回收」来的，而配比是 3 比 1。

⭐ 「回收（recycled）」这个词值得注意，它说明了成本结构：那 20 万对非推理数据不是为 R1 新做的。它是 V3 做指令微调时就有的，直接拿来用。

所以这一步的边际数据成本接近零 —— 而这正是「有一个前代模型」的好处。

把那个 3 比 1 算一下，数字就具体了：非推理：约 20 万对（回收的）。推理：约 60 万对（新生成的）。合计约 80 万对。

对照一下冷启动的「几千对」—— 两百倍的差距，而这正是讲者说「更大的规模」的意思。

而「3 比 1 偏向推理」这个配比本身是一个设计决定：偏向推理 ⇒ 保住刚长出来的推理能力（这是主要目标）。但留 1/4 给通用 ⇒ 足够把日常能力拉回来。

这个比例没有理论依据，它是调出来的 —— 而论文给出它，别人才能复现。

⚠ 「指令微调那一讲」—— 指 L4，那里讲过 SFT 数据该覆盖哪些领域。

100:23they used the model that had been trained so far to generate a response

那 60 万条推理数据从哪来 —— 而这里有一个漂亮的自举。

⭐ 请看清这个自举（bootstrap）,它是整条流水线的核心机制：第二步的 RL 训出了一个「会推理但可能答错」的模型。用它对一堆题各生成几个回答。只留下「答对的 / 完美的」那些。

于是你得到了 60 万条高质量推理链 —— 完全没有人工写作。模型在给自己造教材。

「拒绝采样」这个词在统计里本来是另一个意思，这里是借用：统计上：从一个易采的分布采样，按比例拒绝，得到目标分布的样本。这里：从模型采样，按「对不对」拒绝，得到「只有正确答案」的数据。

共同点是「生成很多，筛掉大部分」—— 而这正是 Best-of-N 的同一个结构。

请注意这件事和前面那张「不做 SFT 的三张票」的关系：那三张票里最重的一张是「没有推理链可用」。而到了这一步，推理链已经有了 —— 是前两步造出来的。

所以 SFT 在这里重新变得可用，而且比 RL 便宜得多。这正好印证了讲者那个 takeaway 的前置条件：「如果我们从零开始」。

⚠ 「某个评判者（some judge）」—— 下一镜会说这是 LLM judge，而那是 L8 的内容。

101:17they went on to a last stage

为什么用自动评判，以及第四步开场。

⭐ 「LLM judge（用 LLM 当评判者）」在这里第一次作为工具出现，而它有两个用途：这里的用途：筛数据 —— 判断一条生成的回答够不够好，留下还是扔掉。L8 的用途：评测模型 —— 判断一个模型的输出好不好。

而两处是同一个技术：拿一个强模型当裁判。

为什么这里必须自动做，讲者说得很清楚：要筛60 万条。人工审 60 万条推理链 ⇒ 不可能。

所以「自动」不是一个偷懒的选择，它是唯一可行的选择。而代价是：评判者本身会犯错，于是数据里会混进一些「judge 看错了」的样本。

而「可能会让你想起非推理流水线里的那些阶段」这句话，是在说第四步其实就是普通的 RLHF：第四步不再是推理专用的东西。它就是 L5 讲的那一套：用人类偏好对齐「有帮助」和「无害」。

所以 R1 的最后一步，是把它变回一个「正常的助手」。

⚠ 「这些是工作得相当好的启发式」—— 讲者在为自动评判辩护，而这个辩护是基于「实际效果」而不是「原理保证」。

102:01the harmlessness was a reward that was applied on the whole tokens that were outputted

两个新奖励，而「无害」那一项有一个很重要的细节。

⭐ 请把这个区分记清楚，它是一个很好的设计判断：无害（harmlessness）：覆盖「所有」输出的 token —— 包括 think 里的思考过程。有帮助（helpfulness）：只看「用户那一层看到的」—— 也就是最终答案。

两个奖励作用在不同的范围上 —— 而这个差别是有道理的。

为什么无害必须覆盖思考过程：思考过程可能被泄露（界面显示摘要、API 返回、日志记录）。更重要的是：一个在思考里就开始规划有害内容的模型，最终答案也不可能真正安全。

所以安全性不能只管「门口」,它要管「整个房间」。

而为什么有帮助不需要覆盖思考过程：思考过程本来就是「杂乱的、试错的」—— 那是它该有的样子。如果你要求思考过程也「对用户有帮助」,你就会把它压成一篇整洁的作文。

而那恰好会破坏它的作用：思考需要允许犯错和改口。

所以这个范围差别不是偷懒，它是在保护推理过程的自由度。

⚠ 「有帮助 + 无害」这一对概念来自 Anthropic 的 HH 框架，而它在 L5 讲偏好调优时出现过。

103:01R1 was pretty competitive with respect to closed source models

结果有两个观察，而第一个比具体分数重要。

⭐ 「两簇（two clusters）」这个观察比任何具体分数都重要：它说明：「是不是推理模型」造成的差距，比「哪一家做的模型」更大。也就是说：一个小一点的推理模型，可能打败一个大得多的非推理模型。

所以在推理类任务上，「用不用推理模型」是一个比「用哪个厂的」更重要的决定。

而第二个观察 —— 追上闭源 —— 的意义在前面已经讲过了：追上了，而且方法公开了。所以从那一刻起，「推理能力」不再是任何一家的护城河。

而这正是 2025 年开源模型集体跟上的那个转折点。

不过也请对这类结果保持一点清醒：benchmark 分数是「直接被优化的目标」（前面讲过）。所以「在 AIME 上追上」不完全等于「推理能力追上」。

而讲者用的词是「相当有竞争力（pretty competitive）」,而不是「超过」—— 这个措辞是准确的。

⚠ 「声称是基于推理的（claim to be reasoning-based）」—— 讲者在这里用了「声称」,因为闭源模型没公开做法，你只能信它说的。

103:30let's say you don't have a 600B MOE at your disposal

最后一块，而这个问题对绝大多数人才是真问题。

⭐ 这个问题的实际意义比它听起来大得多：R1 是 671B 的 MoE —— 自己部署它需要多卡服务器。而绝大多数人手上能跑的是 7B 到 32B。

所以「怎么把大模型的推理能力搬到小模型上」才是大多数人真正要解决的问题。

而这一块也是 R1 那篇论文被实际用得最多的部分：R1 论文同时放出了一系列蒸馏出来的小模型（1.5B 到 70B）。而真正被下载、被跑在个人机器上的，大多是这些小的。

所以「蒸馏」不是一个附录，它是这篇论文落地的主要途径。

请注意讲者又一次「先回忆旧定义」：这一讲他做了至少五次：CoT、advantage、value function、KL、现在是蒸馏。而每次回忆都不是客套，是因为接下来要在那个定义上做一个修改。

所以听到「让我给你一个提醒」时，你就该知道：下面要改的正是这个东西。

⚠ 「600B 的 MoE」—— R1 实际是 671B 总参数，每个 token 激活约 37B。

104:04so for example, for next token prediction, you know the text you want the model to fit on

旧的蒸馏设定，而「数据是固定的」这四个字是整个对比的关键。

⭐ 请盯住「固定的（fixed）」这个词，它是下面那个转折的全部前提：预训练：那段文本是给定的 ⇒ 你知道每一步的「正确下一个 token」。SFT：那些对是给定的 ⇒ 你知道「正确回答」是什么。

所以在这两种情形里，「要拟合什么」是一个已知量。

而推理这个场景恰好不是，这就是问题：你没有一份「正确推理链」的数据集（这是这一讲反复说的）。所以你不知道「要拟合什么」。

于是旧的蒸馏方法在这里直接用不上 —— 它少了最关键的那个输入。

这就是讲者说「另一种口味的蒸馏」的原因，我先把答案给你：旧蒸馏：数据固定 ⇒ 学教师在每一步的「概率分布」。新蒸馏：数据不固定 ⇒ 先让教师「生成」数据，再学它「生成的那个序列」。

所以差别不只在「学什么」,也在「数据从哪来」。

⚠ 「几讲之前」—— 指 L4，那里讲过知识蒸馏作为一种压缩手段。

104:32you fit it instead the whole probability distribution of the teacher model

旧蒸馏的核心：学「整个概率分布」而不是「硬标签」。

⭐ 为什么「学分布」比「学硬标签」好，这是蒸馏的全部精髓：硬标签：「正确答案是『猫』」⇒ 一个 one-hot 向量，信息量极小。教师分布：「猫 0.7、虎 0.2、狗 0.05、桌子 0.0001」。

后者多出的信息是：「教师认为哪些是「次好的」、哪些是「完全离谱的」」。而这些「相对关系」正是教师学到的「知识」。

这件事有一个很好的说法（Hinton 的原话大意）：硬标签告诉你「答案」。软分布告诉你「教师是怎么看这个世界的」。

所以蒸馏传递的不只是答案，还有教师的「相似性结构」。

而这就是为什么学生能用小得多的参数达到不错的效果。

那么「在这个情形里你会怎么做」—— 请自己先想一下：要学教师的概率分布 ⇒ 你需要「每一步的分布」。而拿到每一步的分布 ⇒ 你需要能访问教师的 logits。

而且你还需要「一份固定的数据」来跑那个前向。两个条件在推理这个场景里都不成立 —— 所以答案必然是一个「变通版本」。

⚠ 「硬标签（hard label）」—— 指 one-hot 的真值标签，对应的是「软标签（soft label）」也就是教师的概率分布。

105:13we use the teacher model here, R1, to generate some sample responses including thinking tokens

先让教师「造数据」—— 这是关键的一步。

⭐ 请看清这一步解决的是什么，它正是上一个知识点那个缺口：缺口：没有一份「固定的、带推理链的」SFT 数据。解法：让 R1 自己生成一批 —— 于是数据就「固定」了。

所以这一步是在「把一个没有数据的问题，变成一个有数据的问题」。

「离线（offline）」这三个字有很实际的含义：离线：先一次性把数据造完、存成文件，然后正常跑 SFT。在线（对比）：训练中每一步都调用教师，拿它的实时输出。

离线便宜得多：教师只跑一次，而那批数据可以反复用、也可以给别人用。

而这也是为什么 R1 的蒸馏数据可以被开源出来给社区用。

请注意这件事和前面「思考摘要为什么不给你看」那一镜的呼应：那一镜的第三个理由是：「有了链，你就能训一个模仿它的模型」。而这里，DeepSeek 自己正是这么做的 —— 用自家 R1 的链去训小模型。

所以那个「担忧」是真实存在的，因为它真的可行，而且 DeepSeek 做了。

⚠ 「不一定有开箱即用的（not necessarily out of the box）」—— 委婉说法，实际意思是「根本没有」。

105:51you just try to predict the same sequence of tokens that the teacher has outputted

第二步，而这个「另一种口味」其实就是普通的 SFT。

⭐ 请把两种蒸馏并排写出来，差别就非常清楚了：经典蒸馏：固定数据 + 学教师的「软分布」（需要 logits）。这里的蒸馏：教师生成数据 + 学教师的「硬序列」（只需要文本）。

所以这个「另一种口味」其实就是「在教师生成的数据上做普通的 SFT」。

这件事有一个很实际的好处，讲者没有明说：只需要教师的「文本输出」,不需要它的 logits。而这意味着：你甚至可以用一个只提供 API 的闭源模型当教师。

所以这种蒸馏在工程上门槛极低 —— 这也是它在今天被用得这么广的原因。

不过也请注意它丢掉了什么：经典蒸馏传递「教师的相似性结构」（次好的是什么）。这里只传递「教师最后选了哪个 token」。

所以它的信息效率比经典蒸馏低 —— 理论上需要更多数据才能达到同样效果。但它换来的是「只要能调 API 就能做」,而这个便利压倒了那点效率损失。

⚠ 讲者说「拟合到你那个蒸馏出来的模型上」—— 他口误了，应该是「拟合到那批蒸馏出来的数据上」。

106:11the results, once again, are very competitive with closed source alternatives

小模型也追上了对应的闭源小模型，而这一次的实际影响更大。

⭐ 请注意这件事在两个尺度上都成立了：大尺度：R1（671B）追上 o1。小尺度：蒸馏出来的小模型追上 o1-mini。

而后者的实际影响更大，因为它是绝大多数人真能跑起来的那一档。

这一讲里「追上闭源」出现了两次，而它们的意义不同：第一次（R1 vs o1）：证明方法可行 ⇒ 科学意义。第二次（蒸馏版 vs o1-mini）：证明能力可搬运 ⇒ 实用意义。

两件事合起来，才让这篇论文真正改变了行业格局。

对你的用途，这里有一个很具体的推论：你不需要 671B 才能用上推理能力。一个 7B 到 32B 的蒸馏版推理模型，在数学和代码上已经相当可用。

所以如果你想在自己的课题里用一个推理模型做实验，这条路是开着的。

⚠ 「声称是一个推理模型的更小版本」—— 讲者又用了「声称」,因为 o1-mini 的做法同样没有公开。

106:48distilling the knowledge is more efficient in terms of performance than directly learning from scratch

整讲最后一个问题，而这个答案很重要。

⭐ 这个问题问得很好，而答案推翻了一个很自然的假设：自然的假设：既然 RL 能在大模型上长出推理，那在小模型上也该能。实际结果：在小尺寸上，蒸馏比直接 RL 更有效。

所以 RL 不是在所有尺度上都最优的选择。

为什么会这样，有一个很直观的解释：RL 是一个「搜索」过程 —— 模型要自己摸索出好的推理路径。而能摸到什么，取决于「它本来有多大可能生成那种路径」。

一个小模型的初始分布里，那些复杂的推理路径概率极低 ⇒ 它几乎采不到 ⇒ 也就学不到。而蒸馏绕过了搜索：直接把答案摆在它面前让它模仿。

所以整讲最后的结论可以这么收，而我认为这是最该带走的一条：推理能力需要「足够大的模型 + RL」才能第一次「长」出来。但它一旦长出来，就可以被「传」到小模型上。

所以「发现」和「复制」的成本完全不对称 —— 第一次很贵，之后很便宜。

而这正好解释了这一整年的格局：一家做出来，全行业几个月内就都有了。
